# Recorded offline proof

The Lab separates four kinds of evidence: recorded-model transport against a fixture, a real product build prefix on recorded domain evidence, a candidate trial, and a saved Flow's successor series. A result of one kind cannot stand for another.

`lab attempt SITE --task ID --authoring-mode answer-first --recorded-model FILE` uses the real extension chat and attempt runtime, with a raw-response local model server. It writes `recorded-replay.json` with proof `recorded_model_fixture_runtime`, `domainEvidenceReplayed: false` and `fullAttemptAccepted: false`. Missing artifacts, unexpected streams or changed requests stop playback. They cannot switch to a provider. Only HTTP loopback model endpoints are permitted; redirected model traffic is refused. Requests retain their substantive task/model/grammar/evidence hash, with no transient normalization currently enabled. Streams have independent cursors, and there is no lookahead.

Recorded artifact version 1 carries explicit synthetic-fixture provenance, exact scenario/task/oracle identity, source fingerprints and ordered stream exchanges. Each response is raw base64 bytes plus HTTP status and media type, not a decoded provider answer. `readRecordedStepLogs` reads Core's actual `request.json`, `response.json` and `meta.json`; HTTP status and historical bill come from metadata. Core does not record media type, so recognizable SSE framing or valid JSON can establish an explicitly reported inference. Unidentifiable malformed media, missing response/status or missing stream attribution remains a gap. A transport-only admission reports missing build-state/domain proof separately; it never claims that proof.

`lab recorded-replay --input FILE --out FILE` invokes the real public build entry over a closed-store copy or SQLite backup under an isolated run root. It opens separate isolated roots for the archived domain trace and the target starting snapshot. It verifies both fingerprints and uses Core's public recorded-trace session. Starting-position admission requires an actual source-trace artifact binding the snapshot, task, oracle and entry request; a copied-store hash alone does not establish its position. `captureRecordedStart` closes an owned provider-free fixture host, reuses the closed-store copy helper, compares before/after/copy digests and prepares that receipt before entry. Its one-shot hook records through the existing public trace artifact sink in the actual matching project/Flow exploration trace. Missing/wrong membership, changed request/snapshot or unproved trace completeness stays a gap. The helper never captures a user panel or an original historical store. The native provider parser receives the exact recorded bytes, including unreadable answers and their usage. Before another model response is consumed, the typed session guard checks domain support. A gap triggers existing build cancellation. Optional admitted chat data exercises actual conversation interpretation before the existing build; the report names that entry precisely. This is `recorded_build_prefix`, always `fullAttemptAccepted: false`, even if every supplied exchange matched. No final result is invented beyond the recording. Model-response latency is not replayed and is reported as such.

`lab offline-preflight SITE --task ID --evidence DIRECTORY` composes an isolated paired extension, the real chat, a generic confirmation and a real snapshot read. The read-only probe Flow contains no lasting action. Like any Flow Core runs, it carries one active written task instruction, saved through the public generation-instruction route; Core refuses to run a Flow without one. It also sends the task's unchanged instruction through the normal chat build-start path. Stage receipts say which of these actually happened. Confirmation is not action permission. A task's explicit read-only declaration can mark permission not applicable with a task digest; a consequential task requires a separate actual start-gate/person-protocol receipt. The social deletion preflight uses its unchanged instruction and declared deletion class, denies the actual start permission through the panel, requests existing cancellation and verifies that no lasting site change or task-decision call occurred. It proves permission protocol only; unsupported consequential tasks remain explicit gaps. A generic confirmation does not prove a site's own person-only challenge. Declared challenge modules are reported separately as not run; absent modules are reported as not declared.

`node scripts/lab/offline-scoreboard.mjs --evidence test-runs/LABEL` reads ten fixed task subdirectories. Each contains an actual emitted `attempt.json`, `source.json`, `oracle.json` and `preflight.json`; stage artifact paths must exist. The source fingerprint includes current tracked/untracked authored implementation, excluding docs and ignored runtime data. The oracle fingerprint covers the unchanged task, its resolved judgement and fixture expectations. Historical baseline calls remain distinct from current calls.

Strict SUCCESS requires four right answers, three exact predecessor saved-Flow/digest proofs, current source/oracle/preflight evidence, zero logical model calls on attempts two through four and explicit zero external spend. Unknown per-attempt call attribution remains unknown. `lab attempt` exit zero alone is insufficient. Prefixes, isolated saved replay, stale source, missing digests or later calls cannot become SUCCESS. External billed cost, logical scripted/recorded calls, modelled usage and historical bills are separate fields. The lens-hood task is the fixed auction row; Mk II sellers remains supplemental. No task wording or oracle is changed by this facility.

These commands use ignored run-scoped artifacts only. Never point them at a live user store, publish raw responses/captures, or alter the campaign's original workspace. Builds and provider-free browser launches still follow the Lab's normal gate and supervision rules. A preflight is plumbing evidence; task acceptance requires an exploring attempt and three as-left successors with oracle and continuation proof.

The fresh producer is runnable as `lab recorded-capture company-website --task company-website-apprentices --evidence test-runs/LABEL`. It creates a blank Flow and saves the unchanged task instruction, then uses the owning topology's stopped-child boundary to copy consistent starting stores. The new host module calls the actual public known-Flow bootstrap entry with a native Haiku provider whose transport has no network fallback. Inside its real exploration episode, the first native request attaches the producer receipt and receives literal malformed fixture bytes; the diagnostic then requests Stop. This is a **fresh stopped bootstrap prefix**, not a conversation build, historical campaign reproduction, task completion or strict scoreboard success. Source traces remain unknown/incomplete unless public completeness evaluation, actual artifact bytes and receipt binding all pass. No open trace is relabelled complete. The stopped snapshot predates host restart; any resulting state/request drift remains a strict replay divergence.

`lab recorded-read SITE --input FILE --out FILE` proves a narrower original read boundary when the whole trace is open. It verifies the exact producer metadata call ID, command/result correlation, binding hash, result-file hash and snapshot artifact references through existing public segment APIs. A hashed original Lab entry receipt binds run, scenario and task to the unchanged fixture declaration; the snapshot must use that fixture path on loopback. A synthetic-fixture input flag alone proves nothing. The production content reader runs over that original HTML through the existing snapshot sandbox, in a visible browser, with page scripts and network disabled. Each layer is compared with its own original, and neither stands for the other. The reproduced native gateway result and its raw rows must equal the recorded native result and rows. The canonical step's rows are what the model was shown, which the production read writer (`webNodeReadWithRejectedRows`, reached as the domain's `webOfflineReadModelResult`) derives from the native payload, writing same-origin links as paths from the read's stated `origin`; so the reproduced payload is projected through that same writer and its rows must equal the canonical rows, with the projected origin equal to the canonical origin and the reproduced, recorded and snapshot page addresses equal. Missing null cells, changed value types, extra fields and row reordering fail either equality. Contract acceptance also requires valid public schema validation derived by the **current** dispatch from the literal original readable specs. Raw row equality is reported separately; a missing or invalid schema cannot pass contract acceptance. This current-derived schema is not recovered historical metadata. No validator output replaces raw compared rows. Provider calls are zero by construction; browser network leakage is measured separately and remains unknown when observation is unavailable. Reports always state `traceOpen: true`, `wholeTraceAdmitted: false` and `fullAttemptAccepted: false`. A six-field match supplies no missing cells or proof of newly retained fields. Full detector-spec parity or new detection on the same captured HTML needs its own distinct proof. Input files select existing hash-bound evidence; they do not assert admission or fabricate trace completion.

Fresh capture passes the fixture task's explicit processing declaration through the public bootstrap request. For apprentices this filters role containing apprentice and projects name, role and branch in captured page order. Undeclared task criteria are refused rather than replaced with empty processing. Historical recorded requests remain untouched.

The receipt binds the entry the service actually received, not the posted body. Core's public route hands the service the posted fields plus the caller it authenticated, the permissions it parsed and the wait it gives a person's answer, and the service requires that caller; a receipt over the posted body therefore never matched, and the first fresh Company capture made no model request (`native_request_not_captured`). The stopped boundary now records only the closed store's facts (its digest and copy time) and the posted request. Inside Core, at the service boundary, the host module checks that every posted field arrived unchanged, refusing otherwise (`recorded_capture_actual_entry_changed`), and binds the routed request whole, with one change: the caller's session id, which validates a live sign-in, is replaced by a fixed marker, since the fixture host binds its own provider and no session's key pays. The service then runs exactly that bound entry, which is also the `request` a replay enters, so changing criteria still invalidates the receipt. `capturedAt` remains the store copy time, before entry. A host refusal is reported by its code (`hostRefusal`) instead of disappearing behind the route's generic failure sentence. Provider calls are zero by construction; the command does not observe browser network, so `externalCalls` and `externalUsd` are null.

The snapshot runtime answers the content script's own-page address query with the real background response shape. It reports no application addresses because that isolated runtime owns no Core panel or gateway. The production document guard makes its usual decision from that response; other messages receive no invented background reply.

`lab recorded-read SITE --task TASK --input FILE --out FILE` is the P1-P3 acceptance over a campaign run's own recorded reads (`recorded-attempt-replay/read-oracle/`, t990). The input names a copied run's step folder, a copied trace store and the read step numbers in capture order; nothing else. Each step is found by its own metadata and admitted by the recorded-read checks above. Its recorded command is reproduced as the control: the native result and raw rows must equal the recorded ones, and the model-visible rows must equal the canonical step's rows. A saved Flow's pass shows only each kept row's label (`readRows`), so its labels and page address stand in for that last comparison (`canonicalKind: "replayed"`). The same recorded page is then read again by today's production reader with no provider. A fresh web evidence runtime gets the recorded snapshot as its only client. It detects the page's list and runs the model's own recorded node call, renaming only its list handle to the reissued one, or replays the saved step as Core asked. Every safe detected field is retained by that resolution. The changed read must read the recorded item selector, keep every recorded requested cell unchanged and pass the domain's differential rule (D37). The answers are stored by Core's own row sink and told to Core's own result feed, published unchanged at `fluxiq/automation/answer-first-data`. The feed's ledger joins the pages, and its data stage applies the task's processing declaration at the run's start time. That declaration is a test fixture (`read-oracle/declarations.ts`, falling back to the scripted fixtures). A declaration name that the run's reads aliased under one model key is rewritten to that key, and nothing else is rebound. The answer is judged by the task's oracle with the Lab's own dataset judgement. Reports hold counts, codes, field ids and digests only: retained schema labels embed a first-item sample and are never written. Model and provider calls are zero by construction; external calls are the sandbox's observed leaks. Recorded-read projection context now treats a link-free read, with no `origin` on either side, as matching; a canonical read without an origin beside a reproduction with one stays unavailable.
