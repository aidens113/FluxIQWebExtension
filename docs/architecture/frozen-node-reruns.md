# Frozen node reruns

The web evidence runtime can attest an actual node execution to Core through a
host-local capture scope. A model result, authored draft or old extraction handle
cannot create that attestation. The original public request and the concrete
execution parameters remain separate.

The capsule records the canonical node/version, actual resolved parameters and
effective inputs, fixed reference time, semantic subject and exact safe
session/resource/tab/frame/address/document scope. It records the real final
gateway command after defaults and each actual main retry, including an existing
same-subject refresh. Unknown/uncertain or synthetic settlement cannot establish
an eligible original.

The selected path looks up the opaque capsule before ordinary handle resolution.
It validates the current runtime and actual scope, finds the original subject
through existing strong record-aware identity, and uses the current operational
handle only for bookkeeping. Reusing the old public handle for another item
cannot redirect the selected command. A missing or ambiguous subject, changed
document or changed resource refuses rather than choosing a position.

A captured extraction reruns its concrete detected query and original reference
time against current rows in the same scope. It does not promise an unchanged
physical row/container. Row/state/output-bound subjects requiring new source
binding remain unproven; no new replay or dataset write is introduced.

The ordinary permission, origin, shown-address, actionability, retry, effect and
uncertainty paths remain shared. Core requires an actual settled primary
permission assessment as well as its current registered effect. An empty model
declaration alone never lowers that floor. Ordinary no-check reads retain their
behavior but do not become batch eligible. Missing proof remains unproven.

Before the main selected command, permission precedes capsule acknowledgement
and dispatch. Core can veto a stronger or unknown actual effect before a person
is asked or an action is sent. Acknowledgement proves selection, not execution.

The same final-lowering attempt observer is used for original capture and fresh
selected reporting. Scoped command cloning forwards that actual observer; it
does not synthesize receipts. Only main-command attempts enter a selected report.
Auxiliary looks, effect checks and synthesized settlement are excluded. The
producer flushes the optional host report once after ordinary postprocessing,
preserving actual failure/uncertainty replies and never reusing the original receipt.

A missing or rejected report cannot trigger a fallback, alternate subject,
repositioning or another retry loop. The actual result remains available to Core
for unproven settlement and private receipt retention. Unknown dispatch is not
silently counted as executed or definitely skipped. A successful batch does not
write a Flow step or establish a judged whole-Flow result.

Target/extraction map replacement does not rotate the binding generation.
Runtime, project/Flow/build/session replacement or lost actual scope cannot
recover a capsule from JSON. Capsules, actual parameters, receipt objects and
private errors never enter the public batch envelope.

Core owns tool offering, permission-effect proof, canonical list guards,
accounting and final settlement. Its developer contract is documented in
docs/architecture/automation-studio/prior-call-batches.md in the sibling Core
repository. The web domain owns DOM identity, query/source and gateway evidence.
