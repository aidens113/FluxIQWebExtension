## Inspection and approved design

Current graph import checks revision1, upserts Flow, inserts revision, then nodes/edges/regions/operations/partitions sequentially. Failure after revision insertion can leave partial graph and cause false already_imported on retry. Existing node/edge/region/partition helpers accept SQL executors; Flow upsert is the missing executor parameter. Proposed source change places the entire already-imported decision and all SQL under the actual lease.database BEGIN IMMEDIATE transaction, passing that executor through every helper and preserving public result/default arguments.

Five discovered production import callers are outside SQL transactions: runtime/service.ts getFlowGraphViewport; runtime/service/flows/graph-patch.ts applyFlowGraphPatch (graph patch unit-of-work begins afterward); runtime/service/flows/store.ts replaceFlowGraphIndex (initial import path); storage/project/migration-cutover.ts importLegacyFlowGraph; testing/scale-graph-store.ts. Project database held scopes are lease lifetimes, not enclosing SQL transactions. Only internal import currently invokes upsertFlowFromArtifact. No caller/service/schema/ledger changes are required. Import will own its transaction; calling it inside a queued transaction remains unsupported because it would enqueue behind its caller.

Supervisor approved graph-store.ts, scoped docs/architecture/automation-studio/persistence.md paragraph and this report. Placement inspection found existing project/tests has25 files; new file would exceed budget. Supervisor approved extending existing graph-store.test.ts (351 lines before change) instead. Focused cases were moved there and the worker-created new file removed with exact native Remove-Item. No baseline growth. Tests were authored but not run while provisioning70216 is in progress; no product source edits yet.

Planned real-SQLite cases: RAISE(ABORT) triggers on revision/node/edge/region/operation/partition writes, verify Flow/revision/entities/FTS/bounds/operations/partitions zero; reopen, remove trigger and retry complete import. Existing Flow metadata/revision must restore on failure. Concurrent separate pools/connections must yield one complete imported graph and one already_imported. Inject loss of acknowledgement after actual COMMIT; report thrown uncertainty, reopen complete graph and retry already_imported, never claim rollback after committed storage.

## Limits

This is one project's SQL graph import, not atomic parent/router/subflow accepted topology, global/JSON/document projections, source/settings/publication authority or candidate promotion. No new cancellation API, graph representation or policy permission is introduced. Existing ownership/rehome and graph patch/inverse semantics remain subject to owning regressions. No power-loss or literal process kill claim is made for these SQLite trigger/reopen tests.

Source change is now exactly the optional executor on Flow upsert plus the import-owned transaction/executor propagation. No nested helper queues remain in this import. Existing first-revision marker/result shapes/count fields are compatible; this change prevents new partial imports, but does not diagnose or repair pre-existing revision-1 partial state from older builds. Direct low-level external SQL/SDK callers remain outside this bounded migration. There is no cancellation parameter today; storage errors propagate rather than manufacturing a cancelled or successful result.
