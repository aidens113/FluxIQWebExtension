# S7 paging retirement readiness

Status: Read-only worker audit; implementation not started
Owner: codex-t517
Date: 2026-10-13
Inspected pair: downstream `6a46e66b`, Core `73550acb`

S7 remains mostly unimplemented. The old browser reader can still page internally, checkpoint rows and resume across documents. Production Flow dispatch already refuses multipage `paginate` and strips a permitted one-page legacy setting, so removal must preserve that compatibility behavior rather than turn old paged Flows into successful partial reads. The historical lane-C qualification satisfies the original S7 live prerequisite; current instruction-first extraction/export/restart acceptance is still outstanding and must be validated after removal. No new paid build is needed merely to establish removal readiness.

The historical removal list needs two corrections: extraction-handle resolution has already retired its old paging helpers, and several listed Core paging modules now also own valid Repeat/Next-page evidence. Do not delete those modules wholesale. Detector/pager and cross-document resend support also remain necessary for Next page.

## Compatibility requirements and prerequisites

- Existing multipage Flows must still fail with the explicit migration path: Read, Next page, Repeat. No automatic graph synthesis or successful one-page truncation. Explicit instructions remain mandatory before any legacy Run/resume.
- Existing single-page picker definitions with maxPages 1 decode as a one-page read; unknown/malformed evidence stays rejected. Never rewrite stored recording payloads or synthesize task authority from them.
- Existing stored action/run summaries may retain pagesRead/paginationStop; accept them only as historical evidence. Do not promote unknown list end into complete. Shared Next-page answer and loop evidence remain authoritative for new runs.
- The original lane-C proof is documented qualified in current MVP state; the extraction plan's pending-live sentence is stale. Its old off-peak prerequisite is also obsolete. New instruction-plus-described-evidence end-to-end extraction/export/restart acceptance remains an actual release proof gap, not a reason to preserve obsolete paging internals indefinitely.
- Source is currently frozen for qualification; implement in isolated paired worktree after supervisor assigns exact files. No dependency/test/provider/permission blocker found by this read-only audit.
