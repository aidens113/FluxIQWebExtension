## Findings recorded during inspection

- runtime/service.ts getLlmExecutionDependencyDigest (:1315) hashes full parent Flow, router, paged subflows/owned graph Flows, graph revision bindings, paged instruction documents, reachable publication dependency state. getLlmExecutionBinding (:1442) independently reads settingsRevision from project SQL (or metadata fingerprint without SQL); these reads do not share a transaction/snapshot.
- runtime/service.ts saveFlowInstruction (:3282) writes source document/index/summary, then catches SQL projection failure. Source body is not the SQL body: flows/store.ts writeSqlFlowInstruction intentionally persists inlineBody:null with title/body digest. SQL migration therefore must import actual document text, not reconstruct it from this projection.
- runtime/service.ts publishFlow (:1930) saves Flow through ordinary writer then writes global publication record. deprecateFlowPublication (:1990) writes global publication status, then current Flow repository/document; it bypasses saveFlowInternal and metadata/change-feed projection. Same-project SQL alone cannot CAS all publication dependencies.
- storage/project/flow-resource-mutations.ts saveInstruction and deleteResource support ordinary SQL-only source changes independent of service document path. Both must enlist; routing only service.saveFlowInstruction misses a competing writer.
- runtime/service/catalogue.ts can synthesize absent global publication records from Flow history. Old projections must not resurrect deleted/deprecated authority.
- Graph dependency reads catch missing/failed owned graph reads to null; paginated source reads filter absent instructions. Preparation must reject unresolved required dependencies rather than shrink the CAS vector.

The concrete inventory and proposed sequence below complete this bounded discovery. No storage atomicity was tested or established.

## Cache and projection inventory

- R/flows/store.ts loadProjectFlow prefers existing global repositories.flows entry; getFlow mixes it with materializeCanonicalGraphFlow SQL and read-time locked-default/token-cap migrations. Global memory repository is Map-backed; SQLite canonical repository is durable global document storage, not merely an in-memory cache. Treat both as compatibility projections after adoption.
- R/indexes/store.ts read/writeFlowIndex, FlowRouterIndex, FlowSubflowIndex and FlowInstructionIndex use ProgramJsonStore. Membership controls dependent IDs. Full paged membership must come from authority generation; zero typed rows may mean genuine empty/deleted, not fallback to old index.
- R/summaries/store.ts getFlowInstruction resolves path using document instruction index, not SQL source body. listFlowInstructionSummaries prefers typed SQL only when total>0, otherwise ensureFlowInstructionSummaryIndex/global summary fallback. Subflow paging has analogous fallback/import paths. Summary repositories use separate SQLiteRepository kinds flow.instructions / flow.subflows; counts/version-based repairs are not generation CAS.
- S/flow-resource-repository.ts resolveEffectiveInstructions reads scope IDs, active rows, instruction detail and effective_instruction_digest_cache in separate queries. Cache currently validates recomputed maxRevision/contentDigest before hit; it is not just blindly reused. Full authority read must include scope/binding revision and complete enumeration rather than maximum revision or default page limit alone. upsertInstruction clears cache; mutations.saveInstruction catches clear failure; deleteResource lacks explicit clear. No claim of demonstrated stale cache outcome from that omission.
- R/bootstrap-adaptations.ts memoryBootstrapAdaptations and R/candidate-drafts/store.ts memory read-through stores are not fresh authority; current main get() can return memory first. t304 worker owns uncached draft hook; this companion did not read or alter its source. Apply/promotion must use fresh persisted candidate/receipt joins.
- R/catalogue.ts history synthesis and global publication records have no generation boundary; deleting a record alone can resurrect it from history. R/flows/store.ts lazy imports can likewise resurrect removed owned graphs.
- programs/_shared/storage.ts writeLocks and database-manager/storage/sqlite-repository.ts databaseOperationLocks serialize process-local paths. ProgramDocumentTransaction is layout-v2/root/kind restricted. S/database.ts BEGIN IMMEDIATE transaction is one project SQLite connection; unrelated document/global DB/cache/generated files are outside it.
- Generated Flow source/config, object documents, summary/index mirrors and change feed are durable projections/outputs. Projection generation and recoverable outbox must commit with authoritative mutation. UI caches are display-only; their deletion is not CAS evidence.

## Smallest executable migration sequence (proposal, not implemented)

1. Keep t304 receipt preparation explicitly unsupported. Define supported project-SQL scope with complete source/topology/settings authority and explicit exclusions for external/global publication authority. Add adoption/generation/tombstone and revision-vector contracts; retain normal authorization/registry/compiler/version joins. Do not enable promotion based on a copied snapshot.
2. Introduce transaction-bound accepted document, settings, source, membership and graph primitives. Migrate one isolated project via explicit opt-in/import under fenced writers: read full legacy Flow/instruction bodies and complete paged membership, validate ownership/digests, refuse document-vs-SQL ambiguity, write one committed generation and adoption marker. No automatic user migration/reset. JSON stays unsupported.
3. In one coherent reader/writer unit, route **every** listed ordinary writer for adopted scope through those primitives: service save/delete/compile/visual conversion/router/subflow/instruction, low-level SQL resource APIs, graph imports/patches, lazy migrations and projection synchronization. Guard low-level global repository put/delete against adopted scope except controlled generation projections. Before this unit is complete adopted promotion remains disabled; partial routing allows evasion.
4. Move getFlow/router/subflow/source/settings/summary membership and getLlmExecutionBinding to one executor-bound coherent authority reader, used also by runtime/executor/dependency validation. Project SQL settings must actually drive normal execution, not just a binding counter. Remove legacy repair fallback for adopted generations. Projections never overwrite authority after cache miss/restart.
5. Publication scope decision: initial accepting scope can exclude all publication-dependent candidates until authority is complete (explicit refusal, no digest weakening). Later move publication status/version/availability and dependent project lifecycle into one shared transactional owner, or a separately designed crash-safe cross-owner protocol with all ordinary writers participating. A project-local CAS of copied external rows is insufficient. Global immutable snapshots alone do not cover mutable deprecation.
6. Implement candidate promotion only after these units pass: trusted receipt lookup, normal permission/validation, full binding compare inside transaction, topology/source/settings/membership+promotion result+outbox/feed commit once. Reconcile lost acknowledgements and post-commit projections by committed key; never rerun candidate commands. Leave interpreter/start/oracle/command acknowledgement joins separately unavailable until implemented.

The migration sequence requires an explicit supported-authority policy, not a flag that silently skips ordinary APIs. A temporary maintenance fence can protect one-time adoption, but cannot replace persistent writer participation or cross-process CAS.

## Required regression and restart negatives

- Two service instances and two processes: instruction body/scope/priority/status edit or SQL-only delete versus promotion yields one authority winner; SQL-only save must be visible through ordinary getFlowInstruction. Instruction delete followed by empty typed summary must not resurrect old document. Add/remove a second required instruction after source enumeration must invalidate binding, even if maxRevision unchanged.
- Settings SQL-only mutation versus full Flow save/promotion: stale metadata cannot reset current settings; runtime executes same settings generation the binding certifies. Harmless upsert revision behavior explicitly covered.
- Parent/router/fallback/group/rule/subflow/owned graph create/delete/disable/rename/mapping mutation versus create/extend promotion, including compile-to-code and convert-to-visual bypass routes. More than100 members/instructions remain complete. Lazy import and read-time migrations cannot manufacture new adopted state.
- Published version/deprecation/delete/history fallback and nested cross-project Call Flow mutation before/during commit; unsupported authority refuses without graph mutation. Project removal between permission/read and commit cannot accept into removed project.
- Warm global cache, cold cache, fresh service and reopened DB must read the same old-or-new generation; stale files/summary repair cannot resurrect deleted members. Mixed graph/settings/source revisions must fail, not produce a hash considered current.
- Inject failure before each SQL write/COMMIT, after COMMIT/before acknowledgement, and during each projection; reopened storage has complete old/new authority, same durable mutation/promotion key, pending projection truth and no repeated action. Exercise graph public patch/import, source save/delete and global low-level put/delete, not only candidate promoter tests.
- Permission revoked, actor/project access changed, compiler/registry/version mismatch and missing source IDs/spans must refuse. Requirements/start/oracle/acknowledgement unavailable remains unavailable regardless of authority migration.
