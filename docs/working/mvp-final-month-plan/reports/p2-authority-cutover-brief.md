# P2 first coherent production authority cutover

Status: concrete bounded implementation proposal, not implemented. Worker: p0_acceptance. Date: 2026-10-07. Read-only main Core/downstream inspection; only this report written. t309 source remains frozen for supervisor review. No source edits, builds, tests, providers, browser/panel or git operations.

## Recommended coherent unit

Create an **explicitly requested new local visual project** with managed project/resource IDs. Its complete snapshot, real project record, activation, mutation receipt and projection intent commit in one project-SQL transaction. Serve its actual production project/Flow/router/subflow/instruction/settings/graph/catalogue reads from that generation. Every ordinary legacy/private/public writer either joins the new CAS owner or refuses before its first side effect. In this first unit all legacy authoring paths refuse; one explicit authorized complete-snapshot replacement/tombstone path owns changes. This is a usable but narrow storage/read/execution cutover, with ordinary GUI edits initially unavailable. It is not the whole MVP, existing-project adoption or candidate promotion.

Do not call it active when only the store or facade has landed. Preparatory partitions may integrate with activation unavailable; enable the explicit endpoint only after the combined writer fence, actual readers and runtime wiring pass supervisor verification. No permissive feature flag, maintenance-only fence or copied staged generation substitutes for that gate.

New-project-only scope removes legacy capture freshness from the initial transaction. Existing projects remain on their current path; requests to import/adopt them return `authority.existing_project_adoption_unsupported` before mutation. Creating a managed project is explicit opt-in, not a read/cache-miss migration. Ordinary `createProject` currently generates a bare randomUUID and has no supplied-ID parameter; it must continue doing so, and must not install a managed record through normal legacy index/manifest writes.

## Identity and durable storage contract

1. Introduce one shared, domain-neutral managed identity owner under `model/project-authority/identity.ts` with its barrel. Proposed grammar: `asql.<UUID>` for projects, and `asql.<projectUUID>.<kind>.<UUID>` for owned Flow/router/subflow/instruction/binding/category/policy IDs. Graph IDs also follow this ownership grammar; node definition IDs remain actual registry IDs. Keep the existing200-character bound. Mint IDs inside the explicit creation coordinator, never trust a caller to turn an arbitrary existing ID into a managed one. Validate all captured resource ownership against the minted project, including scope/membership and owned graph Flows.
2. Reserve the namespace at **all legacy write boundaries regardless of whether a marker exists**. This avoids `check absent → activation → late legacy write`. Namespace is routing/fencing only, never evidence of authorization, existence or active authority. Raw Flow put with a managed resource ID but forged legacy projectId still refuses; delete checks the resource ID before lookup, so a missing cache row is not permission to delete. Publication IDs derived from managed Flow IDs refuse too. Before dispatch, inspect for historical namespace collisions; if any exist, choose another reserved grammar or refuse this unit rather than silently adopting/blocking real data. Existing normal UUID projects are unchanged.
3. Reuse t309 `accepted_project_snapshots`/`accepted_project_heads` complete canonical+SQL payload and immutable history. Do not introduce a second graph/source schema. Add a local numbered migration allocated after then-current migrations, with `managed_project_authority(project_id PK, epoch, namespace_version, lifecycle active|tombstoned, activation_mutation_id, protocol_version)`. Its epoch is tied to the head; lifecycle must agree with head state. The marker is production ownership, not a new enum in a caller-supplied snapshot. The full actual `AutomationStudioProjectRecord` is a required, validated `snapshot.project.metadata.managedProjectRecord` in the production envelope; no independently mutable manifest row. It includes name/description/domain/category/timestamps/hierarchy/workspace. First scope requires local domain/categoryId:null and no externally owned category/hierarchy dependencies.
4. Factor focused transaction-bound snapshot/head primitives from t309 store into `accepted-state/transaction.ts` with deterministic preparation/read validation as needed. The staged API and managed API both use the same primitives; managed code never sequentially calls `stageInitial` then activates, or nests a separately queued UoW. The public staged-store opener/mutators refuse managed IDs before migration/write; they cannot be a production compiler/permission/outbox bypass. Its ordinary unreserved staged tests remain compatible.
5. Managed create writes generation1 snapshot/head, marker, durable mutation response, authority change-feed event and generation-tagged projection intent with **context.sql in one UoW**. Full replacement CAS increments generation and preserves epoch; project record edits are included in that replacement. Tombstone retains history and makes all later execution/read requests closed, without removing the database directory. Restore/recreate/physical delete are unsupported. Do not reuse an epoch or fill missing state from old mirrors.
6. Add `database.ts` focused `acquireExisting`/open-without-OPEN_CREATE support for managed reads: no mkdir, database creation or migrations on an unknown managed ID. A reader queries the real marker/head/snapshot join and fails on missing marker, mismatched epoch/lifecycle/pointer/hash/schema, invalid project ownership or corrupt rows. Ordinary `pool.acquire` remains for explicit creation/other current owners. Prefix alone cannot make a nonexistent project real.

Use a typed current production binding `{projectId, epoch, generation, snapshotDigest, protocolVersion, lifecycle}`; return it with every managed read/result and execution admission. Keep t309's recorded-binding versus current-binding distinction. Source membership/body/scope/settings/project record changes invalidate the project generation. Strictly reject extra binding/request fields when reconstructing durable request proof. Reuse the verified receipt checks for owner/operation/status/request/result/historical-snapshot joins; keep unknown outcomes closed. No claim of SQL tamper resistance against arbitrary database rewriting.

## Normal validation, authorization and execution

New `runtime/service/project-authority/coordinator.ts` owns request preparation and trusted gates. The storage owner never infers actor rights from ID/payload/compiler strings. New API handlers use existing registry program read/write permissions and actual request actor/scope; coordinator checks the committed project's local domain against that scope. It verifies the real loaded registry/compiler/normalizer identity, full canonical Flow validation, source/settings agreement and actual compiled normal form. Refuse missing definitions/versions, unsupported normalizer rewrites or forged supplied provenance. Reuse `compileFlowDefinition`/`normalizeAutomationStudioFlow` and current registry/native permission/consequence dispatch; do not authorize all capabilities or accept a model's claim that compilation succeeded. Do not silently resolve SQL/document disagreements.

Actor/project authorization is checked through the existing trusted permission owner before commit/execution, with fresh committed project lifecycle/domain and CAS inside the transaction. If the normal policy owner offers a revision/fence, bind it and revalidate through that owner. Do not claim cross-owner policy revocation atomicity from a copied digest or a callback immediately before COMMIT; absent a suitable policy fence, explicitly refuse any operation requiring that stronger guarantee. Per-action native consequence/permission checks remain mandatory. The new API does not weaken existing endpoint permissions.

New `runtime/service/project-authority/view.ts` is an immutable generation-bound read object acquired once. It exposes project, Flow, router, subflow, full instructions/effective bindings/settings, complete membership/pages/summary projections, graph viewport/binding, and scoped Flow catalogue from the same stored snapshot. A page cursor carries its binding and refuses generation change; empty membership is empty, never a request to repair/import from files. Current single-object facade calls can acquire a fresh view; multi-object execution/binding/dependency construction must use one explicitly passed view, not repeated `service.getFlow` calls that can each see different generations. Do not hide the view in process-wide mutable state.

Managed runtime admission uses the real project marker and one view before creating a session. It refuses caller-supplied Flow documents, stale resumed sessions and canonical-read failures rather than falling into legacy `getProjectArtifact`. `startRuntimeSession` currently catches getFlow failure and chooses that legacy fallback; it must branch before the catch. `runRuntimeSession` currently rereads canonical parent, router/subflows and settings/adaptation context; a focused managed execution collaborator supplies pinned normal-executor closures for parent/selected router/subflows/full instruction set/settings. SQL settings actually drive execution and match stored canonical metadata, not merely a counter. Validate current binding/lifecycle and normal permissions again at admission and before native dispatch; do not hold a SQL transaction across browser work. A concurrent authority edit cancels/refuses the next dispatch as stale, rather than changing a running plan silently. A dispatched command's uncertain outcome remains uncertain and is never repeated because storage resumed.

A final freshness read followed by an effect is still a race. For the stated mutation-versus-dispatch invariant, add a bounded `managed_authority_dispatch_claims` join (project/epoch/generation/digest/runId/dispatchId/requestDigest/status) in B's local migration. Inside the same project SQL transaction, dispatch admission compares current authority and records one pending claim; managed replacement/tombstone refuses while a pending/unknown native effect claim exists. A trusted normal dispatcher settles the exact claim from its execution acknowledgement, never model success fields. No SQL transaction stays open during native work. Crash/cancel/lost acknowledgement with unresolved native effects preserves unknown and keeps edits/replay closed until a trusted reconciliation adapter resolves it; a time lease expiring is not evidence that the old effect stopped. If this claim/reconciliation integration is not implemented, managed **execution stays unavailable** and the unit may only be reported as production storage/read cutover. Do not claim serialized edits against actual dispatch from a preflight check alone. This auxiliary receipt table is not another graph schema or candidate promotion receipt.

First execution scope is declared deterministic/native execution with authored `no_llm_intervention` settings; reject a supplied adaptive/intervention request before effects rather than changing the user's settings. Runtime patch/recovery/auto-promotion are unavailable for managed projects in this first unit. Reuse normal executor routing, cancellation, signals, action permissions, consequence checks and run accounting. This restriction is explicit scope narrowing; later reviewed managed authoring/adaptation writers can expand it. Candidate requirement interpretation/start/reset/oracle/performed acknowledgement and promotion remain separately unavailable.

## Projection outbox, catalogue and restart

Use existing transaction-bound `AutomationStudioStorageOutboxRepository(context.sql)` for file projection intent; it already accepts an executor and must not be reopened/queued in the authority transaction. Output paths are **generation-versioned** under a distinct managed-projection directory and never normal legacy Flow/source paths. Outbox IDs/path/hash encode project/epoch/generation/snapshot digest. The immutable SQL payload is the regeneration source; staged/final projection files are reconstructible, not input to current reads or CAS. If using existing outbox is insufficient to validate binding/claim lease, add one narrowly scoped outbox-envelope/claim table in the new local migration; do not treat unversioned finalPath as proof of current generation.

New `runtime/service/project-authority/projections.ts` processes only owned generation-tagged exports after commit, with bounded recoverable claims. It rereads/validates the committed SQL binding/payload and regenerates missing owned temp data. Failure is pending/failed projection, not rollback of acceptance. A delayed generation1 worker cannot replace generation2 authority or make catalogue read an old file. No raw global Flow/publication put bypass credential is needed in this first unit: do not mirror active projects into those repositories. Normal action/session accounting remains separate from these topology projections.

Managed project discovery may enumerate reserved directories only as **discovery hints**. Validate each existing project.sqlite's marker+head+snapshot and real local project record; do not acquire/create a database for an unknown directory, synthesize project existence or load a JSON index as authority. Persist a committed registry only if needed for complete root enumeration, with a separately reviewed authority boundary; do not sequentially commit a global registry and project head and call it atomic. First `listProjects` can return per-project generation-tagged results from validated discovered managed databases plus the unchanged legacy catalogue, with explicit non-atomic cross-project listing semantics. Scoped Flow catalogue/execution/CAS is one project generation. Global/cross-project dependency catalogue operations remain unsupported for managed scope rather than using mixed records or silently excluding required managed data.

Real restart tests must distinguish pre-COMMIT rollback, COMMIT followed by lost acknowledgement, pending projection and native action state. Reconcile the same durable mutation and original request, not a copied snapshot result. Literal process termination/relaunch is required before claiming restart durability beyond fresh-owner reopen; use owned fixtures/markers and opt-in built-artifact probe as t304 did. No browser command is replayed by projection or receipt recovery. Unknown external effect state stays unknown, even if SQL authority is committed.

## Concrete implementation partitions and integration order

Use one coherent parent unit with serial shared-file integration. Each bounded child has its own report; preparatory tasks never expose active creation. Do not assign `service.ts`, project barrel, API register/endpoints or shared architecture to multiple concurrent workers.

**A — identity and storage fence, can start immediately.** New `model/project-authority/{identity,index}.ts` and owning tests; existing SQL graph/resource/mutation/migration-cutover open guards; canonical SQLite/memory repository guards; new `storage/authority-repositories/{guard,index}.ts` + owning tests; staged store namespace guard. No production marker/activation API. Exact guard owners are disjoint from runtime reader partition except staged store reserved guard must precede B's serial refactor. Public/default/injected factory compatibility is tested. Record and close every named writer before B or final activation.

**B — one transaction production store, starts after A contracts/source freeze.** New `storage/project/managed-authority/{contracts,migration,store,index}.ts` and owning real-SQL tests; existing `accepted-state/store.ts` plus new `accepted-state/transaction.ts`/barrel for shared primitives; focused `database.ts` existing-only acquire; one additive project barrel. Extend validated production envelope without changing t309's stored full graph format. Atomic marker/snapshot/head/receipt/feed/outbox, CAS/tombstone and original-request reconciliation; dispatch-claim admission/settlement CAS and mutation refusal during pending/unknown claims are a focused `managed-authority/dispatch-claims.ts` owner if execution is in this unit. Methods remain internal/unreachable from production endpoint until final integration. No service/GUI writes, legacy capture or promoter.

**C — runtime generation view and legacy owner guards, parallel with B after identity contract.** New `runtime/service/project-authority/{view,coordinator,projections,index}.ts` (execution may be a further focused file after ownership review) and owning tests. Existing `flows/{writer,mutations,graph-patch,store}.ts`, `indexes/store.ts`, `summaries/{store,sql-paging}.ts`, `projects/{store,update,files-removal,artifacts}.ts`, `catalogue.ts`: runtime fences/delegation. Split C into C1 Flow/instruction/index owners and C2 project/catalogue owners by these files, both consuming frozen view contracts; neither changes service.ts. Coordinator preparation applies actual compiler/registry/settings/permission gates. All activation helpers remain uncalled until D. If file budgets need splits, approve a focused owning collaborator before editing, not baseline growth.

**D — serial actual facade/API/executor integration, owns all shared wiring.** `runtime/service.ts` (small delegations; move touched orchestration into project-authority helpers), `runtime/service/facade-ports.ts` only if typed view ports require it; new `api/contracts/project-authority.ts`, `api/contracts/{index,endpoints}.ts`; new `api/handlers/project-authority.ts`, `api/handlers/register.ts`; ordinary handlers only to preserve explicit unsupported failures. Add explicit create/replace/tombstone/read/reconcile endpoints with normal registry permissions, actor/domain scope and typed binding. Existing getFlow/router/subflow/instruction/settings/graph/catalogue facade calls delegate; managed start/run uses one pinned actual executor view and refuses legacy fallback/caller Flow/resume drift. Sync request/response consumers if exposed; no downstream UI flag in this initial API opt-in unit. D activates only after A–C review and full official-ingress audit; otherwise creation remains unavailable.

**E — literal restart/projection/native execution proof, after D source freeze.** Owning provider-free scripted real-service/compiler/native dispatcher tests plus bounded opt-in literal child kill/relaunch; no product edits during supervisor verification. Validate actual default/injected repositories, low-level exported API refusals and private bypass guards; include stale warm mirrors/cold restart/empty membership and generation-bound pages. Native effects use trusted scripted dispatcher, exact count and permission refusal; this is not browser/live qualification or independent semantic candidate verification.

## Combined acceptance gate and remaining limits

- Explicit new project creation with actual local actor/scope and real registry/normalizer/compiler checks; wrong actor/domain/project, missing marker, forged prefix/registry, unsupported code/JSON/global/cross-project/publication and unknown normalizer rewrite refuse before mutation/effects.
- Every named ordinary facade, private direct projection/import, exported SQL resource/graph writer, raw canonical put/delete, staged mutation, physical project removal/legacy seeding refuses managed identities. Verify sentinel files/global rows/counters remain unchanged, including absent/warm/malicious mirror cases. A single surviving official ingress blocks activation.
- Complete >100 source/subflow/binding membership and actual project record; same one-generation view drives Flow/router/subflow/instructions/settings/catalogue/graph and selected executor route. Changed page binding or deleted membership refuses without legacy fallback. SQL settings and native permission/consequence checks affect actual execution.
- Separate processes racing full snapshot/settings/instruction/project-lifecycle changes against CAS or transactional dispatch admission see one admitted owner; pending/unknown native claim blocks authority edits until trusted settlement. Stale bindings and tombstones cannot execute. Same mutation replays original recorded binding; borrowed valid snapshot/foreign mutation receipt/corrupt prior rows refuse. If dispatch claims are omitted, production execution is explicitly unsupported, with storage/read scope only.
- Failure at marker/head/receipt/outbox/COMMIT yields complete old/new authority. Lost acknowledgement/relaunch reconciles original key; interrupted projection remains honest and cannot overwrite current authority. No action repeats from restart/reconciliation. Literal kill proof is bounded storage/native-fixture evidence, not browser reset/outcome or power-loss qualification.
- All activation source is integrated and supervisor-reviewed before the endpoint becomes callable. No automatic old-project adoption, ordinary managed GUI edits, code conversion, public Flow publication, cross-project/global source, recording/migration authoring, adaptive mutation, accepting candidate promotion or full A–D/MVP completion claim.

Inspection used current concrete project store/index/manifest behavior, bare UUID createProject, canonical SQLite/memory factories, Flow writer/private save, SQL mutation open boundaries, catalogue history synthesis, full snapshot contracts, compiler/normalizer, API project handlers, and start/run canonical fallback/rereads. This report is an implementation proposal, not verified authority, authorization, restart or execution behavior.
