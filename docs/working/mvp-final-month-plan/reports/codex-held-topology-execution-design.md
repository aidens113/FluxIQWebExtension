## Finding

Do not remove the existing one-Subflow fence on its own. `held-candidate.ts` deliberately permits only the previously selected Subflow and graph, with every Router rule/fallback naming it. `repair-rerun.ts` never reroutes: it executes the selected held graph using the original graph options, preserves previous route decisions and updates only the previous Subflow entry. Those options already contain accepted selected-frame input mappings, `currentSubflowId` and an accepted-store sibling loader installed by `runtime-session/subflow-frame.ts`. A changed Router, new entry or rewritten helper therefore needs a new detached topology adapter, not a broader graph-return shape alone.

Result verification also retains the original `subflowId`: `result-verification/run-outcome.ts` recursively passes the original verification input with only session/flow/check replaced; the service's failed-step retry verification similarly passes the original route's selection. This can resolve the wrong instruction scope and shape after a changed Router. Existing held settlement binds an adaptation ID to the session's performed `answers` verdict, rather than a full topology/pass identity. Current failed-pass checks protect against a failed rerun inheriting an earlier verdict, but cannot establish full-topology provenance by themselves.

## Proposed bounded contract

Introduce an internal immutable held-topology execution identity: project/parent Flow/run, held adaptation ID, normalized topology digest, validated build-plan digest, base dependency digest, authoritative instruction/task digest, and a monotonically distinct pass ID. Clone the validated owner record before awaiting. Freshness checks reread its validated/held status and exact bytes, original instruction authority and current base digest before routing, every child load, after execution and immediately before settlement. A changed/superseded candidate must stop; no accepted graph substitution.

Keep original parent inputs separately when the normal options are first built. Create the held pass from those inputs, preserving dispatcher/native/host, authorized domains, signal, instruction-bound run control, dataset write/parking and normal retry behavior. Clear previous-frame invocation, selected ID, sibling source and approved runtime overlays; disable model diagnosis/live patch mutation for candidate execution. Install t529's loader and the newly selected candidate frame's input mapping, and expose its output mapping. Reject partial/resume invocation for topology rerun: this is a start pass, not a patched-node continuation.

Return a focused held pass result containing identity, fresh Router decision, actual selected candidate Subflow, selected graph, candidate graph definitions for evidence attribution, trace and invoked graph versions. Candidate definitions are not evidence all routes ran. Extend `AutomationStudioRepairRerunResult` and `rerunRepairedFlow`'s internal return with selected Subflow identity and pass receipt. Both service verification call sites and recursive verification must use that selection, including explicit replacement/clearing of old instruction scope. Treat parent task as authoritative, with only the newly selected candidate's actual instruction references supplementing it; a new unsaved Subflow cannot depend on an accepted-store instruction lookup succeeding.

Keep earlier attempts visible as history, but identify the new pass's attempt range and recursively invoked frame IDs. Judge only current-pass graph/read/act/end-state evidence, and its attributed dataset batches, rather than merging an earlier answer into a new pass. Keep every reset/act in history/accounting. Existing `attemptsOfThisSession` alone is insufficient for this distinction when the new session trace appends old attempts. Prefer a shared explicit pass projection and t529 frame evidence over a second recursive implementation.

Record authoritative judgement against that exact pass identity, selected entry and full candidate digest/base/task, not just same run ID or a prior `resultVerification`. Before candidate dispatch remove the previous pass's active verification fact while retaining its historical receipt. A failed/cancelled/parked/stale/unjudged pass cannot apply. Positive result for one selected route is only that route's receipt; whole-candidate apply additionally requires the applicable entry-case receipts from unit 3 for the same candidate/base/task identity.

## Reset and entry-case prerequisite

The trial's `prepareStart` hook precedes the model-free start check; an unset hook records `not_reset`. The build ledger compares opaque domain state through owning arrival/tools and tracks build-owned lasting acts. `repair-rerun.ts` itself has no reset/start-preparation port. A completed creation trial, start-page hint or fresh route observation does not prove the subsequent whole rerun starts clean.

Unit 3 must supply declared applicable cases and exact start receipts bound to candidate/base/task, with fresh Router selection and witnessed reset of only this build/run's attributable acts. Preserve the original run's preexisting lasting state; never use fixture wholesale reset as product undo proof. The final held rerun needs a receipt after the last exploration/trial and before its dispatch. Where prior-run acts need reversal, the originating run's pre-act provenance must be available to the owning reset ledger; the build's later start snapshot must not adopt those effects as the intended baseline. Missing baseline, unidentifiable/uncertain act, failed reversal or unprepared entry remains refused. A provider-free executable case may use a qualified deterministic preparation callback through the same receipt boundary; absence cannot be replaced with a model claim or rollback.

## Settlement and truthful retention

Keep bootstrap apply under its existing parent lock, dependency/permission/normalization gates and topology persistence owner. Add a durable settlement operation identity keyed by held adaptation and exact judged pass. On repeated settlement, read the owning applied adaptation/application proof and return the same decision without a second graph mutation. A record-save failure after successful apply must be reconciled from that proof rather than retrying as a new apply or marking a kept edit rejected.

The current bootstrap apply requires `validated`; it is not an idempotent applied-status success (the runtime-patch reviewer has separate idempotency). Current judged re-author applies before saving the run marker. Its `save_record` failure note is truthful, but does not establish repeat-safe full-topology settlement. Cover this narrow seam explicitly; parent lock alone only serializes execution. Do not treat runtime patch idempotency as bootstrap behavior. Durable proof must name the candidate/pass/task/base being accepted and actual applied owner identity. Preserve automatic/latest-only authorization and reject superseded candidates without erasing failure receipts.

No early accepted Router/helper writes are allowed. Existing apply's rollback handles its own write failure, not safety for executing an unjudged topology. UI should continue t530's authoritative true/false/unknown projection, with specific re-author identity only when actual same-run application proof exists. Missing settlement proof remains unknown/unkept as its owner reports; do not infer retention from revision advance or created IDs.

## Fail-first checks for those units

- Held Router changes selection from accepted entry A to candidate B on fresh host state; old mapped input/source cannot leak; candidate frame outputs match normal saved execution.
- Added/changed helper, nested calls and repeated calls with distinct inputs execute exact candidate bytes with no accepted-store reads/writes. Foreign source/target, stale base/task/topology, missing required state and cancel during child call decline before further dispatch/apply.
- Selected case passes while a declared alternative fails or lacks prepared receipt: no apply. Empty/missing reset receipt after a lasting act, unknown prior act or failed undo: no rerun; existing state is preserved.
- Prior pass `answers` plus candidate pass failed/unjudged cannot apply; prior datasets/read attempts cannot satisfy new-pass evidence. Current child effects/reads are counted once.
- No application before authoritative candidate judgement; changed base between judge and apply refuses. Repeated settlement and apply-success/run-record-save-failure reconciliation mutate once and retain actual proof.
- Cancellation/parked/permission refusal retain normal endings and zero premature durable writes. Successful promotion saves complete owned Router/helper topology and later normal provider-disabled run uses that topology with matching input/output and zero recovery/model interventions.
