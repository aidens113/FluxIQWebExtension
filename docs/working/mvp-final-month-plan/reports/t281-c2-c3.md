## What changed and why

**C2: `R/llm/node-tools/rerun-check.ts` `checked()`.** A check that answered `verified`/`present` used to take the new
value. If the value's `node` differed from `step.actionId`, `actionId` stayed the old action unless the answer declared
one, and a check never declares one. That produced run `run-mux74k5q-1c3c2127`'s step 8: a click holding a type node's
`text`/`submit`. Now, when `value.node` is a string other than `step.actionId` and `parsed.draft.actionId` is undefined,
the check does not take. `took` is false and the step (actionId, input, ranWith and everything else) stays unchanged. The
answer's `rerunCheck.detail` says the new argument names `<node>`, a different action from the step's `<actionId>`, that
the check ran nothing (`<code>`), that the step keeps `<actionId>` and its argument, and that a different action is a
different step to run as a new call with add true. The step's action is still never inferred from `value.node`. Taking
still happens in three cases: a value with no `node`, a value whose `node` equals the step's action, and an answer that
declares an action. I added a header paragraph that cites the run.

Because `took` is false here, the loop's held amendments settle as `failed`, the same as a rerun that did not work
(`evidence-loop.ts` ~L481, unchanged).

**C3: `R/llm/repeat-guard/outcomes.ts`, `R/llm/node-tools/rerun-check.ts`, `R/llm/evidence-loop.ts` (runCall only).**
- `automationStudioNodeRerunAnswer` now returns `checked: boolean`. It is true exactly when the call was sent as the dry
  run's check (`replay: "verify"`) and false for the unreachable put-back and for calls run as asked.
- `AutomationStudioLlmEvidenceCallOutcome` gains an optional `checked?: boolean`.
- In `recorded()`, a checked call still updates `latest` from `stateAfter` and still ends a run of looks

- `runCall` keeps `rerunChecked` from the rerun answer and passes `checked: true` to `recorded()` when it is set. This
  is the only change in `evidence-loop.ts` apart from the variable declaration and the updated comment.
- I added a header paragraph to `outcomes.ts` (run `run-mux74k5q-1c3c2127`, C3, steps 0059-0068) and a line to the
  JSDoc of `automationStudioNodeRerunAnswer`.
