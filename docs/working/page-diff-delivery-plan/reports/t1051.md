# t1051 report: the answer contract reads the asked columns right

## Outcome
Done.

## What changed and why
The misreading is not in `instruction-record-columns.ts` (that only matches names to fields). The reader is
`runtime/flow-authoring/bootstrap/answerability/instruction-columns.ts`; the matching tolerance is in
`runtime/result-verification/asked-words/table-lacks.ts` and `held-column.ts` (called by `cited-yes/records-yes.ts`).
These three are outside the brief's literal owned list but are the cause; no forbidden path was touched.

Cause: "with columns title only" read the last item as the column "title only" (a completeness word kept in the name).
`table-lacks.ts` hid that by treating any held column sharing a word as a match, so a table with the wrong column passed.

- `instruction-columns.ts`: a trailing "only", "just" or "exactly" after a name is dropped (`COMPLETE_LIST_WORD`), only
  after a name, so "only child" keeps its word. General, not phrase-specific to one task.
- `table-lacks.ts`: removed the shared-word tolerance; a named column is lacking unless `held-column.ts` finds it.
- `held-column.ts`: besides exact, and case/space/`_`/`-`, it now meets singular and plural (`titles`/`title`,
  `copies`/`copy`). Other callers of `automationStudioResultHeldColumn` (answer-first narrowing) get the same tolerance.
- `instruction-record-columns.ts` callers (accept, assemble-draft, assembled-record-output, unread-columns) only consume
  the reader's names; their tests pass unchanged.
- Tests: new `answerability/tests/instruction-columns-forms.test.ts` (X only; X and Y only; `columns: X, Y`; "the X and Y
  of each" names none; two-word names; no columns; names containing "only"). In `cited-yes/tests/asked-table-yes.test.ts`
  the old "shares a word is left to the judge" test is replaced by a refutation test and a singular/plural test.
