## What changed and why

### 1. No count ends an evidence loop (brief)

Every ending the brief named is gone from `runtime/llm/**`, for every loop, with or without `loopSignal`:

- looks in a row (`searching.ts`), refused repeats in a row (`refused-repeat.ts`, `evidence-loop/refused-again.ts`),
  refusals of one kind (`refusal-run.ts`), unusable decisions in a row and unreadable replies in a row
  (`evidence-loop.ts`, `unusable-decision.ts`, `evidence-loop/unreadable-reply.ts`), `maxIterations` and `maxToolCalls`
  (`evidence-loop.ts`, `evidence-loop/exhaustion.ts`, `loop-budget.ts`, `provider-task/preflight.ts`, `prior-nodes/**`,
  `node-reruns/**`), the draft-amendment allowance, and the iteration backstop in the loop budget.
- Where a run of these used to end the loop it now climbs the existing loop-detection ladder. New
  `decision-handlers/ladder-top.ts` is the one place the ladder's top is handled: the caller's `loopSignal` decides
  (answer-first ends the round), and a loop with no caller gets "continue", then the caller's own `recoverStall` move
  where it has one (`decision-handlers/repeat-stall.ts` holds the stall moved out of `refused-repeat.ts`).
- Steering is kept and sharpened: each count-based feedback now says plainly what the model keeps doing and that "one more
  is caught as a repeat, and you decide how to go on" (`repeat-guard/feedback.ts`, `candidate-feedback.ts`,
  `loop-detection/feedback.ts`, `refusal-run.ts`, `searching.ts`, `unusable-decision.ts`). `core.loop_decision` is now
  offered to every loop with tools; where no person can be asked (no `loopSignal`), `ask_person` is withheld with
  "No person can be asked from here: what you repeated is yours to change, or finish with the result you have."
  (`loop-decision/options.ts`, `offered.ts`, `ask.ts`, `decision-handlers/model-decision.ts`). All model-facing words are
  generic; downstream model-text passes.
- Unusable and unreadable replies are asked again on the same model with their note, and each costs from the purse.
- Deprecated chain deleted: `unusableDecisions.maxInARow`, `maxUnreadableInARow`, `maxConsecutiveUnusableDecisions`
  (loop-limits, `round.ts`, `unusable-decisions.ts`, `candidate-generation.ts`, `project-build/run.ts`,
  `brief-ports.ts`, `service.ts`), `AUTOMATION_STUDIO_LLM_EVIDENCE_LOOP_DEFAULT_MAX_STEPS_WITHOUT_PROGRESS`,
  `AUTOMATION_STUDIO_LLM_EVIDENCE_LOOP_DEFAULT_MAX_UNREADABLE_REPLIES`, the loop limits' `MAX_ACCOUNTED_TOKENS`, the
  `"turns"` shortfall and `iterations`/`tool_calls` exhaustion bounds, `brief-calls.ts`. Result codes stay truthful:
  `llm_evidence_loop.iteration_limit` now means only "a budget ran out" (purse, tokens or clock).
- The build purse's call allowance (the brief's last bullet) is gone where it is fed: the creation purse takes no
  `maxCalls`, the service and the session-key resolver no longer read `FLUXIQ_LLM_BUILD_CALL_LIMIT`, a project build
  carves each brief's allowance in dollars only (`project-agents/dispatch/start-allowance.ts`, `run-brief.ts`,
  `allowance-said.ts`, `types.ts`), and a Flow's stored `llmExecutionSettings.maxCalls` narrows nothing
  (`flow-execution-limits/resolution-within-flow-settings.ts`). The purse class itself (`runtime/agents/budget`, not
  owned) still supports a call count if a caller passes one; no caller in Core does.

### 2. Coordinator addition 1: call counts in the run budget

- `runtime/llm/run-budget.ts`: the run ledger's policy count is `Infinity` and a declared `maxCallsPerRun` is stripped
  before the generic ledger sees it, so `llm_budget.run_call_limit` is never produced by a run budget. The dollar ceiling
  (`llm_budget.run_cost_limit`) ends a run; `AUTOMATION_STUDIO_LLM_RUN_CALL_RECORD_LIMIT = 250` bounds only the receipt's
  itemised lines.
- The 250-call backstop (`flow-execution-limits/run-call-backstop.ts`) ends nothing. It stays exported because the Flow
  settings check bounds a stored count by it and because `adaptation/recovery/annotation/run-budget.ts` (t1057's, not
  touched) still passes `declaredCalls ?? AUTOMATION_STUDIO_LLM_RUN_CALL_BACKSTOP` as `maxCallsPerRun` into the ledger,
  which strips it. `resolver-contract.ts`' `maxCallsPerRun` is marked deprecated for the same reason (recovery and
  `result-verification/run-outcome.ts` still pass it on).
- **Token ceilings exist and were left.** The ledger refuses on `llm_budget.run_total_limit` (`maxTotalTokensPerRun`)
  and `llm_budget.run_output_limit` (`maxOutputTokensPerRun`), and the evidence loop's own budget ends a round on
  `maxTotalTokens` (exhaustion `budgetBound: "tokens"`). These end runs whose calls report usage; they do not bound
  calls that report none.
- `estimatedCostUsd` stays truthful: test providers were changed to charge per call where a test needs the purse to end
  it, never given a count.

### 3. Coordinator addition 2: provider failures that report no usage

- Non-transient failures already end at the first call through `models/failures/disposition.ts` (auth, empty balance,
  a refused 4xx request): proved by the new tests below, which drive the real harness and fail at call 1 with
  `provider failure: <code>`.
- New in `evidence-loop.ts`: an unreadable reply the provider never billed (no tokens, no cost) is classified as the
  provider failing, not as the model's unusable reply, and joins the existing unanswered-calls outage rule
  (`models/failures/unanswered.ts`, which ends the loop `llm_evidence_loop.provider_unavailable` when the same failure
  repeats). A billed unreadable reply is the model's, asked again and paid for. This is what keeps a broken provider
  envelope from looping to the clock for free. Transient failures are retried as before.

### 4. Proofs added

`runtime/llm/evidence-loop/tests/no-count/tests/no-count-ends.test.ts` (fails before the change, passes after): a loop
with no caller signal that looks, is refused, gets refusals of one kind, unusable or unreadable (billed) replies far past
each old bound runs on, steered and offered its loop decision, until the model's result; `maxIterations`/`maxToolCalls`
given are ignored; through the real harness a stuck model is ended by its purse with
`exhaustion: { bound: "budget", budgetBound: "cost" }`; a provider that always errors with no usage ends at once
(auth, balance, 400) or as `provider_unavailable` (timeout, unbilled malformed reply), never by a count and never by
the clock.
