## What changed and why

All paths are under `packages/fluxiq/src/runtime/`.

### 1. Row handles reach the Flow-less judge's first ask (K5)

- **`result-verification/flow-less/judge.ts`**
  - Right after `automationStudioFlowLessJudgedSummary(...)`, the judge's copy goes through the new local helper
    `automationStudioFlowLessWithRowHandles`, which calls t1087's `automationStudioResultSummaryWithRowHandles`.
  - Where any row shares a label, the copy also gets `validCitation: AUTOMATION_STUDIO_RESULT_CITATION_RULE` (the
    shared rule), appended after the existing members. That is how "the first ask carries the shared rule" is met.
    Where no label is shared, the copy is the same object as before and no rule is added, so ordinary first asks and
    their prompt snapshots are unchanged.
  - The local `CITATION_RULE` is gone. The re-ask notice (`citationsNotMatched`) now uses the shared rule. It leaves
    `validCitation` out of the notice when the copy already carries it top-level, so the rule is not said twice.
  - `read`, which Core checks the reply against, is unchanged and has no handles. The deciding digest is unchanged too:
    `answer-first/completion/shown-summary.ts` calls `automationStudioFlowLessJudgedSummary(...).sent` on its own, and
    that never passes through this helper.
  - The page views stay kept beside the handled copy, because it holds the same `trail` object. I read them from
    `judged.sent` directly anyway.
- **Test: `result-verification/flow-less/tests/judge-row-handles.test.ts`** (new, 4 tests). It runs through the real
  harness with a scripted provider, over garden-centre rows where two share the label "Seed Tray". It checks:
  - the first ask carries `rowHandle` "Seed Tray #1" and "Seed Tray #2", nothing on the third row, and `validCitation`
    equal to the shared rule;
  - the re-ask after a refuted yes says the rule once, and Core's refusal names "Seed Tray #2";
  - the deciding-digest copy holds no handle;
  - rows with distinct labels get no handle and no rule on the first ask, and the shared rule in the re-ask's notice.

### 2. A judge the provider sends on its own request also gets the pages

**The seam.** The Anthropic adapter is the only place that knows whether a judge marked `continuesDecider` really
continues. So:
- the judge now builds every request with the page views, continuing or not;
- the adapter leaves them out only where it builds a continuation.

Every fallback (`own(...)`) sends the one request the harness built, views included. Nothing is built twice. Because
the views travel inside the harness-built request, they go through the harness's run-secret withholding like
everything else, on top of the denied-key screening `page-views.ts` already applies.

- **`result-verification/flow-less/judge.ts`**
  - `pageViews = AutomationStudioJudgePageViews.of(judged.sent)` for every judge, not only non-continuing ones.
    Budget, whole lines, order and screening are still `page-views.ts`'s, unchanged.
  - For a judge marked continuing, the window-fitting form is chosen by measuring the forms without the views
    (`formFor`), because a real continuation does not send them. If it falls back to its own request, the harness steps
    that request down by the provider's own measure (`llm/harness/sized-request.ts` →
    `measureInput` → `continued(peek)`), which counts the views.
  - Header updated.
- **`models/providers/anthropic/continuation.ts`**
  - `automationStudioAnthropicJudgeContinuation(prefix, system, user, { pages? })` deletes
    `context.resultSummary.pageViews` from the judge's message unless `pages: true`.
  - New header paragraph "The pages stay with a judge of its own (t1089)".
- **`llm/anthropic/provider.ts`**
  - Passes `{ pages: again }`. So a continuation asked again with no reply held (`continues_the_decider_again`) keeps
    the views, as t1067's `unreadable-asks/note.ts` already arranged. A first continuing ask leaves them out. The
    in-conversation answer path (`judge-call-answered.ts`) takes only the note, as before.
  - **Size check moved for marked judges.** `prepare` refused a request by its own size before the continuation was
    decided. Now that the request a marked judge was built as carries up to 20,000 page characters a continuation does
    not send, that refusal could fire on a judge whose continuation fits. `prepare(..., sized)` now skips the check for
    a judge marked continuing, and `withinWindow` runs after `continued` only when the continuation is not used. Every
    other request is checked exactly as before, in the same place. The check itself was extracted unchanged into
    `withinWindow`.
  - Header paragraph added.
- **Test: `llm/anthropic/tests/judge-own-request-pages.test.ts`** (new, 6 tests). The fetch is scripted. Each case
  reads the step meta's `continuation` to prove which path ran:
  - **Really continues** (`continues_the_decider`): the appended judge message has no `pageViews`, and the page line
    appears nowhere in the wire. `measureInput` with views equals `measureInput` without them.
  - **No decider held** (`no_decider_request_held_for_this_attempt_on_this_model`): the own request carries `pageViews`,
    last, equal to what the judge sent.
  - **Past the window** (`continuation_past_the_window`): the decider holds about 500k characters of evidence, and the
    judge's limits are 60k/8k/70k. The own request carries the views.
  - **Decider offered no answer tool** (`decider_offered_no_check_answer_tool`): `vi.mock` of `../request.ts` strips
    `core_check_answer` from the decider's tools, since today's builder always offers it. The own request carries the
    views.
  - **Asked again with no reply held** (`continues_the_decider_again`): keeps them.
  - **Held to the window by what is sent:** views too large for the judge's own request do not stop its continuation.
    The same request sent alone is refused with `llm.provider_input_budget_exceeded`.
- **Updated tests (`result-verification/judge-evidence/tests/`)**
  - `page-views.test.ts`: the continuing-judge case now expects the judge port's request to carry `pageViews` last.
    It used to expect none.
  - `replay-judge-pages.test.ts`: the continuing-judge assertion now expects the same views as the non-continuing
    judge. The deciding-digest assertion is unchanged.

## Open questions or contradictions found

- **Where the rule goes on the first ask.** The brief's test wants the first ask to carry the shared rule, but its
  change list says only to swap the local rule for the shared one. Before this change the first ask carried no
  citation rule at all. I add the rule top-level (`validCitation`) only where some rows share a label, which leaves
  every other first ask byte for byte as it was. If the rule should be on every first ask, it belongs in
  `flow-less/question.ts`, and the prompt snapshots would then need regenerating.
- **The `continues_the_decider_again` exception.** A continuation asked again with no reply held keeps the views, to
  preserve t1067's design: that note re-ask carried them before this change, via `note.ts`. Say if a real continuation
  should never carry them. That would mean dropping `{ pages: again }` in `provider.ts` and one test.
- **`prepare`'s size refusal is gone for marked judges.** A marked judge whose own request is too large but whose
  continuation fits is now sent as the continuation. Before, `prepare` refused it outright. I consider this a fix that
  this change requires, not a behaviour change anyone relied on. No existing test covered it.
