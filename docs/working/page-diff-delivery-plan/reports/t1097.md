### The leak

In the test "an interval counts until its first run, an animation-frame loop its first frame, and frames not at all
in a hidden document", `page(t)` is called twice. Each call saved the globals as they stood and added its own
`t.after` restore. node:test runs a test's `after` hooks **in the order they were added**. I checked this on Node
22.23.3 with a scratch test, which printed `after #1` before `after #2`. So the first page's restore put the real
globals back, and the second page's restore then put back the first page's stand-ins. From then on,
`performance` was `{ now }`, with no `getEntriesByType`. Every later file whose stub calls
`t.mock.method(performance, "getEntriesByType", …)` threw `ERR_INVALID_ARG_VALUE`. `page-world/**` sorts before
`runtime/**`, so the leak only appeared in the full run. That is why each click-landing file passes when run alone.

## What changed and why

- `apps/extension/src/page-world/page-work/tests/page-work.test.ts`
  - New `standIn(t)`, which `page()` calls. It saves the page globals **once per test**, through a
    `WeakSet<TestContext>`, and adds a single restore. A second page in the same test no longer saves the first
    page's stand-ins as if they were the originals.
  - The restore puts each global back by its property descriptor, and deletes one that was absent before. If the
    descriptor has a setter, it also sets the value again. Node's `globalThis.performance` is an accessor that keeps
    whatever was last assigned to it. I checked this with a scratch script: putting the descriptor back alone left
    `getEntriesByType` undefined, and assigning the saved value again restored it.
  - Two tests left page work running after they ended. One was a timer due at `PAGE_WORK_HORIZON_MS + 500`, in "a
    timer due within the horizon…". The other was the hidden page's animation frame, in the test above. When either
    fired, the watch's drain callback reached for the global `window` (`page-world/page-work/index.ts:29`). The leak
    used to hide this, because `window` always stayed some leftover stand-in. With a faithful restore it became
    `ReferenceError: window is not defined`, thrown outside any test, and the run exited 1 with every test passing.
    Each test now cancels its own leftover work (`clearTimeout` / `cancelAnimationFrame`). Every assertion is
    unchanged.
- `apps/extension/src/runtime/tests/result-mapping.test.ts`
  - "a known action type passes through unchanged" now sends `web.dom.select` with the least that names an option
    (`parameters: { value: "M" }`) and expects exactly that to pass through (`value` and `options`). Every other type
    is checked exactly as before. A comment names t1081 (`domain/src/actions/select-option-issue.ts`) as the change
    that replaced the old contract.
  - One line added: a bare `web.dom.select` is now a rejection. That pins the new contract at the extension seam.
