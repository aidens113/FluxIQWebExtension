## What changed and why

**F4**

- `domain/src/actions/select-option-issue.ts` (new): the two closed phrases for a select that names no option
  ("no option: the command named none", "option not readable: ..."), the test of a command's parameters against them, and
  the reader of a refusal's `actual`.
- `domain/src/client/gateway-mapping.ts`: a `web.dom.select` whose `option` did not read and whose `value` is not a string is
  rejected before dispatch as `INVALID_PARAMETER`, so there is no verb run and no retry. An empty `value` still counts as
  naming an option (the blank option). `label` beside the target gives "unnamed", `option` without `by` gives "unreadable".
- `domain/src/runtime/llm-evidence/action-failure/refusal.ts` (the domain's refusal; Core has none for this): reads the
  phrase and returns `invalid_input` with reason `parameter_not_readable`, `instead` = one closed code
  `web.select.option.<unnamed|unreadable>`, `missing: ["option"]`.
- `domain/src/runtime/llm-evidence/rejection-next/select-option-next.ts` (new, plus a barrel line) and `next-sentence.ts`: the
  sentence names the shape (`{"by": "label", "label": ...}`, or `value`) and says label/text keys are not read. It echoes
  nothing the model sent.
- `domain/src/output-nodes/definitions.ts`: `value` and `option` of the select node carry a description and an example.
- `apps/extension/src/content/actions/select.ts`: the content verb's own no-option branch (reachable only by a caller that
  skips the domain) carries `INVALID_PARAMETER` and the same leading phrase. `apps/extension/e2e/content/tests/select.spec.ts`
  follows.
- Test: `domain/src/client/tests/gateway-mapping-select-option.test.ts` (replays 0014's and 0026's recorded inputs).

**F3, removed**

Deleted `draft/compose/unused-press.ts` and `tests/unused-press.test.ts`, and the call, import, doc block and barrel line in
`compose.ts` / `index.ts`. `git diff --ignore-space-at-eol` over the compose directory is empty.

## F3: what is open

- **The cause of the miss.** `dead-end.ts` brackets a press that leaves state S with a later step whose state after is S
  again. The press of "2" (step 10) left page 1; every later return to page 1 was a fresh load of the address (steps 12, 15).
  My inference: a whole-state digest of a fresh load differs from the digest the press left (it takes in what the earlier visit
  left on the page), so nothing "came back" and nothing was bracketed. Steps 12 to 16 did bracket because the last of them
  reached page 2 again with the digest step 12 left.
- **What would settle it.** The step record carrying `stateBefore` / `stateAfter` for request 0057's steps 10 to 17. The
  request record shows the draft without them, so I could not read them. With them, step 10's `stateAfter` against steps 12 and
  15's would show whether they differ (and which part of the digest differs, which is the real defect to fix: a digest that
  changes on a reload of the same page).
- Also unknown: whether the real step 10 carried `changed` lines; if it did, `lasting.ts` would also keep it.
- Any fix that needs the host to say a step opens an address passes through the evidence loop (t1078's files).
