## What changed and why

All paths are under `packages/fluxiq/src/runtime/result-verification/`.

- **`judge-evidence/trail-pages.ts` (new).** Picks out the trail pages a standalone judge is shown, in the brief's order:
  - First, the page each lasting act was pressed on, newest first. That is the act entry's own answer page, then the
    nearest earlier page, which covers an act that moved away or a replay step passed over as already done.
  - Then the page each entry landed on, newest first.
  - An entry counts as a lasting act from Core's facts: `judgeAct`, declared consequences that applied or may have, or a
    step passed over. This is the same rule `summary.ts` uses for the before view.
  - Carried entries come first in the trail, so "newest first" gives this attempt's acts first, then carried ones.
  - A `{ sameAs }` repeat stub (`run-trail/repeats.ts`) is read as the page it points to.
- **`judge-evidence/page-of.ts` (new).** The shape-only page finder, moved out of `page-views.ts` so that both files can
  use it.
- **`judge-evidence/page-views.ts`.**
  - `read` now also takes the trail's entries. Its order is: end view (plus the after witness where that is a different
    page), then the before view where a lasting act ran, then the trail pages.
  - A page whose text was already shown is dropped.
  - The pages share one budget, with whole lines only and `linesNotShown` as before. Everything is screened under the
    denied keys.
  - Each trail page is named `trail.<n>`, and the note now explains those names.
  - New `shown(summary, views)` puts `pageViews` last and keeps the views beside the new copy.
- **`judge-evidence/summary.ts`.** The views are now kept whatever the run did. The `stateRequired` gate is gone, and the
  trail is passed from the summary as held, before projection leaves the pages out. The before-view gate is unchanged.
- **`flow-less/judge.ts`.** When `continuesDecider !== true`, every form it sends carries `pageViews` last, the
  window-fitting forms included, so the window measure counts them. A continuing judge's request is unchanged.
- **`verify.ts`.** The Flow judge (used for finished runs and build tests) never continues a decider, so every form now
  carries `pageViews` last.
- **`unreadable-asks/note.ts`.** A re-ask keeps the views where the first ask had them, so the bytes before the note are
  still the first ask's. It now uses `shown`, and falls back to a summary's own `pageViews` when the WeakMap has none
  (fitting copies).
- **Tests.**
  - `judge-evidence/tests/replay-judge-pages.test.ts` (new): the deterministic proof from this run's records.
  - `judge-evidence/tests/trail-pages.test.ts` (new): order, `sameAs`, budget, screening, and a press-and-read-only run.
  - `judge-evidence/tests/page-views.test.ts`: updated, because the first ask now carries the views and the re-ask's
    bytes before the note equal the first ask. Adds a continuing-judge case.
- **Fixture.** `judge-evidence/tests/fixtures/run-mwz29d50-replay-judge.json` (69 KB) is built from the step files:
  - 0008 (c3) and 0018 (c8): the calls and answers, with each answer's `read` member left out;
  - 0006: the page before the first act;
  - 0081: the cart as the replay left it, from the opening look of attempt 3's repair.

  It holds only Lab fixture-site pages (127.0.0.1 bigbox-retail), as the existing `run-trail/tests/fixtures` do. No
  credentials appear in it; a grep for token, cookie, Bearer and sk- found none.
- **Docs.**
  - New paragraph "Page views for a judge asked on its own request" in Core
    `docs/architecture/automation-studio/evidence-window.md`, under "Semantic evidence for result judges".
  - Updated headers in `flow-less/judge.ts`, `page-views.ts` and `note.ts`.

The constraints hold:
- A continuing judge is unchanged; a test checks it.
- The deciding digest is unchanged, because `sent` holds no `pageViews` and no page line; a test checks it.
- Screening applies to every page.
- Core compares texts only for equality and length.

## Open questions or contradictions found

- **Carried acts' pages are held in memory only** (`answer-first/witnesses/carried-evidence.ts`). After a Core restart, a
  carried act has no entries and so no page here. As the brief says, I invented no storage for them.
- **A judge marked `continuesDecider: true` can still go out on its own request.** The provider falls back to the judge's
  own request when it holds no decider prefix, when the continuation is past the window, or when the decider offered no
  answer tool (`runtime/llm/anthropic/provider.ts`, `own(...)`).
  - Such a first ask still carries no page views, because the request is built before the adapter decides.
  - Fixing it would need the adapter to add the views, which touches `runtime/llm/**` or `runtime/models/providers/**`.
    Those are outside my ownership, and the latter now belongs to t1087. I did not touch them.
- **Carried evidence held only two entries in run-mwz29d50:** just the two act calls (c3, c8), not the looks and reads
  before c8 that `act-evidence.ts` describes. So "the nearest earlier page" for c8 was the home page (c3's answer), not the
  product page before the press. The product page still arrives as c8's own answer page.
  - Why the segment was so short (perhaps the journal entries attempt 1 held when attempt 2 opened) is outside this task
    and was not traced.
- **Build-test and finished-run judges (`verify.ts`) now carry up to 20,000 characters of page text on every ask.** After
  `earlierAdvice` it is no longer the last member of the provider request. The cached prefix before it is unchanged, and
  the framework tests that assert `earlierAdvice` last read the judge port's summary, not the provider request.
