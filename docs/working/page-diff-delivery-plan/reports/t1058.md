## What changed and why

1. **Held rows read by any group name.** `scripted-model/scripts/evidence.ts` has `heldRowsOf(entry, evidence)`: it
   resolves a `core.view_reference` through `core.current_view` by `{callId, group, holder: "read"}` and returns the rows,
   so no script compares a group name. `company-website-apprentices.ts` uses it (the literal `"holder:read"` is gone).
   No other script resolved a reference. The apprentices test read fixture now has a `listKey` and a `url`, so Core
   names the group `holder:read:<digest>`; the test asserts that name and still completes. A read with no `listKey` is also tested.
2. **Legal key.** `company-website-saturday-certificate.ts` writes `group_heading`. The test pins the new key and proves
   each written key matches the domain's key rule and that the declaration's `"group heading"` folds to it (the same fold Core's binding applies).
3. **A refusal stops the script.** `evidence.ts` has `callsMade(request, reported?)`: a call whose result has `ok: false`
   throws `The call <id> (<tool>) was refused: <code; reason; instead...>`. All scripts with a `made` or `callsMade` set use it
   (apprentices, saturday, bigbox, crossborder, everything-store, local-classifieds, professional-network). Saturday keeps its
   payload-wide scan for "done" ids and adds the refusal check. Where a script already reports a refusal in its own words, it
   passes `reported` so that message is kept: apprentices' team reads (repaired on a fresh detection), crossborder's `detect-hubs`,
   professional-network's final reads. Tests: `scripts/tests/evidence.test.ts` (new), plus one in the apprentices and one in the saturday test.
4. **Bad field key named (domain).** A read column key that is not a legal record field key now refuses `web.handle.malformed`
   at that key with hint `web.handle.expected.extract_list.field_key` and the issue
   `{code: "web.handle.field_key_invalid", field?, valid: [<legal spelling>]}`. New: `actions/extraction/legal-key-spelling.ts`
   (`webAutomationExtractFieldKeySpelling`), `plan-resolution/extraction/field-key-issues.ts`; edited `columns.ts`, `slot.ts`,
   `resolve-plan-node.ts` (code declared; comments reflowed to stay at 800 lines). Tests: `legal-key-spelling.test.ts`, `field-key-refusal.test.ts`,
   and the two existing tests that pinned the old refusal (`slot.test.ts`, `resolve-plan-node.test.ts`) updated. The `field` of the
   issue is dropped by Core's name bound when the key has a space (`refusal-issues.ts`), so for `"group heading"` the model is
   told `valid: ["group_heading"]` and the hint. Docs: `docs/architecture/build-loop.md` and `testing-facility.md`.

The new tests were written after the fixes, so I did not watch each fail before its fix. Two existing domain tests did fail
on the new behaviour (the old refusal), which shows the change is live.
