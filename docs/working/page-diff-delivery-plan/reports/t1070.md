## Outcome
Done. A refused processing declaration now names each refused part (`where[i]`, `anyOf[g][i]`, `derive[i]`,
`compare[i]`, `sort[i]`, `dedupe`, `columns`, ...), its field and operator, and why. For a pattern, "why" is
JavaScript's own reason. For an unknown field, it lists the fields the schema stores. A leading `(?i)`, `(?m)` or

JavaScript's. Both debug files are written. Nothing is committed.

## What changed and why
Core, `packages/contracts/src/record-sets/process/`. This is the process validation `record-output-contract.ts`
calls. Putting the reasons in the parser means the parser and the reasons cannot disagree.
- `condition/pattern.ts` (new): `readAutomationStudioRecordConditionPattern` gives `{ok, pattern}` or `{ok:false, reason}`.
  - The reason quotes only V8's reason (for example "Invalid group"), never the pattern.
  - A leading `(?i)`/`(?m)`/`(?s)` (or a mix, after a `^` too) becomes the flag.
  - Any other inline group is refused with a hint.
  - It exports `AUTOMATION_STUDIO_RECORD_PATTERN_CHARACTERS` (200).
  - `holds.ts`'s `automationStudioRecordConditionPattern` is now a thin wrapper over it. The run-end filter, derive,
    the parser and the downstream domain's grammar all call that one function, so their parity holds.
- `parse-condition.ts`: `readAutomationStudioRecordCondition` gives every rule a condition broke, with its operator
  and why. `parseAutomationStudioRecordCondition` is that reading with the reasons dropped, so accept and refuse are
  unchanged.
- `parse-processing.ts`: the failure result now carries `refusals: AutomationStudioRecordProcessingRefusal[]`
  (`{code, part, field?, operator?, said}`, type in `types.ts`).
  - Every part is read, so one refusal names all the broken parts.
  - A field that a valid entry names is checked even when another entry in the same list is refused.
  - A column that a refused derive entry would make still counts as derived, so it is not reported as an unknown
    field.
  - Codes are unchanged, except that those extra field checks can add `process_unknown_field` /
    `process_excluded_field` beside an invalid entry.
- `binding/bind.ts`, `result.ts`: the binding passes `refusals` on, leaving out an unknown-field refusal for a
  reference that `unresolved` already explains.
- `binding/refusal-text.ts` (new): `automationStudioRecordProcessingRefusalText` writes the codes, each refusal's
  sentence, then each unbound reference with why and "The rows hold ...".

    `runtime/llm`, which the structure audit refused.

Decision on `(?i)`: translate a leading one rather than add `ignoreCase`.
- A bare source already ignores case, and `/source/i` already exists. An `ignoreCase` key would be a third way to say
  one thing, and would grow the grammar the brief wants kept simple.
- `(?i)` at the start is the PCRE/Python habit models write, and it means exactly the JavaScript flag.
- Only a leading group is read, because a PCRE group further in scopes to the rest of the pattern, which is not a
  whole-pattern flag. Any other inline group is refused, and the refusal says so.
