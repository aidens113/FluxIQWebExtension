# t1066 report: live attempts draw their Flow chart

## Outcome
Done.

## What changed and why
Cause: both chart calls in `run-attempt-command.ts` read `<bundle>/steps`, but a live run writes its steps under `lab-runs/<date>/<runId>/steps` (`stepsDirectory`, line 191). The writer found no draft, and the returned "none written" line was discarded.

- `flow-chart/chart/model.ts`: `ChartRead` gains an optional `stepsDirectory`.
- `flow-chart/read/chart-flow.ts`: `readChartFlow` reads steps from `stepsDirectory` when given, else `<runDirectory>/steps` (so scripted runs and the `lab flow-chart` command behave as before).
- `attempt-lane/live/run-attempt-command.ts`: the per-attempt chart and the run's own chart pass `stepsDirectory`. Both now log the returned line (`[attempt] attempt N Flow chart: ...` / `[attempt] Flow chart: ...`) through the Lab `log`, so a chart that cannot be drawn says why. A thrown error is also logged.
- `flow-chart/tests/write-flow-chart.test.ts`: new test with the steps in a different directory from the bundle. It checks that `flow.png` and `flow.svg` appear in the bundle, and that without `stepsDirectory` the same bundle gives "none written", which is the old defect.
