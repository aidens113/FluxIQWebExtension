## Integration changes I made

- `view-channel/tests/binding.test.ts`: fixed three type errors (the executors are now typed as the loop's own) and
  one statement-packing violation.
- `view-channel/tests/projection.test.ts`: the old equality test now expects the new `split` field. The new split
  test checked the wrong thing ("no attributes in part 1"); it now asserts that every visible line comes before any
  extra line.
- Moved `evidence-loop/tests/answered-split-page.test.ts` to `evidence-loop/tests/answered-request/tests/split-page.test.ts`,
  because the directory had 26 files and the limit is 25.
- `harness-options/tests/binding.test.ts`: three t235/t289-G tests sent undeclared parameters (`selector`, `bogus`)
  only to exercise their own subjects. One test now asserts the new refusal before anything is sent. The other two
  use declared parameters, so they still test what they were written for. The t280 rule there ("never refuses an
  undescribed node") is about the describe gate, not about parameters, so it still holds.
- `evidence-loop/tests/repeat-guard.test.ts` (t1014, "through the loop"): its script repeated the same part run with
  nothing between, which is now steered as a near repeat before the completion it meant to test. The script now
  alternates completion and part run, and the original assertion (the refused completion is steered) passes
  unchanged.
- `domain/.../node-run/replay.ts:403`: test-run replays pass `{ found: before }` to the dispatch, so the page check has
  the page they found. That page exists only for in-place acts; replays of page-moving acts behave as before.
