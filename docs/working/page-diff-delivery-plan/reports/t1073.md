## What changed and why

Core paths are under `packages/fluxiq/src/`, test-runner paths under `packages/test-runner/src/`.

**F2: a follow-on step is lasting by what it declares, not by its verb.**
- `engine/automation/state-routing/decision.ts`: the "state never arose" rule now asks `followOnLasts` instead of `doesAct`.
  - Lasting is: declared consequences, a floor that names permission consequences, explicit lasting risk, a plan claim, or an earlier attempt of that step that landed an effect.
  - A press that declares nothing and claims no act is a navigation and is passed over. The verb floor `commit` alone no longer counts.
  - A node with no trusted floor still uses the old answer.
  - The sometimes-present path (`declaredAct`) is unchanged.
- `engine/automation/contracts/graph-execution-options.ts`: new optional `stepClaimsAct`.
- `framework/.../answer-first/run-acts/run-gate.ts`: the gate sets `stepClaimsAct` to the claim reader it already uses, so a claimed act step is never passed over.
- I did not edit `domain/.../action-effect/table.ts` or `act-not-done.ts`. The verb floor stays correct for repeat safety, and Core cannot tell a click from a download.
- Tests:
  - `state-routing/tests/not-arisen.test.ts`: every press floored `commit`. A plain click after an already-done act is passed over under `executor.state.not_arisen`. A declared click, a claimed click, and a click an earlier attempt landed keep their recovery.
  - `run-acts/tests/carried-press.test.ts`: the "today" test now claims the option press, so it still ends gone. A new test shows an unclaimed plain press after the refused Continue is passed over.

**F5: a superseded paging loop is dropped.**
- New `runtime/flow-authoring/draft/compose/superseded-loop.ts`, called last in `compose.ts` and exported from the barrel.
  - A paging loop (repeat-while span) with no result read and no act claim is left out as `repeat` when a later paging loop holds a result read of the same list (`reads` code).
  - It is skipped if a kept step outside the loop names a loop step in its routing.
  - It applies to the model's own span too. Before, a model repeat made its span the model's, so the draft never dropped it.
  - The model keeps the last word. A step it keeps again loses `drafted` and carries `supersededLoop`, so it is never dropped again.
  - Idempotent.
- `draft/step.ts` (outside `compose/`): added optional `supersededLoop?: true`. It is the only way a model's `keep` can outlive the rule, so the type needed it.
- Tests in `compose/tests/compose.test.ts`: dropped loop; loop over another list stays; settles; a step outside naming it blocks the drop; a model `keep` stands.
- I did not drop the navigate (step 8 in the run) separately. It remains under the existing dead-end and after-result rules.

**F6: the checklist showed an act missing when its step claimed only the choice.**
- Cause: `standing.ts` tried only steps named for the act's own id, so a step named only `a1.fulfilment` left `a1` with no candidate.
- Fix in `bootstrap/instructed-acts/standing.ts`: an act with no named step borrows kept lasting steps named for its choices, but only if `automationStudioInstructedActStepDoesItsVerb` says the step's change shows the act or its words name it. That function is new in `act/evidence.ts`.
  - The borrowed step also counts as making the choices it claims, so no `choice_is_the_act_step` fault appears.
- My first version borrowed any lasting choice-claiming step. That broke two existing tests (`object-binding`, `checklist` quantity), so I added the verb condition.
- Test in `checklist.test.ts`: a lasting step claiming only choices, named "Add to cart", shows `a1` done. A read claiming a choice does not.

**F7: Lab wording.**
- `attempt-lane/live/result-line.ts`: `run_flow_then_repair` now reads "then repaired the Flow where it fell short (the run stopped at a step, or its judge did not accept it)".
  - Core's `path.ts` labels a judge-no repair `run_flow_then_repair`, so the old wording was wrong for it.
  - I did not add `saved.why` to the continuation line, as the diagnosis suggested; that was optional.
- Test in `live/tests/result-line.test.ts`.
