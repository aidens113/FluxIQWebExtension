## What changed and why

Cause (from `reports/t1036/h-column-names-diagnosis.md`): a column the plan renames got the site's word as its `label` and the model's name only as its `id`; Core heads an answer with `label`.

All under `domain/src/`:

- `runtime/llm-evidence/plan-resolution/extraction/retained-schema.ts`: a column whose id is neither its detected key nor its readable name is "renamed" and its label is its id. An unrenamed column keeps its page words or readable name. `webLlmUniqueStoredLabels` still keeps labels unique.
- `.../extraction/retained-output.ts`: a column labelled by its own id takes the label the author wrote for that id (screened with `screenedPageText`, 200 chars). An authored label that is only one of the column's site names folded equal (a stale saved label) is ignored, so saved Flows re-resolve to the asked name. New optional `siteNames` input.
- `.../extraction/site-names.ts` (new): `webPlanSiteNames` gives, for each renamed column, its detected key, readable name and page label. A name two columns share, or that is another kept column's own name, is left out.
- `.../extraction/slot.ts`: the resolved slot carries `siteNames`.
- `.../extraction/stored-columns.ts` (`webPlanStoredColumns`): takes `siteNames` and, before any guess, rewrites record output names that are a renamed column's site name (case and `_`/`-`/space folded, as Core folds) to the plan's key. It returns the rewritten `recordOutput`. This is where t997's site-word binding now lives, so Core binds by exact id and needs no change.
- `output-nodes/extract-list/stored-columns.ts`: `recordOutputNames` split into one visitor (`visitRecordOutputNames`) plus new `webAutomationRecordOutputWithNames`, so there is still one reading of which positions hold names. `column-match.ts` did not already do this (it matches against the read's keys only, and a renamed column's detected key is no longer a key), so nothing was duplicated.
- `.../plan-resolution/resolve-plan-node.ts`: passes `slot.siteNames` and uses the rewritten record output as `authored`.
- Docs: t997 paragraph in `docs/architecture/retained-extraction.md` and the comment in `structure/stored-label.ts` rewritten. They record it as the lead's decision (2026-11-25), reversing t997 to match Core's `label` contract.

Tests:
- `extraction/tests/retained-labels.test.ts`: renamed-column tests rewritten (`host`, `pets`, `plus`-style rename labels are the plan's name); new tests for this run's shape (labels `name`, `price`, `rating`, `process.columns` unchanged), for an unrenamed column keeping page words, and for the author's own label and uniqueness.
- `extraction/tests/stored-columns.test.ts`: a process naming the site key of a renamed column (columns and sort) is rewritten to the plan's name, the schema labels are the plan's names, and every process name is a stored id.
- `extraction/tests/saved-list.test.ts`: a saved step holding the old site labels re-resolves to `name` and `price`.
- `plan-resolution/tests/one-record.test.ts`: existing expectation updated (`item` and `price` were labelled `span:1`, `span:2`).
