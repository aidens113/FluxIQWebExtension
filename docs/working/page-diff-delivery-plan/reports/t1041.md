## What changed and why

Cause (from `reports/t1036/h-column-names-diagnosis.md`): a column the plan renames got the site's word as its `label` and the model's name only as its `id`; Core heads an answer with `label`.

All under `domain/src/`:

- `runtime/llm-evidence/plan-resolution/extraction/retained-schema.ts`: a column whose id is neither its detected key nor its readable name is "renamed" and its label is its id. An unrenamed column keeps its page words or readable name. `webLlmUniqueStoredLabels` still keeps labels unique.
- `.../extraction/retained-output.ts`: a column labelled by its own id takes the label the author wrote for that id (screened with `screenedPageText`, 200 chars). An authored label that is only one of the column's site names folded equal (a stale saved label) is ignored, so saved Flows re-resolve to the asked name. New optional `siteNames` input.
- `.../extraction/site-names.ts` (new): `webPlanSiteNames` gives, for each renamed column, its detected key, readable name and page label. A name two columns share, or that is another kept column's own name, is left out.
- `.../extraction/slot.ts`: the resolved slot carries `siteNames`.
- `.../extraction/stored-columns.ts` (`webPlanStoredColumns`): takes `siteNames` and, before any guess, rewrites record output names that are a renamed column's site name (case and `_`/`-`/space folded, as Core folds) to the plan's key. It returns the rewritten `recordOutput`. This is where t997's site-word binding now lives, so Core binds by exact id and needs no change.
- `output-nodes/extract-list/stored-columns.ts`: `recordOutputNames` split into one visitor (`visitRecordOutputNames`) plus new `webAutomationRecordOutputWithNames`, so there is still one reading of which positions hold names. `column-match.ts` did not already do this (it matches against the read's keys only, and a renamed column's detected key is no longer a key), so nothing was duplicated.
- `.../plan-resolution/resolve-plan-node.ts`: passes `slot.siteNames` and uses the rewritten record output as `authored`.
- Docs: t997 paragraph in `docs/architecture/retained-extraction.md` and the comment in `structure/stored-label.ts` rewritten. They record it as the lead's decision (2026-11-25), reversing t997 to match Core's `label` contract.

Tests:
- `extraction/tests/retained-labels.test.ts`: renamed-column tests rewritten (`host`, `pets`, `plus`-style rename labels are the plan's name); new tests for this run's shape (labels `name`, `price`, `rating`, `process.columns` unchanged), for an unrenamed column keeping page words, and for the author's own label and uniqueness.
- `extraction/tests/stored-columns.test.ts`: a process naming the site key of a renamed column (columns and sort) is rewritten to the plan's name, the schema labels are the plan's names, and every process name is a stored id.
- `extraction/tests/saved-list.test.ts`: a saved step holding the old site labels re-resolves to `name` and `price`.
- `plan-resolution/tests/one-record.test.ts`: existing expectation updated (`item` and `price` were labelled `span:1`, `span:2`).

### Where the two runs diverge

- `flow_not_proven` is **normal and the same in both runs**. Step 0043 of the dev run carries the identical note. Attempt 1 explores and only runs the Flow from step 8 (`core.run_flow {from: 8}`), so no judged whole run is behind the saved Flow (Core `answer-first/attempt/remember.ts:67` `wholeRunYes`; `completion/replay-stands.ts:67`). Attempt 2 is therefore judged in both runs. That judge call is dev's one call, and attempts 3-4 then stand on the record.
- Attempt 2's Flow steps (0029-0042) are identical in both runs: same nodes, all succeeded, 16 rows. The judge's `recordSets.columns` is `["name","price","rating"]` in **both** runs, and so are the sample rows. Both judges answered yes.
- The **only** difference in the attempt-2 judge request (step 0044) is in the evidence. In t1041 it has `witnesses.before = {role: observation, evidence: {}, missing: ["web_judge.evidence_unrecognized"]}`, which Core reports as a gap and turns into `judged_unsure`. Dev's request has no `before` witness. (Dev also has `columnLabels: {name: link_text, rating: number_2}`, which t1041 rightly no longer sends.)
- Why a before witness exists: attempt 2 carried an act from attempt 1. Its decision request lists `{"what":"Accept all","state":"may_have_landed","undeclared":true,"carried":true}`, the cookie banner's button. Dev carried no act (`"carried":true` appears in 0 model requests).
- Why that act was carried: attempt 1's step 0004 (`dom-click` on `Accept all`) answered with `changed` lines. In t1041 those were `t36 "Pickup today, ..." was "Rollbacks on household …"` and `t37 ... was ...`, plus the banner `gone`. In dev they were only the banner `gone`. The bigbox home page's hero rotates every 4 s (`apps/scenario-lab/src/scenarios/bigbox-retail/pages/home-page.ts:37`, `setInterval(..., 4000)`), and in t1041's run it flipped inside the click's before/after window. Everything up to step 0004 is the same script with the same results; this is page timing and has nothing to do with columns.

The chain, file and line:
1. `domain/src/runtime/llm-evidence/node-run/press-effect/change/statement.ts:58`: a line whose words changed is stated `how: "reads"`, even when the page changed it on its own.
2. Core `runtime/answer-first/act-record/gate/read-answer.ts:81`: any `reads` or `rose` line sets `changedState`.
3. Core `runtime/answer-first/act-record/seed.ts:70`: an undeclared act with `changedState` is carried into the next attempt.
4. Core `framework/.../answer-first/attempt/run-attempt.ts:226`: carried acts with no held before reading give `earlier = {}`. Then `witnesses/witnesses.ts:127` `shown()` sets `before = { note: WORDS.notHeld }`.
5. Core `runtime/result-verification/judge-evidence/summary.ts:107` sends that Core-made note through the domain projector as state evidence. `domain/src/runtime/llm-evidence/judge-evidence/project.ts:107` then reports `web_judge.evidence_unrecognized`, and a yes is held unconfirmed with no way to clear it.

### What fixes it (not done here: outside this brief)

- **Root cause (domain, press-effect lane, `node-run/press*` is t1042's):** a press must not be credited with changes the page makes by itself. One option: compare the click's change lines against a second capture taken without acting, or leave out lines inside a region marked `aria-roledescription="carousel"` or `aria-live`, or regions that change between two idle captures. Then a cookie "Accept all" no longer reads as a lasting change.
- **Core (second defect):** Core's own `notHeld`/`takenAfter` before-side placeholder should not go through the domain projector as page state. A judge yes over rows, with no declared lasting act, should not be held unconfirmed because a placeholder is unreadable. That is Core `judge-evidence/summary.ts` and `answer-first/witnesses/witnesses.ts`.
- The scripted model was not changed and needs no change.
