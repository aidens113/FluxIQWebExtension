### The fix: `domain/.../plan-resolution/self-changing/state-words.ts`

- **A link is keyed by what stays the same:**
  - frame and shadow hosts;
  - tag, id, test id, label and class names (sorted);
  - region: `context.landmark` and `context.dialog`;
  - the whole address it leads to: path and query, without fragment (F1).

  The selector is not part of the key. Only links with an http(s) destination are tracked, since only a link can
  be marked.
- **Per address, which links captures showed there.** A step saved by its address (a handle resolution or a host
  absolute target at assembly) finds the link it named: the link at that address whose own words were shown there,
  or the only one there. If two links fit, it marks nothing.
- **Words are state** when the link was shown in two or more wordings that its own act did not leave (t442, t447
  unchanged: `acted()` still records the words an act left in its own document). The address cannot change with the
  words, because it is part of the key. That is F1 by construction: words and address that change together are two
  links.
- **A link one capture shows twice by those facts names no one link,** so its words are never state. Hidden
  elements (`hidden: true`) are not counted.
  - The class names are what keep the cart page's `href="#"` header links apart from its cart link. The evidence
    spells an empty fragment as the page's own address (`llm-evidence/location.ts` `evidenceLocation` drops a
    bare `#`), so "Sign In" there reads as `/cart`.
  - I tried excluding fragment links by their `href` first. It cannot work on the domain side, for that reason, and
    was reverted.
- **The mark carries `href` as the root path with its query,** for example `/cart?view=full`.

### Extension: `apps/extension/src/content/identity/`

- `destination/recorded.ts` and `destination/verdict.ts` compare path and query, not the path alone (F1).
- `destination/region.ts` (new) finds a link's region: the nearest dialog or landmark (`landmarkRole`), or its root
  when there is none.
- `destination/verdict.ts` (F2) counts a rival only when it is in the same region; a link with no region counts its
  whole root, as before. So an open mini cart's "View cart" beside the header's links is no longer a tie (t1071's
  open question 4).
- `score.ts` `ledToDestination`: two leaders that each confirm in their own region are `ambiguous`. The ranking
  within the margin never picks.
- `destination/index.ts`: the header and an export of `destinationRegion`.

## Open questions or contradictions found

1. **F2's "record the nearest landmark's name" cannot be done inside this brief's paths.**
   - The content script already captures it: the pagination nav arrives as `landmarkName: "Pagination"`.
   - The domain drops it before the saved identity: `llm-evidence/elements.ts` keeps only `landmark`, and
     `packet-fingerprint/from-packet.ts` and `plan-resolution/element-identity.ts` follow it. Only the third is
     owned here, and it has nothing to copy.
   - Carrying it would let the place gate (`identity/place.ts`, which already compares `landmarkName`) refuse the
     header's `href="#"` crowd that filled run-mwytbimp's ranking.
   - Suggested follow-up: carry `landmarkName` through `elements.ts`, `from-packet.ts` and `element-identity.ts`.
2. **The class names are now part of a link's identity for this rule.** A link whose class toggles with its state is
   split into two entries and stays unmarked, as before t1071. A site whose class names change per render would
   likewise never be marked. Both fail safe, as no mark rather than a wrong one.
3. **`cart-link-replay.test.ts` lives in `content/tests/`, not `content/identity/tests/`.** I treated it as identity's
   test, since t1071 put the identity fixture there. It is outside the brief's literal globs.
4. **The baseline harness run was built from the tree after F1/F2 but before the defect-2 fix.** That had no bearing
   on the cart link, whose address has no query and whose rival was hidden.
