# Report: fhl-domain-surface

Read-only map; paths are under `domain/src` unless noted. `LE` = `runtime/llm-evidence`. All claims come from header comments and code excerpts, not from running anything.

## Outcome
Done. The domain already prints state as tokens, detects toggles, layers and no-effect from before/after looks, and re-finds stale targets by identity. The model still does these by hand: (a) writes literal values in `where` for membership/sign/bound tests, (b) judges "is this the state I want" from printed tokens, (c) authors undo/reset steps and states in prose what a press changes, (d) decides which column is which from label plus sample. Candidates are in the last section.

## Page view
- Line grammar (`LE/page-view/line/render.ts:1-14`): `<handle> [hN] [kind] ["words"] [icon..] [state tokens..] [group="..."]`, preceded by header lines (`page-view/header.ts:1-17,32-44`: PAGE, URL, VIEW, COVERING, DIALOG, LOADING, FRAMES, ARRIVED, SELECTED, CAPTURE) and marker lines (`structure-markers.ts:1-16`: screen position, `[region]`, `- i/n` list item, `- row r`).
- Which elements get a line: `line/choice.ts:1-50` (rules 1-7: controls, layers, meaningful own-words text, image alts, icon controls, ARIA-group names, merged letterless fragments), with echo-dedupe rules F1-F3. Traits in `page-view/element/traits.ts:56-77`. A div with a click handler or a cursor counts as a control (`traits.ts:92-94`), delegates excepted (`line/control-holders.ts`).
- State tokens (`page-view/element/state-tokens.ts:1-12,27-60`): `placeholder`, `="value"`, select `="label" [a|b|c]`, `checked|unchecked`, `open|closed` (from `expanded`), `selected`, `pressed`, `current`, `marked` (visually "chosen", from the capture), `disabled` (not-allowed cursor, `disabled`, `aria-disabled`), `@column`, link target, `covered-by`, `focused`, `modal`, layer kind, `covers n`.
- Size: no caps on element lines (header comment "no caps", `traits.ts:19-23`; the VIEW line says "n elements ... find_on_page searches the rest", `header.ts:50`). A cut capture is flagged (`CAPTURE incomplete`). Words are cut only for covers (60) and find output (80). Actual bytes on a real page were not measured.
- `find_on_page` (`LE/page-find/search.ts:1-45,60-70`): searches every captured element, hidden and off-page included; exact matches in page order, 50 per page (`:60`); near matches follow (`near.ts`); each match is printed as the view would print it plus the field or attribute that matched; an empty answer names the first 3 wordless icon controls (`:62`). Hidden elements arrive via an `includeHidden` recapture (`page-find/run.ts:37`).
- `describe_element` (`page-find/description.ts:1-12,36-45,66-76`): head line, every attribute whole, box and screen position, and every other evidence field as `context: key=value` (so `checked`, `expanded`, `item`, `cell`, `alike`, `repeats`, `changed`, `recent`); `listWayOn` is withheld from the model (`:30`).
- Left for the model to infer:
  - Toggle meaning: the token covers `checked/selected/pressed/marked`; a control whose state lives only in its words ("Like"/"Unlike") or a class has no token. The domain infers such flips after a press (`actions/toggle-signature/`) but not before one.
  - `disabled` is printed; why is not.
  - Counts: `- i/n` is printed only for lists of more than one (`structure-markers.ts:49`); `repeats` and `alike {index,total}` exist on the element (`elements.ts:147,153`) but appear only in `describe_element`. Badge numbers are plain text.
  - Whether a list is whole: `listWayOn` is captured (`elements.ts:163`) and only the reset list-check reads it (`LE/control-spot/collection.ts:1-20`); not in the view.
  - A select's chosen option comes from `selectedValue` against `options` (`state-tokens.ts:76-80`).

## Read-list structure
- Tool: `detect_repeating_structure` (`LE/structure/detect.ts`) asks the page to run the picker inference (`apps/extension/src/content/extraction/detect-structure.ts:1-30`). With no target it tries the page's runs largest first and keeps the one reading the most items; with a target it walks outward to the nearest run of 3+ identical-template siblings (`infer-list.ts:1-20`). Pairs count when plainly two records (`record-pair.ts`); a table cell is never the record; a `<dl>` is one record (`single-record/`); replies nest into the run (`nested-run/`).
- A targeted call that finds no run is retried once with no target (`structure/detect.ts`, header).
- Packet to the model (`structure/packet.ts:127-215`): handle, list name (`list-name.ts`), `itemCount`, per field `key, label, kind, coverage, at, atItem, sample`, `pagination` mode, `nextPageNote`, `confidence`, optional `record`, `continues`, `atNote`. Selectors never reach the model (D3). Sensitive columns are dropped.
- Field kinds are read modes only: `text|attribute|link|value|column` (`actions/extraction/request.ts:20`); `lines: true` for a container of lines (`:62-74`); `identity: "tracking-free"` for links (`:75`). There is no date/number/price type on a field.
- Typing exists in three weaker places:
  - Label shape: `currency amount` / `number` when every value fits (`apps/extension/src/content/extraction/value-shape.ts:1-40`) and readable labels `price:`, `link:`, `text:` with a sample (`structure/field-sample.ts:20-52`, `MAX_SAMPLE` 40). It changes only the label.
  - Conditions parse the number in the text: `$1,299.00` is 1299, `3.7 out of 5 stars` is 3.7 (`request.ts:102-108`; Core `automationStudioRecordCondition*`).
  - Sort `as: auto|number|date|text` reads absolute and relative dates (`3 days ago`, `yesterday`) (`request.ts:206-212`).
- `where` grammar (`request.ts:96-150`, `condition-grammar.ts`): one `field` (or an own `read`) per condition and one of `is present|absent`, `atLeast/atMost/lessThan/greaterThan` (numbers), `equals/matches/contains/startsWith/endsWith` (one value or a list meaning any), plus `not`. Every comparison is against a literal in the request. Nothing compares a field to a parameter, to another field, or to a run-time set; there are no row-computed columns. The only computed row signals are "the number in the text" and presence.
- Feedback after a read: rejected rows per condition (`rejected-samples.ts`, requested by the exploring run, `node-run/rejected-rows.ts`), the first value each condition read (`seen-values.ts`), up to 3 distinct kept values per condition (`kept-values.ts:1-26`), a sentence when a text condition drops rows that read as numbers (`node-run/numeric-text-filter.ts:1-25`), and no-op conditions named in `dropped` (`request.ts:120-124`).
- Paging: a Flow's read reads one page (`request.ts:178-190`, `paginate_retired`); `Next page {list: handle}` plus a repeat covers the rest (`packet.ts` `nextPageNote`; `plan-resolution/next-page-slot.ts`). Pagination is detected as `none|next_link|load_more_button|infinite_scroll|numbered_pages` (`detect-pagination.ts`, `feed-signal.ts`). The page reveals the end of a lazily drawn list itself (`list-wait.ts:1-20`). A "See all" link is reported as `continues` and never followed.
- Dedupe: `dedupe {by: keys}` (`request.ts:155-165`): first occurrence in page order across pages, after `where`, case and layout ignored; a row with no `by` values is never a duplicate; the default is the whole record; `by` is resolved in `actions/extraction/order-request.ts`; link identity in `output-nodes/extract-list/dedupe-link-identity.ts`.

## Fingerprints and re-find
- Saved identity (`element-fingerprint/build.ts:1-40`): tag, role, implied role, input type, visible text, label, accessible name, id, `name`, each class token, test id, link destination, `drawing` digest for wordless controls (`actions/types.ts:157-166`), `context` (record, dialog, form, landmark, position, shadow hosts), and a `readsWords` flag for read targets (`:175-183`). Selector and xpath ride as locators. Of attributes only `IDENTITY_ATTRIBUTES` are kept (`build.ts:45`). Never value, checked, selected, pressed or expanded. Built from a packet element in `LE/packet-fingerprint/from-packet.ts`, for builds and repairs alike.
- Save-time guard: fewer than 2 independent signals (kind, words, id, testId, name, classNames, drawing) refuses the step as `web.handle.unidentifiable` at its script line (`element-fingerprint/shortfall.ts`, `signals.ts:1-35`; `plan-resolution/identity-guard.ts`). The model is told the code, never which signals.
- Handles are opaque and stable across recaptures and pages within one authoring (`LE/stable-handles.ts:1-30`); the model names a handle, never a selector (`target/override.ts:1-12`). `target/stability.ts` checks that shown handles still name the same selectors before a batched action.
- Re-find at run time: the page looks a control up by id, test id, name, class set, drawing, words and scores candidates (`content/element-finder.ts`, `content/identity/score.ts`). Read targets keep words only as a tie-breaker (`plan-resolution/read-identity.ts`).
- Stale target from its source step (t786): Core re-runs the source step read-only and asks the host which fresh answer is the same item (`runtime/target-reacquire/reacquire-target.ts:1-25`). A control is matched by identity signals (`element-match.ts`). A row is matched by key columns or, without them, by every word column equal while number, count, price and time columns may differ (`row-match.ts:1-25`, `volatile-text.ts`); one match is found, several are `ambiguous`, fewer than two telling things is `unidentifiable`. The host first returns the page to where the source ran (`return-to-source-place.ts`, `source-places.ts`). During exploration a handle whose element re-rendered is re-found from a fresh look the same way (`node-run/retries/looked-up-reacquire.ts:1-20`). A stale structure handle is refused with the current page and, when exactly one element has the old selector, an `instead` handle (`structure/detect.ts` header, t477).
- Where the model still chooses: which handle (among look-alikes and rows); which detected column holds what (label, `sample`, `at`/`atItem`); the `where` literals; `dedupe.by`; sort keys; whether a handle inside a row belongs to the intended row (partly guarded by `atItem` and `plan-resolution/row-context-keys.ts`). `plan-resolution/same-target-identity.ts` and `control-fit.ts` check a handle's fit, not intent.

## Press effects
- A press (`web.output.dom-click`) is judged from the look before and after, by the line facts the model was shown (`page-view/line/facts.ts:1-12`):
  - Page changes as added and removed lines in the words the model reads (`node-run/press-effect/page-changes.ts`, `change/`), also stated to the draft as lines Core reads acts from (`change/statement.ts`).
  - Chosen state of the pressed control from `marked|selected|checked` (`press-effect/chosen-state.ts:1-25`), said as a sentence (`choice.ts`) and stated to the draft as `{key: handle, to: on|off}` (`toggle.ts:13-30`) so Core removes a flip and flip-back pair.
  - Toggle signature output `toggle`: `attribute` (which of `aria-pressed|aria-checked|aria-selected|checked` and the state it left), `name` (words gained and lost, lowercased) or `class` (tokens gained and lost) (`actions/toggle-signature/signature.ts:1-18`; `press-effect/toggle-signature.ts:1-30`). A later `web.dom.click` takes it as `ensureState` and skips when already in that state (`actions/schemas.ts:255`, `actions/types.ts:413,567`). The extension reads states before and after each press (`content/actions/toggle-reading.ts`, `click.ts`).
  - Layer cleared: `layerCleared {signature, control}` when the pressed control belonged to a layer that covered the page and is gone after (`press-effect/cleared-layer.ts:1-25`); Core then replays that close whenever the layer shows (`cleared-way-outs/`, `way-out-handles/`, `node-run/own-layers/`). Answered layer: `answered-layer.ts`.
  - Page notice after a refused press (`notice.ts`); a page line like "Please select a Color" is `web.action.refused_by_page` (`content/actions/click.ts:20-27`); a rate-limit notice is `web.action.rate_limited` with the wait.
  - Navigation: `webMovesThePage` (`node-run/start-location.ts`), the ARRIVED header, state-diff `locationChanged` versus `documentChanged` (`runtime/state-diff/state-diff.ts:1-22`).
  - Which item of a repeating list was acted on (`press-effect/acted-on.ts`, t504).
  - No effect: page unchanged except drawn position and focus, captures whole on both sides (`no-effect.ts:1-25`); uncertain for lasting or toggling presses (`uncertain.ts`, `repeat-press.ts:1-30`).
- Undo and reset today: Core owns a site-reset ledger that is told the act's verb (`node-run/act-verb/act-verb.ts:1-10`); the domain supplies a stateful control's place token and state (`control-spot/place.ts`, `state.ts`, `states.ts`), per-collection item witnesses (`control-spot/collection.ts`), and start-state differences against where the build began (`LE/start-state/differences.ts`). The model is told to leave an already-chosen option (`system-instructions/instructions.ts:77`). The domain reports the toggle signature and place; it does not turn a recorded effect into the opposite press or a destination. Whether Core pairs an act with its undo by place token alone is Core's logic and was not read.

## Existing mechanisms
- Actionability gate in the page: visible, enabled, reachable by hit test at the centre then probe points; `covered` names the layer and its closers (`apps/extension/src/content/action-runtime/actionability.ts:1-30`).
- Press effect wait and one repeat: 1,500 ms window, 250 ms steps (`press-effect/settled.ts`, `EFFECT_WAIT`); repeat only for non-lasting, non-flipping presses; for a lasting press the extension presses once more itself and answers `certainNoEffect` (`repeat-press.ts:13-24`).
- Core default retries around every node a build runs: dispatch, look again, uncertain-outcome, effect check against expected state (`node-run/retries/index.ts`), abortable wait (`retries/wait.ts`), stale-target reacquire inside the retries (`looked-up-reacquire.ts`, `reacquire.ts`, `replay-row-reacquire.ts`).
- Robot checks that clear by themselves are waited out and the command gets the extra time (`actions/check-wait.ts:1-30`, `node-run/cleared-wait.ts`).
- List readiness: wait for the items, then for the list to stop growing, then reveal the end (`content/extraction/page-render.ts`, `list-wait.ts`, `load-retry.ts`); structure detection polls for a run.
- Look until present (`retries/look.ts`); act-landing decides whether a press whose answer was lost landed: control gone is landed, a way-out still shown is not landed, otherwise unknown (`runtime/act-landing/landing.ts:1-35`).
- Replay: reset by navigating to the first step's recorded location, each step re-run with resolved parameters, `remembered` versus `unreproducible` for a missing target (`node-run/replay.ts:1-30`, `missing-target.ts`, `hidden-target.ts` enclosed versus itself).
- Handle-ambiguity and identity refusals, repeated-refusal guard (`LE/repeated-refusal.ts`), refusal diagnostics and next-step sentences (`rejection-next/`, `refusal-diagnostic/`, `action-failure/`).

## Candidate compute-or-enforce points
Each: what the model does now / what the domain could do / where.
1. Membership, sign and bound literals in `where`. Model lists literal values (`not contains [..]`, `equals [..]`, `atLeast 5`). Domain could add computed per-row fields (the number in the text, currency plus amount, a date parsed to a day number, sign, presence flags) and let `where` compare a field to a parameter, another field or a relative date (`price lessThan $param`, `date atLeast today-7`), so the instruction's values are not retyped as literals. `request.ts:96-150`, `condition-grammar.ts`, `plan-resolution/extraction/conditions.ts`, page side `content/extraction/item-filter.ts`, Core record-condition code. A typed field kind (`number|currency|date`) would also replace the label-only hint in `value-shape.ts` (`request.ts:20`).
2. Column type visible to the model. `kind` is a read mode; type is a label hint for two shapes. Domain could add `type: number|currency|date|count|text` and the parsed value beside `sample` (`structure/field-sample.ts:20-52`, `value-shape.ts`, `packet.ts:140-190`).
3. Condition feasibility before the read. Rejected samples show what a condition dropped only after a read (`node-run/rejected-rows.ts`). Domain could check literals against the detection's samples and coverage (a `contains` term never present, a bound that rejects every row, a `matches` over numbers; `numeric-text-filter.ts` does the last only after the fact) and refuse or warn at resolve time (`plan-resolution/extraction/conditions.ts`, `refusal-issues.ts`).
4. Control state before a press. Model infers chosen state from tokens and words. Domain could print one computed `chosen` token for controls whose state is class-, name- or icon-driven, reusing the toggle-signature derive (`actions/toggle-signature/derive.ts`, `class-delta.ts`) learned from earlier presses of the same kind of control (`state-tokens.ts`; `chosen-state.ts:7-12` already defines "chosen" as `marked|selected|checked`).
5. Undo and reset derived from recorded effect. Model authors reset steps and prose. The domain already records per press the `toggle` signature, `layerCleared`, the chosen flip `{key,to}`, the acted-on item and the location move. It could emit, per lasting act, an `undo` descriptor (control place token plus reversed signature, or the navigate-back location) so no one authors the destination: `press-effect/toggle.ts`, `toggle-signature.ts`, `cleared-layer.ts`, `control-spot/place.ts`, `states.ts`, `LE/start-state/differences.ts`. An act that is not a toggle (a cart count change) has no signature today; `page-changes.ts` gives lines only.
6. Expected versus observed effect. The press result gives sentences and line diffs, and the model decides if it is the effect asked for. Domain could compare the observed change (toggle `to`, count delta in the acted-on item, navigation) with the node's declared `done when:` or consequences and flag a mismatch (`retries/effect-check.ts`, `runtime/expectation/`, `runtime/act-landing/`). No numeric badge delta is computed anywhere found.
7. Counts and totals. Model reads counts from `- i/n`, `itemCount`, badges. Domain could print `n of total` for any list and a `listWayOn`-derived "whole|continues" flag in the view and packet (`structure-markers.ts:49`, `elements.ts:147,153,163`, `packet.ts` `continues`).
8. Column choice. Model matches columns by label and sample; readable labels help (`field-sample.ts`). Domain could also refuse a `where` or field whose column type or sample contradicts its use (a bound on a non-number column) (`plan-resolution/extraction/columns.ts`, `unknown-column-issues.ts`).
9. Paging completeness. Model must add Next page and a repeat when `pagination != none` (`packet.ts` `nextPageNote`). Domain could refuse a draft whose read of a continuing list has no Next page step, or add the pair itself (`plan-resolution/next-page-slot.ts`, `own-extraction-list.ts`).
10. Dedupe identity. Default is the whole record; model chooses `by`. Domain could propose `by` from key columns (links, ids) already used for reacquire (`runtime/target-reacquire/row-key-columns.ts`; `actions/extraction/order-request.ts`).
11. Retry window. The effect wait is a constant (`settled.ts`); retries are Core's. Domain could scale it from observed signals (`LOADING busy`, indicators, pending navigation; `header.ts` `loadingLine`).
