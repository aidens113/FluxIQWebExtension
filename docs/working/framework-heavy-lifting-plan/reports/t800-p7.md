## What was built (the gap)

- **K1, dates.**
  - `within: "<n> minutes|hours|days|weeks"` keeps rows dated in [now − n, now], both ends included, measured in
    instants.
  - Relative bounds `today`, `yesterday`, `now` and `<n> <unit> ago` are read against the `now` the condition is
    judged at.
  - Compact ages ("1d", "3h", "45m", "2w", "1mo", "1y", "Posted 2d") are read from row values (coordinator
    addition 1, below).
  - Core keeps one canonical key per meaning. The domain grammar also accepts `after`, `before`, `onOrAfter`,
    `onOrBefore` and `inTheLast`.
  - Shared parity table `AUTOMATION_STUDIO_RECORD_CONDITION_DATE_CASES` (contracts `process/condition/date-cases.ts`)
    runs in Core's parser, judge and run end, the domain grammar and the extension filter.
  - Run end judges relative dates at the run's `started_at_ms`.
  - `extract_list` carries an optional `now`, which the page filter uses when present.
  - Trial read feedback counts the rows a date bound could not read (`undatedByItself`).
  - One `within` line in `flow-script-format.ts`, with a permit-office example.
- **CC1, CC2, CC3 (web fill).**
  - Each packet field carries `type` and `parsed`.
  - Lists carry `fieldMarks`, and per-item `{itemKey, marks}` where the snapshot can prove them, plus `rowIdentity`.
  - New field-spec member `mark: badge|flag|state`. A mark is a column that is absent when off, so Core's existing
    `{field, is: "present"}` keeps exactly the marked rows (fixed wire rule; no Core change). Flags written `""`
    or `"true"` read as on, `"false"` as off.
- **The discriminating-field note** (`flow-bootstrap/listed-values/`, used by `listed-values-advice.ts`). The
  trial now carries `sampleRows` (set in `service/candidate-trial/run.ts`, kept out of the model's evidence), so
  the note names a field that separates kept rows from left-out ones on every sample. With no samples the note is
  unchanged. It is still advice, never a refusal.
- **The numeric-text test, refused once** (`flow-bootstrap/numeric-text/`). A text test that spells numbers or dates
  in characters is refused once (`candidate.numeric_text_test`), naming the number bound, the date bound or
  `within` to write. A resubmission is accepted. Word tests are never refused.
- **`process.where` on a lasting repeat** (`flow-bootstrap/repeat-where/`, wired in `bootstrap-completion.ts`). A
  repeat whose body makes a lasting act over a listing narrowed only at run end is refused at that `process.where`
  (`record_output.process_where_in_repeat`), telling the builder to put the condition on the read. There is no
  automatic move, because the registry has no domain-neutral name for a read's condition parameter. This refusal
  fires every time, not once, and the builder can always meet it.
- **K5, part defaults** (`flow-bootstrap/record-defaults/`).
  - Where a step leaves them out, the dataset id, label, `process.columns` and `process.dedupe.by` (from CC3
    `rowIdentity` when it reaches authoring) come from the one scope part that owes records.
  - Wired end to end for subflow briefs: the dispatcher's `scope.ts` carries `answer.columns`, and the scoped
    submission defaults `partOf` from the scope.
  - With no part, or with several parts owing records, the output is byte-identical.
- **Paging only from a reported `continues`.** The inventory found nothing in Core that adds or requires paging
  without it; the one "move the list on" advice is already gated on `listContinues`. Nothing changed.

## Coordinator additions (lane t795)

### Bare relative dates
`read-date.ts` reads a compact age only when it is the whole value. 14 value-reading cases and 11 condition cases
were added. The domain imports Core's reader, so the twin is identical by construction. Risk: an `auto` sort column
of values like "5m" now reads as dates.

### Date column kept
The domain-neutral rule: a field the record output's own `process.sort` or `process.where` names is kept in the
schema, and so stored, when the step reads it, even when `process.columns` hides it. Detecting "newest" or "in the
last week" from the request alone would need an English word list in Core, so that part was not built. No file
outside the lane was needed for storage.
