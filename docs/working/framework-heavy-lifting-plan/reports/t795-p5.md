## Integration changes I made

- **Interface.** Written before dispatch:
  - `contracts/computed-facts.ts`;
  - `summary.computedFacts`;
  - the eight stub fact modules, the aggregator `computed-facts/computed-facts.ts` and the barrel;
  - `request-rows/every-result.ts` with its test. This is the shared every-result reader, used by F1 and F3, generic list
    nouns only.
- **`columns` fact.** Only a column the build declared can fail. A column read from the instruction's English stays
  information for the judge, as `read-account/unread-columns.ts` designed it. Missing or empty, it gives no fact.
  - Why: a binding Core no should not rest on an English column matcher.
  - It fixed `judge-sees-the-read`.

  the facts, as `verify.test.ts` does.

    pair only once". So the `repeated` Core no is right.
- **K2 `answer.rows`.** Carried in `build-test/task-checklist.ts` and `service/project-build/task-checklist.ts`.
- **Together groups (decision).** One settled member, named in its own sentence with a quote of the request, accounts for
  a group.
  - Every row of a group fails every member, so one stated exclusion is enough for it.
  - A yes that accounts for no settled member is held: under each member where all are settled, row by row where one is
    not.
  - This replaces w1b's "every member" rule, which kept the social T2 yeses held: each held group has an unsettled
    `posted is present` member that excludes nothing.
  - The store holds are unaffected (conditions 3 and 4 are never quoted).
  - Tests rewritten in `request-rows/tests/settled-together.test.ts`.

  - `site-change/held.ts`: a yes over a `not_run` part, or over a `shown` part carrying `notRun`, is now a Core no through
    `computed-no.ts` (`does_not_answer`, fails the run). It used to be held unsure.
