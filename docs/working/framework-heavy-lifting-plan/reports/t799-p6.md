## What was built (by item in the lead's brief)

1. **`clear_interference` rung (CC7).** The client's `obstruction` on a covered or failed dispatch is parsed onto the
   attempt trace (`executor/node-execution/obstruction-of.ts`, `obstruction-way-out.ts`, `opaque-ref.ts`, which refuses
   any `$` key so a client reference can never be resolved from run state). The ladder offers the rung when the
   obstruction has a pressable way out (first `dismiss`, else `neutral`, never `accept`), gated on `mayRepeat`, attempts
   left and not consumed, and not on `retryable`, so a `blocked_by_dialog` gets it. It runs a transient press (no Flow
   node, no consequence) with `controlRef` as its parameters, says it as one interference row, waits for the step's
   state and attempts again; a failed press consumes the rung. `failed-attempt.ts` no longer shows a red "didn't work"
   card before a retry from this rung (rule t774). No obstruction: the ladder is unchanged.
2. **`obstruction` fact and generic kinds.** Kinds are `overlay | notice | rate_limit | assistant | other`; old words
   map (`executor/node-execution/layer-kind.ts`), also in `interruptions.ts runOpenedLayers`, which compared a raw old
   word with the parsed generic one. Layers carry `id` and `controlRef`. A learned handler waits by `obstruction` for a
   layer with an `id`, else by `dialog` (today), keyed by `id ?? name`; `alreadyHandled` accepts both facts.
3. **Handlers from trial interruptions.** `AutomationStudioExploredInterruptions.trial()` records each named close
   with a definition and `controlRef`; `layer-handlers/trial.ts` lowers it into the same handler shape
   (`learnedFrom: "trial_close"`), wired on the candidate, subflow and project-build trial paths and in `service.ts`.
   A handler the plan's check refuses is now dropped alone and named in one submission advice line, never silently
   (`dropped-handler.ts`, `dropped-handler-advice.ts`).
4. **Toggles (`toggle-idempotent.ts`).** A step resolved from a handle whose view says `control.stateful` with
   `ensures` gets `ensureState` at lowest precedence (explored and trial presses decide first). A tie naming
   `idempotentWith` on a node that takes `ensureState` is given `ensureState` instead of the refusal; Core does not
   rewrite to `idempotentWith`, because that would mean reading inside the signature and naming a domain parameter. A
   node that cannot take it is still refused. Trial presses already held every loop pass (t787), now tested.
5. **Pace.** `learnUnhinted` (x1.5 from a 1 s floor, cap 60 s, never below authored) from a `rate_limit` obstruction or
   a cleared `rate_limit` layer with no hint, on the failure path and on a succeeded step; a stated `retryAfterMs` is a
   hint. Core writes the learned pace as the step's `paceMs` at the next submission (`flow-bootstrap/learned-paces.ts`,
   tied by definition and parameters), and the slow-down instruction stops asking the model for `repeat pace:`.
6. **W6 (web).** Generic kinds, stable `id` (hash of role, tag, digit-free name and control names) and `controlRef`
   (`{ selector, element }`, the parameters the click runs with) on cleared layers; `obstruction` on covered and
   hidden refusals with ways out classed dismiss/neutral/accept from structure and the press guard; `rate_limit`
   obstruction on `web.action.rate_limited` (`retryAfterMs` only when stated); the `obstruction` fact answered as
   `dialog` and declared in `WEB_AUTOMATION_FACT_KINDS`; CC9 `control` on handle views from stated attributes and from
   learned word/class signatures.

## Open questions for the lead

- **System-prompt pins.** No change to `plan/flow-script-format.ts` or the system prompt; the prompt-contract tests
  (`llm/deepseek/tests/system-prompt.test.ts`, `conversations/instructions/tests/prompt.test.ts`) passed, so the pin
  file needs no update. Model-facing text that did change: the slow-down instruction (`trial-slow-down.ts`), the
  layer words in trial feedback (`interruptions.ts`), and the dropped-handler advice line.
- **The rung is not reachable on photo-social.** The extension's in-page recovery closes every layer before Core sees a
  failure, sparing only a layer the run opened and tied to the pressed control (`interference/run-opened.ts:41-80`),
  and photo-social has none. A live proof of the rung needs either a realistic scenario with such a layer (a Lab
  change) or a decision that the client should report some layers as `obstruction` instead of closing them itself.
- **Behaviour change without client fields.** A press tied to an explored toggle naming `idempotentWith` is no longer
  refused when its node takes `ensureState` (it gets `ensureState`). This is the "rewrite instead of refuse" the plan
  asked for; it applies to today's web toggles too.
- **Known limits.** In a loop, if the first row a trial passes over was already in the asked state, the step learns
  the reversed signature (CC9 `state` could settle it; Core does not read it). A trial's learned pace is recorded
  whatever its verdict. Persisting trial closes across a project build's reloads needs a `project-agents/record/`
  change (not done). `notice` and `assistant` kinds are never produced by the extension yet.
