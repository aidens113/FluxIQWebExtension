## Decision to freeze

**Emit browser actionability only inside the already-open gateway `payload.actionability`. Lift a validated copy to the new host's public `OutputDispatchResult` and runtime result after gateway acceptance. Do not emit a new top-level `ClientGatewayActionResult.actionability`, extend a failure record, or alter a command receipt.** A new top-level gateway field can suppress an executed result on the old durable path. A reader-only stage is safe preparation, but CC10 acceptance needs actual measured browser production, host lifting, Core consumption/recording, and mixed-version tests.

**Core durable storage is receipt-only.** `client-gateway/service/command-ledger/controller.ts:95-119` writes `commitReceipt` (108), rereads and validates the receipt (110-117), and returns a live in-memory result separately (105/117). A committed command encountered again returns `result_unavailable` (119), not a reconstructed saved result. Do not add actionability to the claim/receipt or claim Core rehydrates it from that ledger. Browser result retention is a separate reconciliation concern. The lead subsequently verified its persistence owners, as recorded below and in [lead acceptance](lead-acceptance.md); those follow-up source claims are the lead's, outside this worker's 26-file inspection.

Expected matrix after the seam lands:

## Truthful production and consumers

Proposed portable contract, for lead approval:

```ts
type TargetActionability =
  | { actionable: true }
  | { actionable: false; cause: "hidden" | "disabled" | "covered" };
```

The browser owns measurement; contracts owns the portable type/reader and closed cause vocabulary; Core reads the generic boolean and never derives control from web failure English. Accept exact plain data objects only: one true-branch key or the exact two false-branch keys, correct literals, no geometry/text/handles/DOM references/accessors. Absence or malformed optional value is unknown. Extract a known own data property without invoking a getter; a bad optional fact must not erase its enclosing result.

Source-supported measurements:

- Down `content/action-runtime/actionability.ts:73-117` checks document connection, visibility, disabled state, scroll/viewport and hit testing. Actual positive branches occur at 91,104,110. The existing report's point/detail stay browser-local.
- `content/actions/click.ts:258-260` measures a negative pre-dispatch gate with `refusedBeforeDispatch:true`; 277 actually presses using the positive report. The early already-in-state success at 253-255 precedes this measurement: it must have no invented `actionable:true`.
- The same click has a measured **post-press covered** branch at 347-351, with no before-dispatch claim. It can truthfully report a negative current target fact while preserving the act's existing effect/uncertainty. This fact alone cannot permit another commit.
- `content/actions/check.ts:50-64` measures reachability before `setCheckedState`; a negative gate is explicitly unacted (60). The later disabled outcome at 67-69 occurs after `setCheckedState` and lacks that claim. Do not infer its actionability solely from the shared `disabled` reason unless that outcome's measuring owner is checked. The hidden-input fallback at 94-98 measures the label actually pressed; keep that target association explicit in implementation.
- `content/action-runtime/results.ts:274-345` mixes closed actionability reasons with other rejection reasons and can promote the failure to dialog/person-needed. It should carry only an explicitly supplied measurement, not classify every rejection or success. `buildResult:585-621` currently drops any new evidence field unless projected deliberately. Auth/challenge failure precedence at 602-604 must stay intact.

Direct typed replacements in Down:

- `runtime/llm-evidence/action-failure/refusal.ts:203-209`: use validated `cause:"covered"` for the covered distinction; preserve the existing failure-code/time-out/person-needed gates (person-needed at 198-199). For old clients, keep the existing closed-token compatibility fallback scoped to a missing valid typed fact; a typed fact must not manufacture a different failure category.
- `runtime/llm-evidence/node-run/retries/answer.ts:38-46,59-61`: use typed covered to keep a genuine cover from being overwritten by an earlier rate-limit suffix. Preserve the all-attempt ambiguity/authority checks at 42-43. Missing/malformed actionability is not permission to suppress a stronger outcome.
- `content/action-runtime/recovery/fault.ts:220-224,275-282,345-356`: replace the hidden/covered/disabled prefix reads with the explicit typed cause while preserving pre-dispatch/effect gates and existing retry policy. Disabled-before-dispatch still requires `failure.effect === "unacted"`; negative actionability supplies no such proof. Existing post-press covered recovery/extra-press policy is separate and must not gain a broader committing retry from this field.

Core has a concrete useful first consumer at `AS/runtime/io-policy.ts`: read the new public field after dispatch and carry a separate exact-target fact into execution outputs/history on both paths, alongside the result status. Record it even when a successful dispatch later fails confirmation, without copying the target fact into that confirmation's effect. `executor/contracts.ts:489-503` already defines **recorded-state readiness**, with elapsed wait/satisfied/condition counts; retain it separately. CC10 should make the exact-target observation available to native/authoring history without inventing a new retry or admission rule. Generic status/transport fallback remains Core-owned; no hidden/covered wording parser moves into Core.
