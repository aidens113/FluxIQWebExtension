## Existing functionality and actual gaps

- **Source re-find is already implemented.** `runtime/executor/target-reacquire/before-attempt.ts:13` returns attempt 4 for the normal four attempts, matching the user's first attempt plus three retries and source re-find after the second failed retry. `step-reacquire.ts` reruns only a read-only source, returns to its source place, matches through the host, rebinds the fresh row/output, and synthesizes a gone failure without dispatch. `lineage.ts` derives row/output lineage from the current graph, including nested-loop ownership. `stale-failure.ts` excludes ambiguous, landed, uncertain and completed acts. Do not globally replace this timing with attempt 2: P8's early identity refresh must be a separate path from the user's source rerun rule.
- **Source-less identity exists downstream for exploration, but not the general Core graph seam.** Core `target-reacquire/contracts.ts` requires `source`, `lineage`, and fresh `candidates`; `step-reacquire.ts` returns immediately without lineage. Downstream `domain/src/runtime/llm-evidence/node-run/retries/looked-up-reacquire.ts` already refreshes handle-resolved controls from a fresh look, matches by fingerprint in the same frame, and replaces the whole stale identity/selector. Reuse `webReacquireElement` and this contract knowledge; do not invent another matcher. General graph playback needs a host request variant for a direct opaque target identity and a fresh-target overlay. Outside-graph retries already accept a reacquire callback and use the shared attempt timing.
- **Typed retry/effect contracts already exist; typed transience does not.** Core `packages/contracts/src/failure/record.ts:42` has required `retryable`, optional `stage`, `effect: unacted|ambiguous`, `retryAfterMs`, `evidenceDigest`, and `certainNoEffect`. Its strict `parse-record.ts` rejects unknown fields, so adding `transient` only to a producer would discard the entire record. Source search found no typed `transient` or `actionable` field in Core packages. `runtime/executor/defensive/thrown-error.ts` already prioritizes status/transport codes, cancellation and bounded cause chains before its English fallback. Preserve those generic transport protections. `llm/repeat-guard/retry-later.ts` still infers retry-later from text; `outcomes.ts:487,528` and `decision-handlers/refusal-run.ts:153` consume it without a typed signal.
- **Authoring repeat guards and state-route guards already exist.** `llm/repeat-guard/outcomes.ts` guards repeated authoring calls using call/page/draft history. `executor/state-routing/progress-guard.ts` stops repeated routes without progress, counts successful distinct nodes and loop body passes, and has a separate reopen guard. Neither is the planned runtime tuple `(node, target, inputs, view digest)` guard: the route guard allows three unchanged returns and body passes count as progress even if the view did not change. `step-loop/loop-context.ts` carries the route guard but no general unchanged-dispatch guard. Failure `evidenceDigest` is not an authoritative digest for every successful view.
- **Skipped-act classification still reads English.** `executor/step-skip/act-not-done.ts:26` inspects control words/label; `state-routing/decision.ts:104` uses it before skipping an optional absent step. Use the trusted CC12 resolver already present in t824 (`options.resolveActionEffect` / run-state action effects), not model metadata or a second effect registry. Preserve the distinction between truthful already-held state and an act never done. Generic commit classification may include dismissals; the typed behavior for those needs explicit acceptance cases rather than preserving a hidden English exemption.
- **Repair history already has state routes.** `recovery/in-run-repair/history.ts` includes retries, handlers, state routes (outcome/destination/refused guards), ladder rungs, prior repairs and counted failures. `llm/harness/task-request.ts:226` defines the recovery kind union. Missing projections are obstruction, pace, and reacquire records already present on `executor/contracts.ts` attempts. History intentionally excludes inputs, outputs and page sentences; retain that restriction. `llm/harness/context-packet.ts:394-419` screens and bounds history, so add projection tests through that boundary too.

Own `executor/step-skip/act-not-done.ts`, `executor/state-routing/decision.ts`, their colocated tests and relevant authored documentation. Do not touch the peer's dispatch/uncertainty implementation.
