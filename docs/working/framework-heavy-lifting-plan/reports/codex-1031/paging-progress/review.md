Findings sent immediately to the lead and producer (line references refer to the reviewed intermediate source):

1. `page-world/press-work/tracker.ts:25` attaches a rejection handler to the Promise returned by an async DOM handler. An ignored rejected handler would normally raise `unhandledrejection`; the new observer consumes that rejection. The direct test checks returned Promise identity but does not cover this host notification. Lead-approved direction: returned native Promises remain unknown without attaching an observer.
2. `tracker.ts:10-30` plus `scheduling.ts:50-58` can mark a visible unreturned async IIFE idle: `() => { void (async () => { await preexistingGate; fetch('/later'); })(); }`. Native await bypasses `Promise.prototype.then`, and the enclosing listener returns undefined. Lead-approved bounded direction: inspect the invoked callback through captured native `Function.prototype.toString`; visible async/await/generator/native/bound/dynamic/uninspectable callbacks remain unknown. This does not claim universal future-work certainty.
3. `handlers.ts:11-34` reads capture as `=== true` and then passes the original options to native registration. Web IDL Boolean conversion admits truthy values: adding with `{capture: 1}` caches under false but natively registers under true, so removal with true fails. A capture getter is also read twice and may produce mismatched cache/native registration. The removed callback can still execute. Native registration/removal/options semantics must be preserved.
4. `scheduling.ts:43-48` wraps an invalid `queueMicrotask` callback into a valid function, changing a native synchronous TypeError into a later error. `scheduling.ts:57-58` tests Promise callbacks by truthiness; native `.then(1)` ignores its non-callable argument, while this wrapper attempts to call it. Both are new wrapper semantics regressions and need direct coverage.

The final frozen-source re-read found fixes and direct regressions for findings 1-4: returned Promises are tainted without settlement observation, click callbacks use a captured native source reader, callback wrappers share identity across capture modes so native options are read once, and invalid callback arguments retain native behavior. The rejection regression additionally has a child-process test asserting exactly one original unhandled rejection identity. The producer reports its narrow run passed 25/25; the reviewer did not execute or independently verify that claim.

Further concrete findings sent during that re-read:

5. `handlers.ts:28` reads an EventListenerObject's `handleEvent` getter before `tracker.run` establishes the causal frame. A getter scheduling a supported timer returns an innocuous synchronous handler; the timer was scheduled with no owners and the click can appear idle. Lookup, inspection and invocation belong within the same tracked call, including getter exceptions.
6. `handlers.ts:18,36` compares the raw event type before native DOMString conversion. A string object representing click registers without a wrapper, and removing a normally wrapped callback with that value misses wrapper lookup. A nullable undefined callback also enters WeakMap storage and throws instead of preserving the native no-op. Exact registration/removal conversion must happen only once.
7. The callback source gate is applied only in `handlers.ts`, while `scheduling.ts` invokes directly wrapped timer/microtask/Promise callbacks without it. A normal click schedules a named timer callback whose own source contains an unreturned native async IIFE; after that timer runs and returns undefined, pending drains while the native async work remains. Applying the same bounded inspection at each directly wrapped callback addresses this without recursively inspecting arbitrary helpers.

The frozen-source re-read also confirms fixes and direct regressions for findings 5-7: dynamic method lookup occurs inside the causal frame, event type conversion occurs once with nullish callbacks delegated, and directly wrapped scheduled callbacks use the same source gate. Native once/capture/removal behavior remains delegated to native registration, with one stable wrapper per original callback; normal function/object receivers and return values are preserved.

## Final accessor confirmation

8. **Coverage reads page-defined accessors before ownership exists.** `apps/extension/src/page-world/press-work/handlers.ts:74` calls `Reflect.get(target, "onclick")` while computing coverage, before `tracker.capture` establishes the event's ownership. An own onclick getter that schedules a delayed timer and returns null is not invoked by native event-handler dispatch; the new probe invokes it, schedules unowned supported work, and accepts coverage. The timer may later start a request after an idle answer. This both changes page behavior and defeats the supported-work check. Inspect the property descriptors and refuse noncanonical accessors without invoking them; read canonical native handler state directly where supported. Sent immediately to lead and producer.
9. **Hook replacement with an accessor can still pass health and execute page code.** `press-work/scheduling.ts:89`, `press-work/handlers.ts:69`, and `page-world/request-starts.ts:34,45` read installed hook properties to compare returned function identity. An accessor replacing a data hook can return the saved wrapper and remain healthy, while its getter schedules unowned work during the query. Because the observer installs data hooks, descriptor/value identity checks can refuse this replacement without invoking page accessors. Constructor identity health checks should follow the same no-accessor principle where applicable. This is the explicit replaced-hook-is-unknown contract, not a demand for hostile-page authentication. Sent immediately to lead and producer.

Final confirmation of finding 8: `handlers.ts:93-107` walks descriptors, refuses own or inherited noncanonical onclick accessors, and calls only captured canonical getters. Attribute inspection uses captured `Element.prototype.getAttribute`. Direct regressions at `press-work/tests/handlers.test.ts:132` verify unknown with zero getter calls and zero scheduled work for both own and inherited accessors; a second regression verifies a page override of getAttribute is not invoked.

Final confirmation of finding 9: handler health checks inspect data/getter/setter descriptors; scheduling health at `scheduling.ts:107` requires the installed own data slot and exact wrapper value. Request health checks use descriptor/value identity for request hooks and constructors. Direct regressions at `press-work/tests/tracker.test.ts:184` and `page-world/tests/request-starts.test.ts:60` assert accessor replacement is unhealthy with zero getter executions, including a request constructor returning its saved original value.
