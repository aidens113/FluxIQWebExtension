## Outcome: Partial

Built:
- **Refutation and re-ask (Core, W1).** A located `asked_missing`, `kept_not_asked` or `wrong_value` defect row is
  refuted by Core's record of that row (`result-verification/located-defects/row-refuted.ts`):
  - `outside_mark`: a left-out row whose item carried the client's `outside` mark. It applies only when the defect's
    request words are first person and negate nothing.
  - `cell_differs`: the row's own cell in the named column is non-empty and does not match the claim.
  - `not_kept`: a claim about a kept row, made of a row the result does not hold.

  A no whose every row is refuted is asked once more instead of the generic t752 recheck
  (`refuted-no/refuted-rows-recheck.ts`). The recheck carries Core's evidence, lists the rows reversed and asks the
  converse question. After that re-ask the verdict is `answers` if every latest no is wholly refuted
  (`core.result.no_refuted_by_record`) or if the re-ask said yes with no refuted citation. The rows are recorded as
  `refutedRows`.
- **Marks (downstream + Core, W2).** The extension reads per-item offer controls (`content/extraction/item-offer/`)
  and sends them as `rejectedMarks` beside rejected samples. They pass through the checkpoint, the domain summary and
  Core's `service/summaries/extraction-summary.ts`, and arrive as a condition's `leftOutMarks` and a together set's
  `marks`. Build-test rows (`build-test/read-rows.ts`) read `marks` too.
- **Cited yes (W3).** The verification diagnosis offers `checked`, which the harness accepts and
  `llm/verification-checked/` reads. `result-verification/cited-yes/` checks each cited cell against the stored rows.
  A yes with a refuted citation is unsure (`core.result.yes_citation_refuted`); a yes with no `checked` is unchanged.
- **Provenance, located-only advice, Core `standingNo` (W4).** Earlier advice carries only defects Core located
  (`standing-no/earlier-advice-located.ts`). Trial feedback carries `provenance` (`judge_said` / `core_found`). A
  computed-fact Core no carries a `standingNo` record with `source: "core"` (`standing-no-record/core-record.ts`).
- **Interface, written by me before dispatch:**

  - together-set `marks` in `contracts/read-account.ts`;
  - `refutedRows` and `yesCitations` in `contracts/verification.ts` (`refutedRows` extended later for `wrong_value` /
    `not_kept`);
