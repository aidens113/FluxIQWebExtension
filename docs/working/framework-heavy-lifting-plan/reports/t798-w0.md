## What changed and why

Goal 1, `packages/test-runner/src/flow-lane/creation/candidate-outcome.ts`
- `chatDraftVerdict(said, trials, kept)` now decides in this order:
  1. the last trial session's own verdict (source `session`);
  2. the candidate in Core's build failure diagnostic, read through `get-flow-bootstrap-failure` (source `diagnostic`). It uses the last trial's verdict, or `not_tested` when the trial count is 0;
  3. a trial run that did not succeed, which is Core's own `execution_failed` (source `session`);
  4. only then Core's closing sentence (`sentence`, `draft`, `none`).
- The diagnostic is read only when no trial session carries a verdict. A read that fails propagates (the structure audit's failure-as-empty rule forbids swallowing it). The call passes the project's domain, as `failedBuildOf` does, and `build-from-chat.ts` now passes `scope.domainId` to it.
- `CreatedFlowCandidateOutcome` gains an optional `verdictSource`, and the draft failure's details carry it when it is set.
- The draft failure message no longer says "judged unknown". It says "was not judged" for `not_judged` and "left no verdict Core recorded" for `unknown`.

Goal 2, `packages/test-contracts`
- I first added `not_judged` to `RunEvaluation.reportedVerdict`, then removed it again (source, validator and test). No producer can set it: `lane-observation.ts` already writes `unverified` for a run Core says was not judged, and the evaluation writer does not see judge calls. A union member with no producer would be dead.
- The producer of "judged unknown" in mvrj-a44a was the draft-failure message above. That is fixed through the candidate outcome's existing `not_judged` verdict.
- `packages/test-contracts` has no net change.
