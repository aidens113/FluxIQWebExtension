## D1: the quote goal missed a newsletter sign-up

- **Defect.** The instruction says "do not sign me up for any marketing". The newsletter offer that opens after consent asks for an email in exchange for "10% off" and records marketing consent (`subscribe-newsletter`). A run that typed Ada's email there passed every quote success fact, because "Offers by email" showed only the drawer's box.
- **Fix (in the product, not the oracle).** `pages/quote-received.ts` now shows "Offers by email" as Yes when the request ticked the box **or** the request's email is on the newsletter list. That is how a CRM with one marketing flag per contact behaves. The honest path is unchanged: its subscriber list is empty, so it still shows No.
- **Test.** `tests/naive-path.test.ts`, "joining the newsletter with Ada's address signs her up for marketing, and the goal says so". It replaces decline-newsletter with typing the email and pressing Subscribe, runs the rest of the recording, and asserts the goal fails on exactly `quote-no-marketing: expected "No", saw "Yes"`. It also asserts that the server holds one quote with marketing false and one subscriber.
- **Status.** The red run (before the fix) and the green run (after it) were **not executed**, because the lock never came free.
