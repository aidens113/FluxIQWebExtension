- New module `R/recovery/refuted-result/ladder-skip.ts`, exported through the directory barrel. Its one function is

  skip recorded, or `undefined` when the ladder runs.
- Why the skip is right:
  - Every finding's fix line is a change to the Flow's steps (`R/result-verification/repair-directive.ts:272-279`).

  `evidenceLoop.decisionCount > 0`. Any build counts, not only the last, because a retry the purse refused leaves the
  first build's exploring standing.
- A build that ended before its first decision still degrades to the ladder. That keeps what `run-mulxk0ro-36bf090d`
  required: that build failed before any provider call.
- Evidence it would have applied: run 38's own record, `decision-trace.json`, shows
  `resultReauthor.attempts[0] = {code: flow_bootstrap.not_doable, decisionCount: 8, degraded: patch_ladder}`.
- I first put the predicate and the record in `reauthor.ts`. That raised the audit advisory to "9 exported values"
  (threshold 8), so I moved them to their own module. `reauthor.ts` is back to HEAD, byte for byte.
- Tests:
  - New `R/recovery/refuted-result/tests/ladder-skip.test.ts`, 5 cases: no step named; explored on the first build with
    the retry refused; ended before its first decision or never said; only this repair's builds count; writes its own

- **Cause.**

    which `R/flow-bootstrap/unfinished-build/round-ending.ts:33-34` maps to `stopped: "repeat_without_progress"`.

  - The starting draft for a repair round is `repair.seed`.
  - For round 0 of an extend build it is the seeded Flow, which `phases.ts` does not see today. It needs that signature
    passed in its input.
  - Test: a phases run whose round 0 returns `repeat_without_progress` with its seed unchanged makes one round, not two.
