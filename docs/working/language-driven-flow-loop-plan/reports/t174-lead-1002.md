## Task 2: why playback did not skip an absent popup

Investigation: `t174-w60-absent-step-routing.md`. Implementation: `t174-w62-absent-step-skip.md` and
`t174-w63-interruption-optional.md`.

### Cause

1. **Playback never treated a missing target as page state** (Core `R/executor/graph-run.ts:572`). When a press's
   target was not found, the run did three things in order:
   - emitted "Recovery started" (`:581`);
   - ran the recovery ladder, where `retry_node` (priority 4) beats the step's own failed route (priority 5, in
     `recovery-ladder.ts`);
   - only then followed an optional step's `failed -> merge` edge.

   An absent popup therefore cost 3 dispatches (about 24 s per run on muq66ff9) and showed as a recovery. The existing
   test `optional-failed-route.test.ts:58-84` pinned that behaviour.
2. **A dismissal was optional only if the model said so.** Otherwise it was optional only if the dry run found it
   `unreproducible`. A popup the site *remembers* passes the dry run as `remembered` and stays a fixed step
   (`R/flow-draft/site-memory.ts:33-38`). The reason is that the host recorded nothing about the press's layer. That
   is how run 38's `s2` and `s4` stayed mandatory, as cause C9.
3. **Run 38's "Core resolved neither target" is a misreading.** `unresolved_no_candidates` is Core's status for
   *every* web press: Core leaves resolution to the host (`R/io-policy.ts:240-250`). The host presses only an element
   whose words, name, label, id or test id match at 0.92 or above. So s2 and s4 most likely pressed the real popups,
   although no screenshot proves it.
4. **Not present at all: routing to the node whose expected state matches.** No build writes a node pre-state
   (`readyState`), so nothing could compare one with the page. That is a follow-up (see below).

### Fixes

- **F38: Core executor.** `R/executor/step-skip/absent-step.ts` applies when two things hold:
  - the node is sometimes-present: either the optional shape (a `failed` edge into a Merge that `success` also
    reaches), or `metadata.sometimesPresent`;
  - the host reported `target_not_found`.

  The run then skips the node:
  - The attempt becomes `status: succeeded`, `route: skipped`, `skipped: {reason: "target_absent", code}`, with no
    `failure`.
  - No ladder runs, no budget is spent and no defended fault is recorded.
  - The card reads `Skipped “Not now”: it was not shown`, never "Recovery started".

  A node with an unmet `readyState` is skipped the same way, with zero dispatches. Anything else keeps the ladder:
  - a step that is not sometimes-present and has an absent target;
  - an optional step that fails in any other way.
- **F39: domain and Core. A press that answered a layer makes its step optional.**
  - Domain: `webAnsweredLayer` (`D/node-run/press-effect/answered-layer.ts`) answers true when two things hold:
    - before the press, the target lay in a dialog or front layer;
    - after it, on the same page, that layer is gone.

    When it holds, the draft statement carries `interruption: true`. The layer predicate is shared with
    `covered-target.ts` through `layer-element.ts` and `layer-member.ts`.
  - Core:
    - `readCallRecord` carries `interruption` when it is `true`, and withholds any other value; it never refuses one.
    - `automationStudioFlowDraftInterruptionStepIds` (`sometimes-present.ts`) selects steps with no acts and no
      routing.
    - `draft-routing.ts` wires those steps as optional on a copy. The model's draft is not rewritten.

    Steps that do an instructed act are never made optional.

Together these give the following:
- **Popup present in playback:** it is pressed as before.
- **Popup absent:** the run uses one dispatch (the host's own wait, at most 5 s), then skips the step and goes on. The
  skip is not a failure and no recovery runs.

## Follow-ups (outside this lane's files)

- **Routing by expected state** (the second half of the user's rule) is not built. It needs two things:
  - a node pre-state written at build time: the domain can write `exists`/`absent` from the page before the press,
    through a declared `readyState` parameter or a plan-node metadata channel;
  - a Core `R/executor/state-routing.ts` at `graph-run.ts:456` that, on a readiness miss, jumps to the first later
    node whose pre-state holds, before the ladder.

  It needs its own design brief.
- **Dry-run gate.** `R/llm/node-tools/dry-run-gate.ts` does not count interruption steps as conditional. Only the
  routing does.
- **Layer-scoped resolution for dismissals.** In `apps/extension/src/content/action-runtime/resolve-target.ts`, a
  generic "Not now" or "Close" should resolve only inside a dialog or front layer. That needs a target-context field
  in `ranWith`.
- **Lane B (ladder):** `retry_node` after a `target_not_found` the host already waited out doubles the wait for every
  non-optional absent target. `clear_interference` never fires, because no build writes `clearsInterference`.
- **Risks:**
  - A large `frontLayer` element, such as a sticky header, that disappears after an in-place press would mark that
    press as an interruption.
  - A press inside a modal whose dialog element is replaced counts as having answered it.

  Act-claimed steps are excluded from both, and the skip applies only when the target is absent.
- **Two leftovers from earlier reports:**
  - F33: the incomplete-draft store (`flow-bootstrap/incomplete-draft/kept.ts`) keeps a step's `control`.
  - F35: the recorded-Flow lane's final-state message still names no facts.
- **`graph-run.ts` is at 789 lines**, against a hard limit of 800.
