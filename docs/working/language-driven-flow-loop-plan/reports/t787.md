## What changed, by fix

1. **A layer cleared while exploring becomes a handler (fix 1).**
   - **Domain:** `node-run/press-effect/cleared-layer.ts` reports `evidence.layerCleared` ({signature, control}).
   - **Core recording:** `flow-bootstrap/explored-interruptions.ts` records it from the permission wrapper.
   - **Core handler:** new `flow-bootstrap/layer-handlers/{patch,explored,index}.ts`. `patch.ts` is now the one handler
     shape, and `service/runtime-session/interruption-handler.ts` uses it too. `candidate/submission.ts` adds the
     handler to every non-recovery part (`inherit: false`), unless a step already makes that press.
   - **Wiring:** `service.ts` and `brief-ports.ts`.
   - **Directory move:** `candidate/` was at its 25-file limit, so the new modules went to `layer-handlers/`.
2. **The in-run handler (fix 2): the cause was not the layer line.**
   - **What really happened:** `t275` resolved to the layer's element. The model wrote the condition's `fact` as a
     description, which the domain fact query answers `unknown`. The worker showed this by running
     `domain/src/runtime/facts/query.ts` on the saved conditions. A `when` that answers `unknown` never holds, so the
     handler was skipped without any record.
   - **The fix:** new `recovery/annotation/patch-fact-kind.ts`, called from `step-evidence-resolution.ts`. For a repair
     condition about a control named by handle, it takes `fact` from `op`. A comparison that never says what it
     compares is refused (`recovery.fact_kind_unread`), so the repair answers `none` and records no adaptation.
   - **Not built:** the layer-line refusal the brief asked for. It would have refused the correct fix in this run.
   - **Wording:** I applied the worker's suggested `fact` description in `llm/harness/runtime-patch-schema.ts`.
3. **Trial-pass toggles (fix 3 and 3b).**
   - **Extension:** `click.ts` reads its own control before and after a press made in place and reports `toggle`.
   - **Domain:** `actions/types.ts`, `client/gateway-mapping.ts` and `io/gateway-output-dispatcher.ts` carry it to
     `outputs.result.toggle`. The attribute rule is shared in `actions/toggle-signature/output.ts`.
   - **Core:** `explored-toggles.ts` gains `trial()`, and `toggle-idempotent.ts` matches a node's own earlier trial
     press. `candidate-trial/run.ts` and `subflow-trial/run.ts` record into it, wired through `service.ts` and
     `brief-ports.ts`, which now share one record.
   - **Existing bug found and fixed (t775):** `submission.ts` wrote `ensureState` only into `buildPlan.plan`. The
     trial graph and the saved graph are built from `buildPlan.subflows`, which was stale. The submission now
     re-validates the rewritten plan. Test: `candidate/tests/toggles/tests/submission-toggles-graph.test.ts`.
4. **Per-pass witnesses and direction (fix 4).**
   - **One witness per pass:** new `trial-change/pass-witnesses.ts`.
   - **Direction:** `proof.ts` gives `contradicted` for an `adds` part whose control witness went back to the build's
     start counts, with finding `result.change_contradicted`.
   - **No pass:** new `trial-change/contradicted.ts`. Both gates turn a judged yes on `contradicted` into a **no**,
     with Core's words as `changeContradicted`.
   - **My wiring:** I connected `port.start` in `site-reset/{trial-change-port,ledger,project-reset}.ts`, so the
     direction check works in a real build, not only in tests.
5. **The Lab's budget label (fix 5).**
   - **The finding:** in `live-llm/budget.ts` and the new `live-llm/budget/`, a Core reservation overrun within
     every cap is a `reservation_undercounted` finding. It goes to `snapshots/live-llm.json` `findings` and to the
     settle event.
   - **The lane:** `flow-lane/creation/lane.ts` judges and publishes the run first, then throws the breach with the
     run's own failure as its cause, on both paths.
