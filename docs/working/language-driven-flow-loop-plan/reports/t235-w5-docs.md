## What changed and why

Core, `docs/architecture/automation-studio/llm-flow-bootstrap.md`:

1. New subsection **"The catalog an evidence decision is shown"**, at the end of "Context boundary". It says the one-shot `flow_bootstrap` call is still sent the whole catalog. It describes the evidence-decision payload: `nodeCatalog` as `{category: ["<id>: <description>"]}` with its ordering, the constant `nodeCatalogNote`, and `describedNodes`, which is append-only and in first-described order. It says `catalogTruncated` and `catalogSelection` are not sent and that the packet keeps the whole catalog for checks. It also covers:
   - `core.describe_nodes`: takes `{ids}` with at most 64 ids, is observe-only and offered only beside `core.run_node`, returns a receipt, refuses a call naming only unknown ids as `describe_nodes.unknown_nodes`, keeps build-scoped memory shared by every round, and is `pageless` with the state-digest hook skipping it.
   - The rule that describing first is advice and never a gate.
   - A failed `core.run_node` call, including an `amend_draft` rerun, describes its node and reports `described`, `definition` or `undeclaredParameters`. Core replays pass through.
   - The reason for the change (user, 2026-10-01; 41,122 of 58,547 characters).
2. Evidence-guided completion paragraph: "Every path sends the whole catalog." now reads that no path cuts the catalog: the one-shot path sends it whole, an evidence decision sends names plus the definitions it asked for, and a link points to the new subsection.
3. Cache-order paragraph (`providerUserPayload`): the constant head now lists "the policy gates and the catalog context (node names, note, `describedNodes`)". A sentence was added saying `describedNodes` is the only part of the head that grows, and since it is append-only it keeps the cached prefix.
4. Evidence-guided generation paragraph: "Every task carries the current filtered node catalog" now reads "...node catalog by name with the definitions the build has described".
5. "Evidence-decision context carries the whole node catalog" now reads "every node by name and the definitions the build has described". A sentence was added that `add`/`act` are explained once, on the first tool variant that can act, and offered bare elsewhere.
