- **Fix 2b** (`activity/wording/act-words.ts`).

- **Fix 3** (`located-defects/untested-column.ts`, new, and `condition-authored.ts`, new).
  - The tested column comes from the authored step, or from the row's `label — column: value` form.
  - When neither gives a column, behaviour is unchanged.
- **Fix 4a.**
  - The shape is `{"field":"posted","atLeast":"2026-09-19","as":"date"}`, plus `atMost` for a range, with both days included.
  - A bound must state its year and be unambiguous. A relative bound or a day/month that could swap is refused at plan time.
  - A row whose date cannot be read is never kept, even under `not`, and is counted as `undated`.
  - The stored condition drops `as`: a bound written as text is what marks a date. This was a design call, made so the domain plan resolver's key-by-key copy carries the condition unchanged.
- **Fix 4b** (`service/candidate-trial/row-mark.ts`).

- **Brief 5** (`request-rows/unquoted-rows.ts`, `summary-reads.ts`). A settled condition is accounted for only by a sentence that itself names it and itself quotes the request. Answer columns no longer count as condition names.
- **Brief 6** (`agreement/unsettled.ts`, plus my `agree.ts` edit). `unstatedExclusion` now runs for `model_unconfirmed` as well. `reasked` is set only for `model_disagreed`.
