### Fix 2 (R3): a rerun that writes a column under a new name renames it (Core)
- Cause: a rerun's `input` is a JSON merge patch, so 0047's restated map `{name, mutualFriends, confirm}` ran as
  `{name, mutual, confirm, mutualFriends}`, and 0051's corrected map merged back into that same failed call and was
  refused as an exact repeat the model never made.
- Change: a key the patch adds whose value is the word of exactly one key the patch leaves out (or an object that
  restates that key's stored object) renames it; the new key takes the stored value merged with the patch, so a renamed
  column keeps its withheld `selector`. Numbers and flags never rename; a value several left-out keys hold renames none.
  The amendment schema's `input` text now says "a key left out is kept, and a new key given a left-out key's value
  renames it".
- Files:
  - Core `R/llm/evidence-loop/rerun-input.ts`

  - Core `R/flow-draft/amendment.ts` (the `input` description only)
- Message: `Core: a rerun that writes a column under a new name renames it rather than keeping both, and the schema says a left-out key is kept (run-murdouox-c5294247 R3)`

  model saw from one the draft screen withheld (`selector` in a re-author's column specs) without the domain's denied
  keys, and the loop input does not carry them. Wiring: add `deniedEvidenceKeys` to `AutomationStudioLlmEvidenceLoopInput`
  (`R/llm/loop-configuration.ts`), pass `this.llmEvidenceRuntime?.deniedEvidenceKeys` at `R/service.ts:1572` and the
