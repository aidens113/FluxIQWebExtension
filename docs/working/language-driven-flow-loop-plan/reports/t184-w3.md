## The fix (local-classifieds offer oracle)

- **Defect.** The goal facts were the receipt ("Offer of £140 sent to Morgan Tate", which reports only the latest offer) and Buying = 3 (which counts conversations, not what went into them). A run that sent the ready-made message the instruction forbids, waited out the 8 s rate limit and then offered, passed. So did a run that offered twice.
- **Fix, in the product.**
  - `readouts.ts` gains `conversationText`: "You've sent Morgan Tate 1 offer" / "… 1 message and 1 offer". It counts only accepted contacts; refused ones never went.
  - `view/listing.ts` renders it in the action bar as `data-testid="marketplace_conversation"`.
  - `route.ts` returns it from `receipt.json`, and `client/listing-script.ts` refreshes it after every send.
  - `manifest.ts` adds the fact `only-the-offer` to `playbackGoal.successFacts` and to `expected.finalState`.
- **Why this is right.** It tightens the oracle rather than loosening it. The honest recording still passes (browser-verified), and every wrong run now fails at least one fact.
- **Tests.**
  - `tests/session.test.ts`: the new test "the offer goal holds for the one honest offer and fails every run that did something else or something more" covers nothing sent, message then offer, two offers, the asking price, e-folding, the honeypot and a second seller.
  - Two existing assertions in the same file changed: the list of test ids now includes the new readout, and `receipt.json` now carries `conversation`.
  - `tests/browser.test.ts`: the test "pressing Send on the ready-made message, then offering once the rate limit allows, misses the goal" fails exactly on `only-the-offer`, which reads "You've sent Morgan Tate 1 message and 1 offer".
