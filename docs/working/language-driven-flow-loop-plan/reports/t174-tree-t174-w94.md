# t174-w94: cancelling toggle pair (cause 2 of run-murwd8le-79e735a8). Investigation and design

## Outcome

Done, for the investigation and design phase. I edited no source and ran no builds, because a live Lab run is in flight on this tree.

The lead's design holds, with three corrections:

- **Key.** Use the stable handle as the opaque key. A hash is not needed.
- **Pairing order.** Pair halves by draft position, never by detour digests.
- **Acts and the model's override.** Clear the act claims of the dropped halves, and never re-drop a half the model puts back.

I recommend one extension: rule (b), for a lone reversal of a step that is outside the Flow.

### 2. Why the current code ships s8 + s13

Draft step 7 (0013, Space Grey on→off) was kept with `add` and claimed `a1.colour`. Step 13 (Add to cart) was refused, so it is not proposable. Step 14 (0028, Space Grey off→on) was `taken`. Step 15 (Add to cart) was kept with `add`.

`KeepOpeners(15)` walks back like this:

- 14 is taken and changed the page, so it is on the way.
- 13 is passed over because it did not work.
- 11 (quantity, kept by the 0025 amendment) is where the walk stops.

So 14 becomes kept. `withoutDetours` never sees step 7, and could not match it anyway. The state after 14 (7-in-1, Spain, coupon, quantity 3, colour on) is not any earlier whole-page digest. A cancelling pair on one control is invisible to whole-state digests, so the domain has to name the control.

### 3. Chosen design

**Contract.** Add `toggle?: { key: string; to: "on" | "off" }` to the draft statement.

- The domain sends it only when a mutate node that does not move the page flipped the chosen state of the control it acted on. This is exactly `webPressChoice`'s condition: the same location, the handle's line on both sides, and a chosen-token (`marked`, `selected`, `checked`) difference.
- `key` is the canonical handle (`t941`). A handle names one control on one page for the whole Flow's authoring (`stable-handles.ts` header, scoped per project+flow). It already crosses to Core and the model in `input`, so it exposes nothing new.
- It passes `EVIDENCE_CLOSED_CODE`, so a hash is not needed.
- Core reads `key` as an opaque code and `to` as one of two words, and never parses web text.

**Core parse.**

- Add `"toggle"` to the exact key list at `evidence-loop-decision.ts:222`.
- A malformed value is withheld, not refused, following the `interruption` precedent. The parse keeps it only when `key` matches `EVIDENCE_CLOSED_CODE`, `to` is `on` or `off`, and the statement's effect is mutate.
- Carry it through `call-record.ts` and the `tool-execution.ts` type, and store it on the step as `toggle`.

**Ordering constraint.** Core must land before or together with the domain change. The key list is strict, so a domain that sends `toggle` to an older Core gets every toggling press recorded as a failed call (`draft.unknown_key`).

**Core rule.** New module `flow-draft/reversal.ts`, exporting `automationStudioFlowDraftDropReversals(steps): AutomationStudioFlowDraftStep[]`, which returns the steps it took out. It runs right after `KeepOpeners` at both join points (`evidence-loop.ts:216` and `amendment.ts:329`).

For each kept step L that carries a `toggle` and has no `cancels`, taken in position order:

1. Find P, the latest step before L by position that is proposable, carries `toggle` with the same `key`, and is not a step Core already took out. A step Core took out has `cancels` set and is not kept, and it is treated as transparent.
2. **Rule (a), the pair.** If P is kept, `P.to !== L.to`, and neither has `routing`, set both to `dropped` and set `P.cancels = L.id` and `L.cancels = P.id`. Clear both halves' `acts`.
   - Reasoning: with two states, an opposite-direction adjacent pair returns the control to the state P found it in, so the pair is a no-op whatever happened in between.
   - This is the murwd8le case: steps 7 and 14 are both dropped, which leaves s8 and s13 out of the Flow.
3. **Rule (b), the lone reversal.** If P is not kept (taken, dropped or exploratory by the model) and `P.to !== L.to`, drop L only, with `L.cancels = P.id`.
   - Reasoning: L only puts back what an out-of-Flow step changed, so in the Flow it would flip the control the wrong way.
   - The case it closes: the model `drop`s step 7 after the 0027 refusal and then adds the re-press. Today the Flow would be that single re-press, which un-chooses a colour the page arrived with.
4. If `P.to === L.to`, something the domain did not see changed the control between them. Leave it alone.
5. **The model's override.** A step with `cancels` is never dropped again. When the model `add`s or `keep`s a half back, the step becomes kept and still carries `cancels`, so its decision stands.

**Draft entry.** In `entry.ts` `stepLine`, for a step that is not kept and has `cancels`, add one line, worded in positions through `automationStudioFlowDraftStepById`:

- Pair: `out: "taken out by Core: step N pressed the same control back, so together they changed nothing; add both back only if a step between them needs it"`.
- Rule (b): `"... it put back what step N did, and step N is not in the Flow"`.

The text is paid for only on such steps. The shared `AUTHORED_INSTRUCTION` does not change.

**Why this design and not the alternatives:**

- **Extend `withoutDetours` or the opener walk. Rejected.** Whole-state digests cannot isolate one control, as section 2 shows, and the walk stops at a kept step by design (t174/F41).
- **Pair halves by `ranWith` equality. Rejected.** It would need no domain change, but the element identity may record state-dependent attributes, so the two halves may not compare equal. The handle is the domain's own robust identity.
- **Drop only when the in-Flow walk is uninterrupted. Rejected.** Steps 8-11 lie between the pair, so this would not fix the failing case.
- **Only tell the model (Causes row 2's other option). Rejected as the primary fix.** The model ignored the change lines and the w82 sentence twice in this run. The drop is visible, can be undone, and is checked by the dry run.
- **Make the Flow-writing step conditional instead of mutating the draft. Rejected.** The interruption precedent rewrites only the written Flow. Here the dry run, the checklist and the model would then read a draft that differs from the Flow. Mutating at join time keeps one truth.
- **Rule (c), a whole-build state simulation from the arrival state. Rejected.** It drops any toggle whose `to` equals the simulated state. An unobserved reset, such as a reload between presses, makes it drop a genuine step, which the local rule in step 4 avoids.

### 4. Edge cases

- **Steps between the pair that needed the un-chosen state.** Example: a box checked, a revealed field typed into, then the box unchecked. Core cannot know this generically.
  - After the drop, the draft must still replay clean before it is proposed (`dry-run.ts`). A step between that needed the state fails there.
  - The `out` line tells the model to add both back, and `cancels` keeps Core from removing them again.
  - The dry run's `notInFlow` hint will not name them, because a dropped step ends that walk. That is why the `out` line carries the instruction.
- **Draft numbering.**
  - A disposition change never renumbers, so every position the model was shown stays valid.
  - Amendments read in order within one decision see no shift.
  - Held rerun amendments are unaffected.
  - The flow signature changes, as it should for a changed draft.
- **Act claims.** Step 7 claimed `a1.colour`. After clearing, `a1.colour` is a todo with `no_step_named`.
  - The checklist is information since t195, not a gate.
  - `CHOICE_INSTRUCTION` (`instructed-acts/check.ts:155-158`) already tells the model to name "the step after which the page showed it chosen".
  - Moving the claim automatically to the nearest earlier kept step was rejected. Here that step is s6, the consent "Accept all", and an act on an interruption step makes it non-optional (`interruption.ts:35`).
  - Keeping the claim on the dropped half was also rejected. It would read `step_not_kept` and invite a `keep` of half a pair.
- **Openers of a dropped half stay kept.** Example: a drawer press brought in only for L. This is harmless, since it only opens the drawer, and it is out of scope.
- **Options in a radio group** (choose Red, then choose Space Grey back) carry different keys and are not detected. That is out of scope. A radio option cannot be un-chosen by pressing it again, so it never produces a toggle pair.
- **Handle lifetime.** The stable-handle registry is in memory, per runtime instance (`tools.ts:282`). After a service-worker restart in the middle of a build, a seeded step's key could coincide with a new control's handle. A false pair is recoverable: the dry run fails, the `out` line is shown, and the model adds the steps back. Every handle in `input` breaks on the same restart anyway.
- **Rerun.** A rerun that takes a step's place (`evidence-loop.ts:481`, `automationStudioLlmEvidenceRerunReplaced`) runs after the pass at `:216`, so a rerun toggle is not paired until the next join.
  - Acceptable. Alternatively, call the pass again after `:481`, which costs one line.
- **Written steps** never ran, so they never carry `toggle`. Carried steps (`f<n>`) carry none either.
- **A half with routing** (`optional`, `repeat`, `only_if`, `on_failed`) is never paired, to stay conservative.
- **Progress or stall counting.** The decision that triggers the drop is the one that kept a step, so `authored.advanced()` still reports progress.
