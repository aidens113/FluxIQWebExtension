## What each worker did

### Fix 1: a page can witness a creation (worker-heavy)

Report: `reports/t791/fix1-page-destination.md`.

- **How Core does it.** Core builds a page-level collection from any complete read of a page in the same tab, an empty
  page included, when the client reports the page's scope and its item subjects (`site-reset/page-collection.ts`).
- **The receipt.** That read prints `destination-N` with `page: true`.
- **What it witnesses.** Only an identified creation that names the ref, in the same tab, whose subject was absent
  from the page before.
- **How a trial reads it.** The trial-change delta reads the page again afterwards. Either the subject appearing or a
  change in a digest of the page's shown values counts as `changed`, which the proof reports as `shown`.
- **Domain.** No source change was needed. A new domain test confirms that a div-row page and an empty page both report
  scope and subjects, and that a cart line's subject token equals the item page's.
- **Why no new witness kind.** I agreed with the worker's choice not to add a `page` witness kind. It would have meant
  editing `packet.ts`, `proof.ts` and `findings.ts`, which another worker owned at the time.

### Fix 4: an unwitnessed step's trial runs (worker-heavy)
