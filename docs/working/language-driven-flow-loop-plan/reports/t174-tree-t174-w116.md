1. **D3, `activity/wording/reason-text.ts` + `activity/observer.ts`.**
   - `automationStudioActivityReasonText` takes a third argument, `{ decision?: boolean }`.
   - With `decision`, it drops each sentence that names an act id (`/\b(?:acts?\s+)?[a-z]\d+(?:\.[\w-]+)?\b/`, which also
     catches page handles such as `t985`). It also drops each sentence in the draft's mechanics: acts, draft,
     amend*, unreproducible, rerun, retest, replay, dry run, tool_call, "step N", and "complete with / the draft…".
   - A reason with no sentence left is nothing, so the heading shows the action alone.
   - The observer applies it to the decision reason before the reason goes to the thought or to the held edit.
   - The result check's verdict (`result-verification/check-activity.ts`) does not use `decision`, so the judge's
     sentences about "the draft" are kept.
2. **R3, `llm/step-log/answer-step.ts` + `llm/decision-handlers/amendment.ts`.**
   - **Deviation:** I did not put the check on the trace row. The row is recorded, and its answer step written, before
     the amendment check exists. `tell()` runs after the no-progress guard, whose count the check carries, and the
     guard's stall and end paths need the row already in the trace. Adding `amendmentCheck` to
     `AutomationStudioLlmEvidenceLoopTrace` would also break that type's rule that every member be carried by both
     rebuilders. Those are other files, and they would put the model-facing text into the stored trace.
   - Instead, `automationStudioLlmStepLogAnswer(row, env, told?)` remembers, in a WeakMap keyed by the row object, which
     folder each amend row was written to. A second call for the same row object with `told` rewrites that step's
     `result.json` with `told`; it does not open a new folder or a new index line.
   - `tell()` now finds the row it answers in `context.trace` (the latest `amend_draft` row of that iteration) and makes
     that call with the feedback, so the settle path is covered as well.
   - `applied` in `result.json` is now `draftChange.appliedCount` when present, otherwise `amended`. This fixes 0061's
     `applied: 0` beside `appliedCount: 1` (a rerun counted in one and not the other).
   - The feedback's own `applied` (main path) now also counts the rerun (`amended.applied + (rerun.request ? 1 : 0)`), as
     the history and `draftChange` already did, so `told.applied` agrees too. The settle path's count is unchanged.
3. **D2 card, `ui/activity-action/action-of.ts`.**
