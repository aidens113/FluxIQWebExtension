### Cause 4: why the handle was stale (root cause, found in this task)

The crossborder item page mints its element ids fresh on every load (`apps/scenario-lab/.../markup/shell.ts`
`rotatingId`, keyed by `state.views`). The Specification group's id, for example, is `fb<base36>`. The extension's
volatile-id check (`apps/extension/src/content/selector/volatile-identifier.ts`) judges the id by its shape:
- On some loads the id looks machine-made, so the selector climbs past it and is structural.
- On other loads the id looks like a word, so the selector is anchored on it, as `#fb… > div > div`.

So the selector's **shape** changed between loads. The domain's stable-handle registry matched controls across a
recapture in three tiers, by exact address, by loose address plus words, and by loose address alone. A loose address
removes only `:nth-*` positions, so it changed along with the shape, and all three tiers missed. Each anchored load
therefore spent new numbers. The step logs show it:

| Step | Load | 7-in-1 | Space Grey | "Color:" |
| --- | --- | --- | --- | --- |
| 0050 | structural | `t985` | `t974` | `t971` |
| 0063 | id-anchored | `t1194` | `t1183` | `t1180` |
| 0067 | structural | `t985` | `t974` | `t971` |
| 0073 | structural | `t985` | `t974` | `t971` |

0063 sent `t985` and 0067 sent `t1194`: in each case the handle the model had read on the previous load. Both were
refused `handle_not_in_packet`. 0073 sent `t985` onto a structural load, so it hit by coincidence.

**Fix (domain, keeps Core generic): tier 4 in `rebound`.** An element that tiers 1-3 left unmatched is matched by
everything except its selector: its page, frame, record and tag (`placesOf`), plus its words. It is matched only when
all of the following hold:
- exactly one element in the whole capture has that place and those words;
- exactly one unclaimed number was last seen with them;
- that number's control is not still standing at its own old address on some other element.

A wordless control is never matched this way. A number found by tier 4 is also filed under its new loose address. The
`seen` record now keeps `place` beside `loose` and `words`. With this change a reload keeps a control's handle, and
`step-place.ts` can keep sending the handle the model read before the reset.

**Core: the refusal now says the page was put back.** `automationStudioNodeRerunPlaceNoted(place, ran, replaces?)` takes
the replaced step's position and its `words`. `words` is the domain's description of the new argument, which
`evidence-loop.ts` asks for before the reset. When a put-back rerun's answer is a refusal (`ok: false`, read the way
the loop reads it), the `rerunPlace` note adds:
- `named`: the control's words, for example `"7-in-1"`;
- a `detail` saying the page was put back where step N started, which loads it again; that the rerun was asked on the
  page as it loaded; that a name read on the page before may name nothing, or another control; and to find the named
  control and name it as this answer's page shows it.

`rerun-check.ts` passes `{ step: replaces.position, words }`. Core cannot know which handle names the control now,
because handles are domain tokens. So it names the control by its words. With the domain fix, the handle should rarely
need renaming at all.

### Cause 6

- **Move:** `moveStep` in `amendment.ts` serves both `reorder` and `add` with `to`. After a real move it clears
  `replayed` on every step from the lower of the old and new indexes onward. Each of those steps now runs after
  different steps than the test ran it after. Steps before the move keep their marks. A settings-only `reorder` onto
  the same position clears nothing.
- **Rerun:** a checked rerun that takes the new argument (`rerun-check.ts` `checked`, on verified or present) now
  deletes `step.replayed`. A plain rerun already produces a new step without a mark (`rerun-replacement.ts`). A failed
  rerun leaves the original step, whose mark is still accurate.
- **Dry-run rows:** `automationStudioFlowDraftDryRunFeedback`, when given `steps`, adds `actedOn` to each row that did
  not replay. `actedOn` is the step's `replay.from`, carried opaquely and never read. The step is found by `stepId`,
  which survives a move made after the test, and otherwise by its position at test time. Replayed rows carry nothing
  extra, so a passing test pays no bytes for it.
- The `replayed` doc in `step.ts` now says when the mark is cleared.

## Open questions or contradictions found

1. **`ranOn` on dry-run rows needs files I do not own.** Each outcome is built in Core
   `runtime/llm/node-tools/replay-draft.ts`, and Core has no generic page token from a replay answer. The answer's
   `routeState` is the page the call *left*, and it carries the whole `controls` list, so it is far too big for a row.
   The generic design would be:
   - (a) the domain's replay answers report the page they ran on in the same opaque shape as `replay.from`. That means
     domain `node-run/replay-answer.ts`, or a new execution key, which also means Core
     `llm/evidence-loop-decision.ts` `AUTOMATION_STUDIO_LLM_EVIDENCE_TOOL_EXECUTION_KEYS`; that file is on my Must-not-
     touch list;
   - (b) `replay-draft.ts` copies the token onto the outcome as `ranOn`;
   - (c) `dry-run.ts` shows it beside `actedOn`, which is a one-line follow-up in a file I own.
2. **Other moves of steps are still stale.** A `drop` or `withdraw`, and a rerun that takes the replaced step's place
   (`llm/evidence-loop/rerun-replacement.ts`), also change what runs before later steps, and they keep those steps'
   marks. I kept to the brief's "moves or reruns". The same rule, clearing from the changed index onward, would fit
   them, but `rerun-replacement.ts` is not mine.
3. **The extension's volatile-id check misses ids like `fb1x3k2a`** (the shape `rotatingId` mints). Tier 4 makes the
   handles robust to that miss. A Flow written against such an id would still be unreplayable, which is outside this
   brief (`apps/**`).
4. **Shared files.** `flow-draft/step.ts`, `entry.ts` and `amendment.ts` already held uncommitted reversal-pair work
   (`toggle`, `cancels`, `takenOutLine`, `automationStudioFlowDraftDropReversals`), last written at 11:36. I made only
   targeted Edit-tool changes on top: `moveStep` and the `replayed` doc. `entry.ts` is unchanged by me. The supervisor
   should check that no live worker still holds those files.
