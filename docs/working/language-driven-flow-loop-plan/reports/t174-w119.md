# t174-w119: a covered target's refusal names the least-consent closer of a consent layer

## Outcome

Done.

## What changed and why

Files owned and edited (named before editing):
- `domain/src/runtime/llm-evidence/node-run/covered-target.ts`
- `domain/src/runtime/llm-evidence/node-run/tests/covered-target.test.ts`

Cause: `closersOf` picks `closeWith` by matching only `CLOSE_WORDS` (×, close, dismiss, no thanks, not now, ..., got it).
At step 0032 of `run-musq0b1m-0472cfa0` the cookie layer `t1067` (`kind: consent`) held "Cookie policy", "Manage choices",
"Reject non-essential" and "Accept all". None starts with a close word, so `closers` was empty, the refusal had no `closeWith`
and fell back to the "close or answer it" text, and the model picked "Accept all". The welcome popup in the flash run had
"×" and "No thanks", so its refusal did name closers.

Fix: when the cover is a consent layer (`kind === "consent"` or `isDialog.kind === "consent"`), `closersOf` returns its
least-consent answers first (`LEAST_CONSENT_WORDS`: reject, decline, refuse, deny, disagree, "necessary/essential only",
"only necessary", "continue without accepting"), then its plain close controls (×, Close, ...). Any control that reads as
consenting (`CONSENT_WORDS`: accept, agree, allow, ok, got it, i understand, continue, yes) is left out, unless it is itself a
least-consent answer. The fix only changes what the refusal tells the model. It refuses nothing: the model may still press
"Accept all", and no other code path changed. Layers that are not consent layers keep the old rule: "Reject" is not treated as
closing a promotion popup. `run.ts` already passes `covered.closers` into `closeWith`, so it needed no change.
`docs/architecture/build-loop.md` does not describe `closeWith`, so it was not touched.
