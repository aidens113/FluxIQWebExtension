## What changed and why

### Task 1: the reset closes tabs FluxIQ opened (cause 15). Implements reports/t174-w93.md.

- `domain/src/client/close-opened-tabs-parameter.ts` (new) exports `WEB_AUTOMATION_CLOSE_OPENED_TABS_PARAMETER = "closeOpenedTabs"`.
  It is exported from the barrel `domain/src/client/index.ts`.
- `domain/src/runtime/llm-evidence/node-run/replay.ts`: `resetPage` sends `{ url, closeOpenedTabs: true }`. It imports the
  constant through the client barrel, because the structure audit refuses the deep import. A replayed Flow navigate does not
  carry the key.
- `apps/extension/src/runtime/fluxiq-opened-tabs.ts` (new) exports `fluxiqOpenedTabs`, which has these methods:
  - `note(tabId, sourceTabId?)` and `forget(tabId)` keep the record.
  - `recorded()` reads the record, for tests.
  - `closeAll()` returns `{ closed, returnTo? }`. It removes every recorded tab, passes over a tab that is already gone, and
    forgets each one as an automation tab too. `returnTo` is the source tab of the oldest recorded tab, if that source is still
    open and was not itself recorded. That tab becomes the automation tab.
- `command-options.ts`: a new `closesOpenedTabs(action)` reads the key from `options`. There is no typed field for it.
- `action-runner.ts`: for a navigate that carries the flag, `afterClosingOpenedTabs(request)` calls `closeAll()`.
  - If the tab in front (`activeTabId`) was one of the closed tabs, the navigate runs on `returnTo`, or else on
    `latestOpenAutomationTab()`.
  - A person's tab in front is driven as before.
  - `updateTabUrl` already brings the driven tab to the front.
  - A forced new-tab navigate (`forceNew` and `drive.opened`) is recorded, with the previously driven tab as its source.
- `click-landing.ts`: `driveOpenedTab` records the opened tab with its source. `closeOpenedTab` (the 429/503 path) forgets it,
  but only once `tabs.remove` has succeeded.
- `browser-tab.ts`: `openTab` records the new tab, with the previously driven tab as its source. `closeTab` forgets it.
- I did not edit `automation-tab.ts`. The `forceNew` case is recorded in `action-runner.ts`, which knows the source tab. The
  plain fallback automation tab is not recorded, as the design says.
- **Is playback's own start covered? No.** The Lab prepares playback in
  `packages/test-runner/src/run-scenario.ts` (`prepareFlowPage`, `moment === "playback"`, about lines 292-318). It uses
  Playwright `page.goto` on the home tab and never sends the reset navigate.
  - For a `scenario-start-page` start it leaves every other fixture tab open. Even for a blank-tab start it only blanks
    those tabs; it does not close them.
  - Expected result: one item tab left by the last build test (it is closed only by a later reset), plus the tab playback's own
    click opens. That should be home plus two item tabs, against home plus three before, but this was not run live.
  - That file would need to close the other scenario-origin pages in `context.pages()` before playback. I did not edit it.

### Task 2: a remembered step no longer waits (cause 7)

- `replay.ts` `replayStep`: after the `before` page read (taken only for in-place mutate nodes) and before `executeAction`,
  a new check `targetAbsentBefore(before, ran, value)` runs. When it holds, the step answers through
  `webNodeReplayMissingTarget(run, "step", …)` without dispatching the click. That returns `core.replay.remembered` with
  `acted: false`, the same answer as before.
- Every condition errs towards pressing, which is today's path. The read must:
  - be whole (`truncated` false);
  - stand at the step's recorded `from.location`;
  - have no element whose selector equals the step's `selector`;
  - if the step carries an `element` identity, have words for that identity (`visibleText`, `accessibleName` or `label`) and
    no element whose `name`, `label`, `text`, `ownText` or `readable` equals them, ignoring case and spacing.
- I added the identity-words check because the extension finds a control by its identity when the selector has moved. A step
  with no selector, or an identity without words, is pressed as before.
- Docs: `docs/architecture/web-capabilities.md` covers the reset flag, the closing, `returnTo`, the record's memory-only
  lifetime and the remembered shortcut, in "The dry run's calls". The Click row now says that a click-opened tab is recorded
  as FluxIQ's own.
