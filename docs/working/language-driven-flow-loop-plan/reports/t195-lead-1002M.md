## The loop binding (supervisor's defect 1, for the general Flow authoring lead)

**At playback a press inside the repeat is NOT bound to one row.** This code path re-binds it to each row:
1. Core `R/flow-bootstrap/authoring/draft-routing.ts:264-268`: a `repeat` emits `builtin.control.for-each` with a
   branch `item` to every body step whose definition declares an input `item` (`takesRow`, ~line 330; `ROW_PORT`).
2. Downstream `domain/src/output-nodes/definitions.ts`: element-target nodes (click, type, select, ...) declare the
   optional `item` input (t195-w5).
3. Downstream `domain/src/output-nodes/native-runtime.ts:77` and `:158-166` (`scopedToRow`): with `context.inputs.item`
   an object, the press's `element.context.record` becomes `{ values }` from that row.
4. Extension `apps/extension/src/content/identity/record.ts` and `action-runtime/resolve-target.ts`: the record gate
   refuses a candidate in any other record, so the absolute selector to the template card misses and the control inside
   the row with those values is pressed. Caveat: the gate needs a record-shaped ancestor (`tr`, `li`, `article`, an
   ARIA record role, or a per-instance id); this site's cards produced one (`context.record.text` was captured).
   Not exercised live in 1002-M (no playback).

**What made the Flow, or the judge, bind to one row (each fixed or reported):**

  the Confirm stayed an unrepeated click on its template card (Tom's). Fix 5 (R8).

  `domain/src/runtime/llm-evidence/structure/first-item/locate.ts` -- as "the Confirm control". Fix 1's AT_NOTE (R9).

  build-test/summary.ts` `targetWords`) and nothing said a repeated step re-binds per row (run 1 round 0: "one remembered

- At build time (not playback): a `rerun` of the act step ran the template live on its card (run 1, Tom accepted).
