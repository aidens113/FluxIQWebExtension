## Existing chain and missing proof

The inspected path is instruction scope/localInstructionIds and task-part coverage → authored subflow/interface/mappings → Flow interface → compiled Flow artifact. The typed output schema can describe an answer's shape if one is authored. The missing demonstrated relationship is an authoritative explicit answer obligation, bound to the original instruction/task revision and to a specific actual delivered output or persisted recordset. Incidental successful DOM/scalar action output is not that witness; neither is the model's own confirmation.

The prior auction audit found empty Flow ports and absent delivered answer. Enforcing only already-authored required ports would not catch an author omitting those ports, and would not demonstrate that the requested structured answer was fulfilled. Conversely, rejecting every zero-recordset run would alter valid action-only and honestly empty-result behavior. A literal word/column-name scan would create a new heuristic contract rather than enforce an existing one. None is proposed.

In this project structure-plan route, valueType.kind must be exactly unknown; a typed record/array/schema shape available in the general Flow model is not accepted here. An authored required flag can only be true. Optional metadata accepts one binding object, validated here only as JSON that is a non-array object. The reader does not link the port to a source quote/part or validate an answer dataset/column obligation. Binding semantics in downstream consumers were not inspected, so this is not proof that the opaque object has no meaning elsewhere.
