## Semantic choices

### Evaluation order

1. A matching `Deny` in identity, guardrails, sessions or the boundary denies. The decision cites the first one in that order, then in statement order.
2. Otherwise the request is allowed only when all of these hold. The decision cites the first identity `Allow` that matched.
   - An identity `Allow` matches.
   - Every session policy has a matching `Allow`.
   - The boundary, if there is one, has a matching `Allow`.
3. Otherwise it is an implicit deny.

`Allow` statements in a guardrail never grant (the grammar refuses them anyway).

### Malformed requests

- An action that fails `isIamActionName` is an implicit deny. This covers wildcards and non-canonical case such as `studio:createProject`.
- A resource that fails `parseFluxIQResourceName` (for example `*` or `.../project/*`) is also an implicit deny. A request never names a pattern.

### Wildcards and matching

- `*` matches any run of characters, including an empty one, and crosses `:` and `/`. `?` matches exactly one character.
- Each pattern becomes an anchored `u`-flag RegExp, compiled once per set. Everything else in a pattern is escaped.
- Actions compare case-insensitively (`i` flag). Resources and trust principals compare case-sensitively.

### Policy variables

- `${fluxiq:PrincipalId}` binds to `principal.id`. `${fluxiq:WorkspaceId}` binds to the compile-time `workspaceId`, not to `context.workspaceId`.
- They are bound at compile time in resource patterns and string condition values (`StringEquals`, `StringNotEquals`, `StringLike`). Bound values are literal: metacharacters are escaped and are never wildcards.
- A pattern or value that needs an unbound or unknown variable matches nothing. As a consequence:
  - A `NotResource` with such a pattern excludes nothing. A fence like `Deny NotResource frn:fluxiq:*:${fluxiq:WorkspaceId}:*` therefore denies everything for a principal with no workspace, which fails closed.
  - A `StringNotEquals` value with such a variable never counts as equal.

### Conditions

- Operators are ANDed, keys under an operator are ANDed, and a key's values are ORed. `StringNotEquals` and `NotIpAddress` pass when no value matches.
- When a key is missing, this follows AWS:
  - An `...IfExists` operator passes.
  - Otherwise a negated operator (`StringNotEquals`, `NotIpAddress`) passes.
  - Every other operator fails.
  - The reasoning is in a comment in `compile-iam-condition.ts`.
  - The effect: `Deny` + `NotIpAddress` denies a request with no source IP, and `Allow` + `StringNotEquals` allows one where the key is missing.
- String comparisons are case-sensitive.
- `Bool` accepts `true` or `"true"` and compares strictly with a boolean fact.
- `DateLessThan` and `DateGreaterThan` compare `currentTimeMs` strictly with `Date.parse(value)`.

### Condition keys

- A null `ownerId` or a null `context.workspaceId` counts as missing.
- `ResourceTag/<k>` reads only the resource's own keys (`Object.hasOwn`), so a key like `constructor` is never inherited.
- `ConnectedBrowserId` reads `context.connectedClientId`.

### IP addresses

- IPv4, IPv6 (including `::` and an embedded dotted quad) and CIDR are supported. Host bits after the prefix are ignored.
- A request address `::ffff:a.b.c.d` is compared as IPv4, because Node reports IPv4 peers this way on dual-stack sockets.
- Addresses of different families never match. An unparseable source IP sits inside no block, so `NotIpAddress` passes for it.

### Grammar violations at compile time

- `compileIamPolicySet` throws a `TypeError` for an unknown operator, a key/operator type mismatch, a statement with neither `Action` nor `NotAction`, or one with both halves of a pair.
- A parsed document can never hold these, so this fails loudly instead of quietly turning into an allow or a deny.

### fullAccess

`fullAccess` is true only when all of these hold:

- `workspaceId` is non-null.
- No policy in the set holds a `Deny`. Any guardrail statement therefore disables it.
- Some identity statement is an unconditional `Allow` with `Action` listing `*` and `Resource` listing `*` or `frn:fluxiq:*:${fluxiq:WorkspaceId}:*`. `NotAction` and `NotResource` never qualify.
- Every session policy and the boundary hold such a statement too.

The fast path in `decide` applies only to a resource in this workspace (same workspace segment, or the workspace's own FRN) that every one of those grants matches. With no `Deny` anywhere, the full evaluation would allow that resource as well, so the fast path never changes a decision.

The only difference is which statement is cited: the full-access grant rather than an earlier, narrower identity statement. Vector "the full-access fast path cites the full-access grant" pins this.

`IamDecision.fullAccess` is true only for an allowed request where every resource took the fast path.

### The workspace FRN

I chose not to have `frn:fluxiq:*:${fluxiq:WorkspaceId}:*` cover the workspace FRN `frn:fluxiq:platform::workspace/<id>`. Its workspace segment is empty, so the pattern does not match it literally. Covering it only on the fast path would make the result depend on which path ran.

A full-access policy that should allow top-level creates and lists must list `frn:fluxiq:platform::workspace/${fluxiq:WorkspaceId}` or use `*`. A test covers both cases.

### Trust policies

- `iamTrustAllows` binds `${fluxiq:PrincipalId}` to `caller.id` and `${fluxiq:WorkspaceId}` to `context.workspaceId`.
- It needs `Principal.FluxIQ` to match `caller.frn` (case-sensitive), the action to match `iam:AssumeRole`, and the conditions to pass. Resource keys are missing in a trust check.
- `Deny` wins and returns null; otherwise the first matching `Allow` is returned.
- It throws a `TypeError` for a policy whose `kind` is not `trust`.
