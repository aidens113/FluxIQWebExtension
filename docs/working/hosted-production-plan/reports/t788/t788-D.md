## Schema (SQLite, WAL, synchronous=NORMAL, busy_timeout 5 s)
- `dict(id INTEGER PRIMARY KEY, value TEXT UNIQUE)`: every principal, action, newline-joined resource list, matched statement (`""` = implicit, `policy` or `policy\u001fsid`), origin, IP prefix, and any non-decimal request id. Loaded whole into memory at open; new strings are inserted once inside the batch transaction and cached only after COMMIT (rolled back with it). Never garbage-collected (thousands of values, not millions).
- `allow_YYYYMMDD(t, req, p, a, r, m, o, ip)`: one table per UTC day, all INTEGER, created lazily. No secondary index.
- `long(cat, dec, t, req, p, a, r, m, o, ip)` + index `long_t(t)`: `cat` 0 = deny, 1 = iam-change; `dec` 1 = allow, 0 = deny (an iam-change can be either).
- Request id encoding: canonical decimal id (`0` or no leading zero, <= 15 digits) stored as that integer; any other id interned in `dict` and stored as the negative dict id. Lossless. Callers that want the compact path should issue decimal ids (e.g. a per-process counter). A non-decimal id (uuid-like) adds one dict row per request, which is much larger than 30 bytes/row; not measured.
- An `allow`-category record is stored with decision `allow` regardless of its `decision` field (denials are recorded as `deny`/`iam-change`).

## Measured
- 10,000 polling-like allow rows (20 principals, 2 actions, 50 resource lists, decimal request ids, one day): **29.9 bytes/row** (299,008 bytes total after close, WAL checkpointed to 0). Asserted < 80.
- Principal read over those 10,000 rows with no index: 13.3 ms (500 hits). Decision: no secondary index on allow tables; a read scans only the day tables overlapping its time range. Revisit if a principal read over 90 days of a very busy day table is needed interactively.

## API (barrel `audit/index.ts`)
- `IamAuditStore.open(file)`; `write(records)` (one transaction, all-or-nothing); `read(IamAuditQuery)` -> `IamAuditRecord[]` newest first (`principal`, `since` inclusive, `until` exclusive, `categories`, `limit` default 100); `expire(nowSeconds, { allowDays, longDays })` -> `{ droppedTables, deletedRows }`; `allowTables()`; `close()`. All operations serialized on the one connection.
- `BufferedIamAuditSink(store, { flushIntervalMs = 1000, maxRows = 100, retainedRows = 10000, onError })` implements `IamAuditSink` plus `close()`, `bufferedRows`, `droppedRows`. `record()` never awaits or throws. Allows flush at 100 rows or 1 s (unref'd timer); `deny`/`iam-change` flush immediately (with any buffered allows). `flush()` drains and rejects if rows still cannot be written; `close()` = flush (does not close the store). A failed flush requeues its rows, calls `onError`, and is thrown by the next `flush()`/`close()` that still cannot write; overflow beyond `retainedRows` drops oldest and counts in `droppedRows`. A crash can lose up to 1 s (and up to 100) of buffered allows.
- `MemoryIamAuditSink`: `records`, `record()`, `flush()`.
- Also exported: `IamAuditDatabase`, `IamAuditDictionary`, `IamAuditQuery`, `IamAuditRetention`, `IamAuditExpiry`, `iamIpPrefix`.
