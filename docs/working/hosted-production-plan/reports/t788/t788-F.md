## API (barrel index.ts)
- `IamAuthorizer(source: IamPolicySource, sink: IamAuditSink)`
  - `authorize(principal, action, resources, context, options?) -> Promise<IamDecision>`
  - `forRequest(principal, context, options?) -> Promise<IamRequestAuthorizer>`
  - `assumeRole(caller, roleName, context, sessionPolicy?) -> Promise<IamRoleSession>`
- `IamRequestAuthorizer`: `decide(action, resources)` (sync, one audit row) and `filter(action, items, toResource, listScope)`.
- Types: `IamPolicySource` (resolvePolicySet, getRole; IamStore fits), `IamAuthorizeOptions {assumedRole?, sessionPolicies?}`, `IamRoleSession` (`{allowed:true, principal, options}` | `{allowed:false, decision}`).
- Internal files (not in barrel): `deny-decision.ts`, `record-decision.ts`. No file-name prefix shared by 3+ files.

## Fail-closed and audit choices
- Failure to resolve or compile a policy set (store throws, compile throws) yields a request authorizer with no compiled set: every decision is an implicit deny with its own audit row. An evaluator throw is also a deny. `authorize` never throws for those. Only a throwing audit sink propagates (an error, never an allow); documented on the class.
- Exactly one row per `decide`: category = decision, time = floor(currentTimeMs/1000), requestId = context.requestId or one generated per request (shared by all decisions of a `forRequest`), principal FRN, action, all resource FRNs, matched, origin, `iamIpPrefix(sourceIp)`.
- `filter`: scope = decision on `listScope`. If allowed with `fullAccess` and every item `coveredByFullAccess`, one row (list action, listScope) and all items returned. An empty list records the single scope row. Otherwise one row per item, only allowed items returned.
- `assumeRole`: unknown role, missing workspace, or trust refusal records one deny row (action `iam:AssumeRole`, resource role FRN). If trust allows, the identity check goes through `authorize` and records its own row (allow or deny). Trust policy is named `<role>/trust`. Success returns principal `{type:"role", id: roleName, workspaceId, frn: role FRN}` and options `{assumedRole: roleName, sessionPolicies: [sessionPolicy] or []}`. The role-session FRN is undefined in contracts (t784 open question); the role FRN is used.
