### list-after-read

- rows it has none of are the next page
- the same rows in another order are a sort
- fewer of the same rows are a filter
- a read taking up where the list ended is the next page of a feed
- a known row in a mostly new page is a repeat; most rows known, out of order, with one new, is a sort of a longer list
- the same page with a value changed carries on, in place, and other pages stand
- a page the call or address names and the list has not held is the next page, whatever it repeats
- a page it has held, read again with its rows moved, starts over
- a first read that named no page is page 1, unless the rows share nothing, as on a site counting from nought
- the model's `replace` starts over, unless the address says it is another page
- another view starts over, and the model's `append` keeps both
- a read holding every row of a short list and more, out of its order, is the list read whole again, whatever `append` says
- a row changed everywhere but its name is that row
- a bare number or a date ties nothing
- a word two rows of a read share tells neither from the other
- a state each short page happens to have once is no tie against the name
- a shared address ties rows whose words changed
- two rows of one read are never one row
- does not change with how a saved step's replay went, or with the page
- changes with the view read and the name the model gave, and a name holds across how it was asked
- three rows, the same list grown and read newest first by a saved step, then sorted by hand: the sorted read, whole
- a re-read goes to the store as a replace of the list's rows, so its order is the account's
