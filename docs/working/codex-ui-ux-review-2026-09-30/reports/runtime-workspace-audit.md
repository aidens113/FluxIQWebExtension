# Runtime workspace audit

Status: Read-only design complete; report frozen for supervisor implementation scoping. Own report only; no product/test/heavy/live mutations.

Required brief/Current State read. Runtime metadata promises clients/capabilities/runs/dispatch/transports but marks preview; ProgramLiveViews.tsx has no runtime renderer. Existing runtime API provides snapshot, list-clients, list-capabilities, list-runs and get-run under programs.read. Public package export fluxiq/runtime exposes contracts via runtime/index.ts. Snapshot contains clients/adapters/transports/capabilities/runs/commandAttempts; getRun returns the run record, not command history. No backend paging/filter contract exists on these endpoints.

Immediate design direction: read-only inspection workspace with bounded rendered/searchable lists and structured allowlisted fields, selection reconciliation, lazy get-run detail, dispatch-path inspection from snapshot attempts, generic error/retry/race/freshness states. Must not render arbitrary run metadata/result/error/message or attempt command payloads that can contain secrets/recording data. Full exact payload/field and minimal-file proposal follows remaining contract inspection.

## Proposed functional workspace

One Runtime workspace with summary counts for clients, capabilities, recent runs and dispatch attempts, a visible last-successful-refresh time, Refresh control, and five compact sections/tabs: Clients, Capabilities, Runs, Dispatch, Transports and adapters. Use existing Panel/SummaryStrip/StatusBadge/KeyValue/LoadingState/EmptyState/VisualAlert/button styles, keyboard-native tabs/buttons/inputs and labelled tables. No new stylesheet required for the first functional increment.

1. Initial snapshot has explicit loading. Initial failed/denied/malformed response renders a fixed safe unavailable message and Retry, never zero counts or an empty-success workspace. A failed refresh retains the previous snapshot with a visible stale notice and last successful time. Do not display raw endpoint errors. Manual refresh only in this first brief; show "Snapshot loaded at ...; use Refresh for current state", not Live/real-time. No unconditional poll or fake health clock. Auto freshness can be a separately owned extension later.
2. Each section has local search and appropriate enum filter (client status, capability kind, run status, dispatch status, transport kind), with page size50. Filter before paging; reset offset on filter/search and reconcile offset if refreshed data shrinks. Sort runs queuedAt descending and attempts dispatchedAt descending, with stable id tie-break. Search only projected structural fields/registered labels, not arbitrary metadata or result contents. Show returned count/page range and matching count. These are **client-side pages of the returned snapshot**, not server-side bounds.
3. Selection belongs to the visible filtered/page list. Reconcile with existing program-selection.ts helper; if a selected entity is hidden or removed, select the first visible row or show a named empty detail state. Changing section resets its selection/detail request appropriately. Do not retain hidden run detail. Client identity combines clientId/sessionId; transport/adapter ownership remains distinct. Capabilities can be duplicated in the global flat list; show entries/origins rather than claim unique capabilities or infer an executable action from names.
4. Selecting a run starts a lazy get-run read. It shows summary while loading explicitly labelled as snapshot summary, then fresh structural run detail. Independent detail failure/denial shows retry; keep the selected summary labelled stale/unconfirmed. Validate returned runId equals the requested selection. Generation+AbortController changes on selection, filter/page removal, snapshot scope change and unmount. Old failures/successes cannot replace a later selected run or clear its spinner. Refresh must not silently authorize a new domain; Runtime endpoints currently return the service's global snapshot even though generic transport carries domainId. Label global runtime inventory; UI filtering is not an authorization boundary.
5. Run detail lists status/times/project/domain/target kind+id/observed selected client/session/transport, command count and related projected attempts. Dispatch detail shows attempt/command/run ids, command kind and capability/input/output/action identifiers, actual adapter or client/session/transport, status and times. Transport/adapter detail shows registered identity, type and client/capability counts. A missing route means "No selected route recorded", not disconnected/unavailable. No execution/mutation buttons or fabricated runtime controls.

## Projection and privacy boundary

Project every record field by field before storing UI view models. Keep known enums, finite timestamps, bounded printable identity/label strings and bounded nested identity lists; use totals/counts for large command/capability lists and page those separately if shown. Display registered labels as escaped text, not HTML. These labels/ids are supplied by the existing runtime contract; a whitelist does not prove all arbitrary strings are secret-safe. Do not persist/export/log the snapshot or add a raw JSON inspector.

Omit capability/client/run metadata, command parameters/target/metadata, attempt message, result payload/message/error/target/metadata/failure prose, run traceRef and arbitrary extra keys. Withheld runtime fields are not a blanket redaction guarantee: contracts.ts:172 says withholding is caller-supplied and service.ts:185 says it shapes the retained attempt only. The UI must not rely on every producer supplying withheld values. Fixed local load errors avoid accidental server/page content presentation.

Existing snapshot is unpaged and receives all persisted attempts/runs, including omitted fields. UI projection protects display/storage/render cost but does not reduce network payload or parse cost. Neither list-runs nor get-run adds attempt pagination. This backend scalability/privacy-at-wire limitation must be documented, not hidden behind the50-row UI page. A future server projection/paged API would be a separate cross-layer brief; no backend edits are proposed here.

## Exact minimal implementation ownership proposal

- Existing `apps/web/src/features/programs/ProgramLiveViews.tsx`: lazy import/runtime case only, covered through composed routing regression in the owning programs tests if supervisor approves an additional exact routing test path; no unrelated switch changes.

## Meaningful regression requirements

- Mount actual workspace with mocked program API: exactly one snapshot GET, no get-run until a run is selected, no execute/dispatch/pause/delete calls; get-run POST carries only requested runId and remains classified as read by existing seam.
- Initial deferred/failed/403/malformed snapshot cannot imply empty healthy inventory; retry succeeds. Refresh failure retains projected rows with stale marker and last-success timestamp. Two overlapping refreshes finish out of order: latest response wins; unmount abort/late response cannot publish.
- More than50 synthetic rows: only current page rows mounted; search/status filter resets/reconciles offset, selection and detail; refreshed removal and no-match state are correct. Different sessions sharing a client id remain selectable distinct records; duplicate capability identifiers do not collide.
- Deferred runA detail then selectB/filterAaway/unmount: A success/error does not replace B/detail loading. Mismatched run id is explicit failure; retry B succeeds. Selecting dispatch shows recorded route, no guessed target. No selected run means no detail requests.
- Inject synthetic credential-like strings and page/text/URLs into every omitted metadata/parameter/result/error/trace field; assert absent from projected model and rendered output. Do not use real private state. Keep allowed registered identity/label behavior separately tested, including malformed control characters and overlong values.
- Source composition or behavior test makes programId runtime instantiate RuntimeLive rather than default placeholder. Focused tests then supervisor web typecheck/full suite/structure/build; visible keyboard/focus/responsive certification requires later authorized browser work.
