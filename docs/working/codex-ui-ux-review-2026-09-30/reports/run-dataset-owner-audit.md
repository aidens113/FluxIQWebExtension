## Confirmed identity and caller protections

RunDatasetTable:29 maps each schema field into each row. It supplies no rowKeys to DataTable; the latter keys tr by caller rowKeys or rowIndex, and td by column index. datasetCell:58/59 creates JsonToggle key=field.id for declared JSON or any object. JsonToggle owns useState(false); no value/owner replacement reset exists. Its JsonPreview receives CURRENT props.value, so reuse retains the OPEN preference, not cached previous JSON content. A mounted row slot whose field id remains equal and whose JSON value changes therefore keeps its expanded preview and renders the replacement value. This is a source-confirmed component reuse property; no actual user-data disclosure was observed.

RunDatasetsPanel owns selectedId, page and cursor. A normal selection explicitly sets page=null and initiates first-page load; rendered rows/schema are []/null whenever page is null or page.datasetId does not match selection. If this intermediate empty render commits, old row children unmount, including every JsonToggle, so the new dataset starts collapsed despite an unkeyed RunDatasetTable. The table itself has no key identifying selected dataset. Async loadPage appends only when cursor is truthy and current.datasetId matches; existing rows remain at their indices, so retaining expanded previews during append-only Load more is appropriate. Selecting the same dataset intentionally clears page before first-page replacement as well. Dataset summary/label refresh alone keeps the current loaded page, not replacement row data.

Project/run owner protection is stronger in the actual runtime caller: RunActionLogViewContent:40-45 creates a new owner generation for projectId, runId OR commands identity and renders RuntimeLogScope key=owner.generation. RunDatasetsPanel is inside that scope, so a real owner replacement remounts the panel/table/toggles synchronously at React reconciliation. Within a standalone reused panel, project/run changes additionally reset page/selection in a passive effect, but that standalone shape is not the identified runtime navigation lifetime. Do not claim the actual caller lacks owner fences or propose changing frozen RunActionLogView.

The panel requestRef rejects older page completions after a subsequent load or committed project/run reset. Export/delete ownership and standalone retained command callbacks are separate operation concerns, outside this JsonToggle investigation; they were not audited or fixed here.

## Conditional risk and priority

D3 remains a conditional risk for the identified product flow, rather than a demonstrated current cross-run leak. Cross-run/project/commands navigation is protected by the keyed runtime owner scope. Cross-dataset selection usually commits an empty table while awaiting page results, which destroys old cell state. However the panel does not express a dataset key, so its state-reset correctness depends on that intermediate commit. If React scheduling combines the page-clear and immediately available page-result updates into one commit, or a future owner introduces direct row replacement without that committed empty state, equal-index/equal-field children are reused and the new value remains expanded. This timing scenario was not executed; the brief is read-only and no browser or synthetic reproduction was run. Existing tests cannot establish that all production scheduling modes commit the empty state.

No stable row ID is exposed in the inspected RunDatasetTable public contract. Rows are arbitrary records, and deriving identity from JSON serialization/content or fabricating primary keys would change semantics, add serialization work and collapse previews on legitimate appends. No evidence justifies global shared DataTable/JsonToggle remount/reset behavior. Reordering/replacing rows within an explicitly same dataset generation would need a separate row-identity policy; current panel path is first-page replacement through clear or append-only pagination.
