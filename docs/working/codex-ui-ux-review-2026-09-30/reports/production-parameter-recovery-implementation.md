## Pure model decisions

prepareProductionParameters(schema: unknown, values: Record<string, string> = {}) returns controlled field descriptors, normalized metadata, fixed issues and valid flag. Field descriptors include name, label, primitive type, required, optional typed default/enum/bounds and control display state. Schema issues and field issues are distinguishable so malformed declarations do not pretend to be user input errors. The helper never mutates schema/draft and never performs requests. Error strings exclude supplied private values, raw exceptions and unknown keyword values; field labels remain ordinary UI text.

Only undefined schema means no declaration and produces valid empty metadata. A declared schema must be a non-array object with own object properties and optional type equal to object. Missing top-level type uses legacy object inference; missing field type uses legacy string inference. Null/malformed property declarations, nonprimitive types, type arrays/unions/composition, unknown assertion keywords and more than 30 own properties produce explicit actionable schema limitations and block Start. No silent truncation or partial launch. Invalid declarations may retain valid visible controls where safe, with the limitation visible beside them; metadata is never submitted while any issue exists.

Allowed top-level keys: type, properties, required, title, description, examples, $comment, readOnly, writeOnly, deprecated. Allowed field keys: type, title, description, examples, $comment, readOnly, writeOnly, deprecated, default, enum, minimum, maximum. This fixed subset intentionally excludes $schema/$ref, additionalProperties, pattern/format, string lengths, exclusive bounds, multipleOf, nested properties/items and composition; these need an explicit unsupported declaration message, never assumed enforcement. Harmless annotations are not interpreted as constraints; only string title supplies a label. Property minimum/maximum on nonnumeric fields are unsupported, rather than silently ignored. Top-level required must be an array of existing own property names (duplicate required names are normalized); malformed/dangling names block launch.

Supported defaults must be own primitive values of the declared type; all numeric values are finite and integers are safe integers. Number enums contain only finite numbers, integer enums only safe integers, string/boolean enums only matching primitive types. Enum arrays must be nonempty; duplicate enum values are normalized without changing the allowed value set. Defaults satisfy enum and inclusive bounds. Bounds must be finite numeric values and minimum cannot exceed maximum. For integers, a bound interval containing no safe integer is contradictory; no truncation/clamping or alternative default. Valid zero/false/empty-string defaults are retained as values, never truthiness fallbacks. Required string defaults must also satisfy the local nonblank policy; a blank numeric/required enum cannot be manufactured from absence.

Own-property draft presence distinguishes untouched defaults from explicit edits. Numeric absence uses a valid default if present, otherwise omission when optional or a correction issue when required. Explicit numeric blank/whitespace omits optional even when a default exists; required blank needs correction. Nonempty numeric text is trimmed before Number conversion, then finite/range/enum and safe-integer checks apply. Optional plain strings retain empty-string output; required strings require nonblank text but preserve their original value once valid. Plain booleans retain false/default semantics; only exact true/false draft strings are accepted. Removed schema fields are absent from metadata regardless of lingering draft keys. Object.fromEntries or defineProperty builds metadata safely for own names such as __proto__/constructor; inherited draft values never supply an edit/default.

## Enum controls and schema-refresh identity

Select options use control-only values such as option:0, option:1 and unset. Those strings never enter the draft or metadata. On selection, the component resolves the current descriptor option and stores its raw scalar text: string unchanged, boolean true/false, finite number String(value). The helper normalizes according to the current declared primitive type. Distinct absence is represented by deleting the own draft key, not a sentinel; selected empty-string enum is an own draft key with value empty string. Untouched optional enum with no default stays unset and omitted; no implicit first choice. Choosing unset on a defaulted enum removes the override and restores the declared valid default. Required unset without a default needs correction.

Raw scalar draft storage also avoids a schema-refresh bug: storing option indices in drafts would silently retarget the value after enum reordering. The component computes its current encoded index from the typed normalized candidate; reordering preserves the actual selection, removal exposes a field issue and unset control while retaining the explicit draft. Existing same-target drafts are preserved and revalidated against each current snapshot. Field keys use field name, labels have useId-derived control/error ids, accessible required/invalid/describedby flags and fixed alert messages. No component effects reset drafts or focus during polling. Select controls remain controlled, including an unmatched invalid retained draft represented by unset plus its local error.
