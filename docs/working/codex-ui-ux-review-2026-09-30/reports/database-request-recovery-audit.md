## Concrete read/recovery contract

1. Owner is API/context (include current user identity where provided), query is database/kind/search/sort/direction/requested offset and effective grant identity. Current render owner/query and actual Date.now grant validity gate displayed page/detail and callbacks before passive cleanup. Selected detail is current-context/id owned; choose explicitly whether query changes clear selection (recommended) rather than silently retaining detail from another search/page.
2. Metadata/list/detail each owns signal, generation, confirmed payload, pending identity, fixed error and retry callback. Abort on owner/query replacement/unmount; recheck after any pre-request yield, before request and before publishing/finally. Obsolete callbacks cannot submit, abort current work, clear selection/error or release current loading. Preserve same-query confirmed rows after transient failure with stale feedback; never retain sensitive data when grant is expired/revoked or owner changed.
3. Grant expiry/revocation invalidates and aborts list/detail, clears retained private records/selection and rejects late responses. Detail render explicitly requires current frontend authorization in addition to current owner. Grant deadlines use actual Date.now and remain independent of ordinary hidden-tab polling; do not adopt visibility-paused display clock for credential expiry. Backend remains authoritative; frontend check prevents stale presentation rather than granting access.
4. Validate minimal metadata arrays, record envelope identity/data object and finite integer nonnegative paging (positive bounded limit, matching requested query scope). Valid empty page/null detail are distinct from malformed/error. Do not normalize malformed response into successful empty data. Keep arbitrary stored record values in existing authorized renderer only; no new raw logging/cache/export.
5. Pager holds confirmed page index/rows until a new page succeeds; pending requested offset is separate, and failure Retry reuses it. Total shrink clamps once to final valid page. Query/debounce updates mask obsolete rows immediately or label their original query explicitly; no old rows shown as confirmed under changed controls. Coalesce/supersede same-query read with explicit owner guard without retrying authorization writes.
6. Local metadata/list/detail errors provide visible fixed feedback and correct Retry action; clear current busy in guarded finally on refusal/malformed/rejection. Loading, valid empty, missing selected record and unavailable states stay distinct. Existing StatusText notification can remain supplemental, not the only durable error feedback.

## Meaningful regressions

- Unexpected rejection for each read channel releases loading, shows fixed local error, exposes appropriate Retry and recovers. Malformed metadata/list/page/record is refused safely; valid empty/list-null detail has distinct UI. No raw synthetic server/private exception text in new error rendering.
- Same-owner manual retries resolve out of order; newest requested confirmed data wins. API/context change masks old metadata/rows/detail before passive cleanup; old response/callback/finally cannot publish or release new busy. Captured inspect/retry/pager/search/sort/store/dismiss callbacks are invoked explicitly after replacement and produce no obsolete request/state change.
- Start delayed record list/detail under synthetic future grant, advance clock past expiry/revoke/navigate scope, then resolve old success. Locked table and inspector both remain empty; captured old detail click causes no new read. Accepted grant never migrates to another API/user/database/kind. Keep all existing14 authorization tests.
- Delayed detail A then selected B: A cannot overwrite B, close/clear B or show A error. Store change, search/sort/direction/page replacement and unmount invalidate appropriately. Detail malformed id/kind/domain cannot display under the requested selection.
- Next-page failure retains confirmed rows/page and Retry requests same pending offset; success commits once. Sort/search resets offset on effective query only; debounce old result is fenced. Large total shrink clamps directly; no fabricated Page Infinity/NaN or false empty success.
- Metadata refresh removes current kind/database: active selection reconciles, old record requests/inspector invalidated. Still-present store/selection remains stable and no focus is stolen by ordinary refresh.
