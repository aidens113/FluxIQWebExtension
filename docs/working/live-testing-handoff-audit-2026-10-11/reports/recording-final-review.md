### Dead-owner admission and exact proof
- Schema adds a private positive owner_pid; owner inserts process.pid with each random claim. reclaim first requires a positive safe integer PID. process.kill(pid,0) success refuses takeover; ONLY thrown codeESRCH permits proceeding. EPERM, unknown errors, malformed PID and other failures refuse. No timeout/age/elapsed-clock rule invents death.
- The SQL takeover updates only claim_id and owner_pid, with exact old claim_id/PID compare-and-swap. It requires matching generation, ended_at_ms, complete_count, canonical complete_digest, first/last storage range and chunk_sha256. The current recording/header/head must still match end/count/generation, indexed cursor first-1 and actual descriptor maximum. A replaced claim, different body or stale generation/range/cursor/end cannot be blindly deleted/reclaimed.
- Competing reclaimers that observe the same dead PID cannot both win: the first changes the random claim identity, so the second's exact old ID/PID update affects0rows and refuses. Reconciliation regenerates the chunk from the proven current desired complete timeline; both complete digest and exact chunk SHA remain unchanged during takeover.
- After takeover, descriptor insertion still goes through schema recording_stream_chunk_open: exact SHA/range, header end/count, head generation and cursor/descriptor maximum must still match. Overlapping storage ranges refuse. The single-use consume trigger deletes the matching claim on descriptor insert; a post-CAS descriptor/head change does not bypass this fence.
- finally cleans up only the caller's current random claim_id, so a refused competitor or an older owner cannot delete the adopted/new claim. Success consumes it; normal rejection cleans it; death after takeover simply leaves a new owner_pid that the same ESRCH/exact-proof procedure can recover later. Ordinary append/removal completion refusal is unchanged; takeover does not reopen the recording.

### Liveness namespace and PID reuse limit
This proof requires every writer of that SQLite project to share one host/OS PID namespace with the process performing kill(pid,0). A shared project copied/mounted across hosts or isolated PID namespaces cannot interpret local ESRCH as proof that its foreign writer died. The private row has no host/boot/namespace identity, so no multi-host/namespace takeover guarantee is supported. Document the same-host assumption rather than claim broad distributed recovery.

PID reuse by a currently live local process returns success and conservatively blocks recovery, even if that process is unrelated to the old owner. Unknown/permission-denied liveness also blocks. No process-start identity is used; this is a deliberate fail-closed availability limitation, not a proof of exactly-once ownership across PID namespaces. A genuinely dead original local process cannot resume merely because its PID is later assigned elsewhere. This review does not add or recommend an age-based override.
