## What changed and why

The seam is `step-views/views.ts` `captured`, as the analysis suggested. That is where the newer capture replaced the
view. `target-packets.ts` only hands in a place function, and `stable-handles.ts` is unchanged: a new handle per state
is how the numbering is meant to work, and the view is what has to remember the earlier handle.

- `step-views/control-places.ts` (new): `webLlmDialogControlPlaces(target)` gives two places for a control.
  - `exact`: the frame, the shadow hosts and the selector (the store's `addressOf`), plus tag, role and context
    (dialog, list position, landmark, form, and the record's key and values).
  - `loose`: the same with `:nth-of-type`/`:nth-child` taken out of the selector and the host chain.
  - The record's `text` is left out. It excludes the words inside buttons but keeps a count beside them ("12 likes"
    becomes "13 likes"), so it changes with the toggle. The address already says which row it is.
- `step-views/kept-by-place.ts` (new): `webLlmKeptByPlace(earlier, newer, placesOf)` chooses which dropped handles to
  keep. It looks only at handles the newer capture does not show, and works in two tiers.
  - Tier 1: a handle new to the view stands at the dropped handle's exact place. Every earlier handle at that place is
    kept, each one a state of the same control.
  - Tier 2: positions moved (a layer beside the dialog shifts every `nth-of-type`). The handle is kept only where its
    loose place holds exactly one dropped control and exactly one new handle that tier 1 did not match. This follows
    `stable-handles.ts` tier 3, which also matches only where nothing is left to choose.
  - A handle the view already held never counts as another state. So rows that shift up into a removed row's address
    keep nothing.
- `step-views/views.ts`:
  - `createWebLlmStepViews` takes a third argument, `placesOf`.
  - A full capture carries over the handles `webLlmKeptByPlace` returns. A partial capture still carries over
    everything, as before.
  - Each handle now records the newest capture that showed it, so `shownIn` for a kept t593 is view 7, not the view
    that dropped it.
  - Behaviour change to check: a handle carried over by a capture cut short now reports its own earlier view. Before,
    it reported the cut-short view, which never showed it.
- `step-views/index.ts`: exports both new functions.
- `target-packets.ts`: passes `webLlmDialogControlPlaces` in, and adds three lines to the t748 U1 header (800 lines; it
  was already past the 400-line advisory).
