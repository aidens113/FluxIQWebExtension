# t730-sl2: retire five synthetic-page Playwright specs

## Outcome

Done. All five specs are deleted. Every check they made on the server side or in pure logic is now covered by a browser-free unit test, either one that already existed or one added here. The DOM-only behaviour is recorded below as fixture-only and is no longer allowed in browsers. Nothing imported the specs or their local helpers. The grep found only `.structure-baseline.json`, docs, and two comments in test files I own, which are now updated.

## What changed and why

Deleted:
- `apps/scenario-lab/e2e/scenario-pages.spec.ts`
- `apps/scenario-lab/e2e/negative-variants.spec.ts`
- `apps/scenario-lab/e2e/intermediate-state.spec.ts`
- `apps/scenario-lab/e2e/keyboard-forms.spec.ts`
- `apps/scenario-lab/e2e/multi-tab.spec.ts`

New unit tests:
- `src/scenarios/dynamic-list/tests/scenario.test.ts` (new): row identity through add and reverse, plus the rendered entity ids and the row count.
- `src/scenarios/long-document/tests/scenario.test.ts` (new): for every seed, the target sits in sections 16-20, below at least 2,520px of content. Also covers the reach mutation and the initial "Pending" result.
- `src/scenarios/reconnect/tests/scenario.test.ts` (new): the event order is disconnect, queued, reconnect, replayed, and the page ends connected. Also checks that the button names match the recording's role targets.

Extended tests:
- `sensitive-input/tests/scenario.test.ts`: a submit whose payload carries the password, card and billing values keeps none of them. Only `synthetic: true` counts, and the page's handler sends nothing from the form. Before this, server.test checked only the password, not the payment value.
- `llm-target-drift/tests/scenario.test.ts`:
  - Each mode renders exactly the target its oracle names, along with the mode text, the result text and the seed marker. The renamed target is "Replacement control". Restore resets the activation count and sets `lastOperation` to `restored`.
  - An HTTP test arms `missing` and loads the page twice. The final state is unchanged, which is the spec's reload check.
- `navigation/tests/scenario.test.ts`: an HTTP test arms `broken-link` through `/api`.
  - The start page still links to `/second`.
  - GET `/second` follows the redirect to a 404 at `/link-retired`.
  - The final state has `mode` `broken-link` and `visits` `["link-retired"]`.
- `ambiguous-targets/tests/scenario.test.ts`:
  - The armed renderings bind both Continue buttons by position (index 1 chooses secondary).
  - In the baseline, each Continue sits inside its own `section aria-label`.
- Comment-only edits: `iframe-checkout/tests/scenario.test.ts:70` and `failure-surfaces/tests/scenario.test.ts:124` cited the deleted specs.

## Generic capabilities a realistic spec would need to prove instead

These checks are not about the synthetic fixtures. They prove browser or runtime behaviour, and no unit test can stand in for them. Each suggested home is a realistic scenario whose source already contains the relevant construct, found by grep in its non-test `.ts` files. I have not confirmed that any of them is reachable in a workflow.

1. **Variant arming as the Lab does it, then a browser run against the armed page.** This is `armVariant` in `lab-fixture.ts`. The remaining realistic specs (`local-classifieds`, `social-network-feed`) already use it, so it is still exercised.
2. **The network guard sees a blocked destination as a loopback interstitial, never as an outbound request.** This was `guard.unexpectedDestinations == []` on blocked-url. Suggested home: any realistic site with an off-site link, such as everything-store or company-website, whose spec clicks an external link and asserts the guard stayed clean.
3. **Multi-tab: new-tab links (`target=_blank`), `window.open`, switchTab and closeTab, and a blocked popup.** `window.open` appears in everything-store and local-classifieds. `target="_blank"` appears in nine realistic sites. Suggested home: an everything-store or local-classifieds spec that opens a listing in a new tab, extracts from it, closes it and confirms on the list.
4. **Native keyboard behaviour (D5).** This covers Enter implicitly submitting a form, an untrusted Enter not submitting, `requestSubmit` reporting no submitter, an ARIA combobox driven by keys, and radio arrow keys that respond only to trusted input. Comboboxes appear in local-classifieds and professional-network. Submit forms appear in job-board, professional-network and others. Suggested home: a professional-network or local-classifieds spec with a combobox filter and a form submitted by Enter.
5. **Cross-origin and same-origin iframe actions.** `<iframe` appears in nine realistic sites. Suggested home: a checkout or embedded widget on everything-store or bigbox-retail, if one exists in the workflow.
6. **History pushState navigation.** Suggested home: local-classifieds, photo-social or professional-network, which use `pushState`.
7. **Waits that really time out against slow content, and a processing interstitial with focus management.** `setTimeout`-driven delays appear in all ten realistic sites. Suggested home: whichever realistic site has a delayed or processing step, for example a checkout on everything-store.
8. **Scrolling to a target below the fold.** Any long realistic page, such as social-network-feed or job-board results.
9. **Playwright actionability: visible, enabled, hit-testable, and a disabled control that refuses a click.** `disabled` controls appear in eight realistic sites.
