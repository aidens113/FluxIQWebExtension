### Brief: t359 a lasting act is never repeated by an automatic retry when its effect is uncertain
- Worker: t359-lasting-act (worker-high). Worktree `C:\Users\osrs_\FluxStuff\fxwork\t359\` (Core-paired, branch `task/t359-lasting-act-retry-check`). Report: `docs/working/mvp-final-month-plan/reports/t359-lasting-act-retry-check.md` in the t359 downstream tree.
- Fact: t355 (merged; see its report) gives every node the first attempt plus 3 retries. A mutating action's failure found at verification or confirmation already reaches Core as not retryable, but Core treats web nodes as non-mutating (Flow nodes carry no effect metadata), so an ambiguous failure after a press was dispatched (for example the target detached or the acknowledgement was lost after the click) is retried, which can add a second item to a cart or send twice. User rule: lasting acts are checked, never blindly repeated.
- Goal: a node whose act lasts (its declared consequence is anything but none, or its definition is a committing action) is retried automatically only when the failure shows the act did not happen (nothing was dispatched: not found, not actionable, covered before the press, busy refusal), or after the existing desired-state or effect check shows the effect did not land; when the effect cannot be determined, it ends as an uncertain outcome that says so and is not retried. Non-lasting nodes keep t355's retries unchanged. One rule, one owner, applied on every path (exploration, tests, trials, playback).
- Owns: Core `runtime/executor/**` retry decision and node effect metadata from declared consequences (list exact files), domain `domain/src/runtime/adapter.ts` and `domain/src/runtime/llm-evidence/node-run/retries/**`, the extension action runtime's dispatch-acknowledgement signals in `apps/extension/src/content/actions/**` if they must report whether a press was dispatched, with tests.
- Must not touch: domain `plan-resolution/**` and Core `runtime/flow-bootstrap/candidate/**` (t358 owns them), the panel chat and overlay, `docs/working/*.md`. No commits, provider calls or paid runs; Lab runs provider-free on the ten realistic scenarios only. No new `as never` casts.
- Definition of done: fail-first tests per path: a lasting press that failed before dispatch is retried and succeeds; one that failed after dispatch with the effect landed is not retried and counts as done; one with an undeterminable effect ends uncertain without a retry; a non-lasting node still retries 3 times.
