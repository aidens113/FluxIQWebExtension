## Outcome

## What changed and why
- D4 (every chat "This project"): Core never titled a thread opened by a person. `runtime/conversations/conversations.ts` `appendTurn` now names a title-less thread from the person's first message (`title-from-message.ts`: whitespace collapsed, at most 60 chars, cut at a word with an ellipsis; best-effort, never fails the message; rename does not move the thread in the list). `ui-components` thread-list label for an untitled project thread is now "New chat" instead of "This project" (rows already show when it moved; the picker adds the time where labels repeat).
- D5 (no-key reply): `conversations/instructions/interpret.ts` `automationStudioConversationModelProblem` now reads the release failure's words. No key: "no model key is set up yet, so add one in Settings, under AI keys". Saved key needing recovery: "needs one sign-in to the panel to upgrade it". Anything else: neutral "could not be used" (no longer claims a saved key). Needed one line outside the brief: `models/providers/anthropic/messages.ts:52` threw away the release error's message (DeepSeek's path already kept it), so Anthropic users always got the generic words; it now passes the person-safe message through.
- D9 (empty Assistant pane): cause confirmed. The dock mounted the chat only after first open, but on a wide screen the column is visible from the start. New `panel-shell/dock/use-docked-beside-page.ts` (matchMedia, 721px, same breakpoint as the CSS) mounts the chat at once when the dock is a column; phones keep mount-on-first-open.
- D7 (modal text ran together): the old `.automation-client-pairing-modal` CSS lives in Studio styles that load only with the graph editor, so on other pages it had no styles. `GlobalClientGatewayPairing.tsx` now renders labelled lines (Client, Client id, Code, Time left) plus one sentence on what approving does, styled by its own `app/client-pairing-modal.css`. Approve/reject calls are unchanged, so the modal and Settings "Connect a client" still use the same two endpoints. I did not touch the Settings list (other worker), so the "inline list under the backdrop" part rests on the modal being the front, complete control; not changed further.
- D8: same cause (Studio styles not loaded on Projects). `features/projects/projects-page.css` now styles the catalog (heading, toolbar, search, category sections, rows) with panel tokens, scoped under `.projects-page`. The 404: with no branding favicon the browser requests `/favicon.ico`, which the panel does not serve (checked: 404 on the running panel; `/fluxiq-mark.svg` is 200). `app/layout.tsx` metadata now always declares an icon (branding favicon, else `/fluxiq-mark.svg`). That is a root-cause fix for every page, not only login and Projects.

## Home polling: not done, and why
`GlobalClientGatewayPairing` polls the full snapshot with backoff (1 s to 10 s; 1 s while a request is pending, 5 s hidden). Nothing in the panel pushes: no EventSource or client WebSocket exists (`conversation/thread/poller.ts` says so), and the gateway has no pairing-change hook. A real fix is a server push: a revision/listener on `ClientGatewayPairingRegistry` (`packages/fluxiq/src/client-gateway/service/pairings.ts`), a small SSE route (new `app-route-iam` contract in `apps/web/src/lib`, which another worker may be editing), and an EventSource in the watcher with the current read as reconnect fallback. That crosses Core server, `lib` and the route contract, so I did not start it. I did not lengthen the interval. Needs a decision/owner.
