# Panel audit: model keys and security (t925, before)

## Outcome
Done. Audit only; no source edits. Final state of the panel at 127.0.0.1:3100: owner `admin` (password changed once; stored in EXT/test-runs/t925-panel-credential.txt, git-ignored, not printed here), one dummy key saved and offered to the workspace: **"Audit key one"** (Anthropic, default), assistant model set to claude-haiku-5-5, allowance $0.25. A pending invite to teammate@example.invalid exists (the cancel was not completed), and a teammate user row came with it (#33).

## Method
Headed Chromium (Playwright from EXT/packages/browser-host; scripts `a1`..`a31.mjs` and `lib.mjs` in EXT/test-runs/key-security-ux/audit-before/panel/) drove the panel as a person with no prior knowledge: first visit, sign-in, keys in every place, one chat message, replace/remove/reveal, model and allowance, connect pages, people and sign-in. Each step was captured in 4 variants (`NAME-light|dark-1440|390.png`, 270 PNGs, same folder). Full-page captures show only the page's own scroll area, not the inner scroll of the main column, so long pages are cut at the first screen; text was read from the DOM. Console and network were logged. Cause paths: W = CORE/apps/web/src, U = CORE/packages/ui-components/src, F = CORE/packages/fluxiq/src (under the t925 Core tree). Dummy keys only; the one chat message got a refusal, no spend.

## What works
- The temporary-password screen and its 12-character rule are clear (#2, #4).
- Settings > AI keys is the clearest key form; allowance and model wording is plain English and persists (#17, #18).
- Removing a key says exactly what happens; the invite flow explains the two roles in one line; resend and cancel exist.
- Light and dark both render; the 390 px layout adapts and no horizontal scroll was seen in captures.
- Dummy keys were saved, rotated, revealed (30 s, masked afterwards) and removed without error.

## Brand note
Panel colours follow the website's dark scheme (amber `#f5b83d` accent, near-black `#0c0d0f`/`#111214` surfaces; website tokens `--color-amber`, `--color-ink`, `--color-panel` in FluxIQWebsite/src/app/globals.css). The amber primary button and dark theme read as the same product, with a warm light counterpart. The weak points are unstyled native controls (#7, #10) and raw JSON and ids (#20, #32), not the palette. Only the website's CSS custom properties were read, not its components.

## Not verified
- Whether the invite email was really sent; invite acceptance (`/welcome` with a token).
- Two-factor enrolment, PIN setting, and the Roles / Authentication Policy tabs beyond their first screen.
- Why choosing a model changed the workspace-key note (#17).
- The chat reply with no key (the no-key screens predate the key); 390 px horizontal overflow was only checked by eye in screenshots.
- Long-page screenshots are cut at the inner scroll area; line numbers are from grep and may drift a few lines.
