# Extension audit: connecting, model keys, security (t925, before)

Date 2026-11-17. Build: `apps/extension/dist/chrome` of the t925 tree. Panel: production instance at http://127.0.0.1:3100 (gateway ws://127.0.0.1:4877/client), owner `admin`.

## Method
Headed Chromium (Playwright persistent profile, `test-runs/key-security-ux/audit-before/extension/profile`) with the unpacked Chrome build. The side panel (`sidepanel/index.html`) and popup (`popup/index.html`) were opened as tabs and driven through one long-running session (`daemon.mjs` plus numbered `cN.mjs` steps) because a pairing does not survive closing the browser. Every extension step is shot at 360 and 480 px, dark and light (`shots/NN-name-{dark,light}-{360,480}.png`); panel pages at 1440 and 390 (`shots/NN-panel-...`). Light/dark was forced by setting `data-theme` on the root, not through the Settings radio (so the radio shows Dark in light shots). The panel address was pointed at 3100 the way a person would: Settings > Advanced > the two address fields > Save changes. The extension shows no console errors; the only console errors are the panel tab's `400 Bad Request` (key removal/rotation). Where a cause is not read from code it is marked "suspected". All "Open FluxIQ" clicks after the address change went to 3100 only. Before the change the unpaired first open probed the built-in default 127.0.0.1:3000 (someone else's server, read-only probe) and reported "FluxIQ is running" (shot 01-first-open).

## What works
- Pairing code flow is clear: a large 6-digit code in the extension, the same code and a countdown in the panel; Confirm connects in about 3 s with no further step.
- Reconnect after Disconnect needs no new approval; the saved pairing survives. Re-pairing after Forget works and the revoked row stays as history.
- The extension notices a removed key within seconds and offers a card with a direct Open FluxIQ; after re-adding it hides the card.
- Revoke is a single inline confirm in the panel, with plain words ("It will have to pair again").
- No page overflow and no console errors in the extension at 360 and 480 in either theme.

## Panel state at the end
Browser left **paired and connected** (the session still runs). The one dummy key was removed and a new dummy key named "Audit key one" (Anthropic) was added to see the extension's no-key state, then re-offered to the workspace and chosen as its key; model stays `claude-haiku-5-5` and the allowance is untouched. The panel now shows one extra revoked client row besides the active one. The panel owner password was read from the credential file and never printed.
