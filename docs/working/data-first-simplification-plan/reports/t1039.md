## Outcome
Done, with two caveats (see Not verified): the hook inside a real `lab attempt` was not run (no live or browser run allowed), and `pnpm lab flow-chart` hung in `run-lab.mjs`, so the command was run through `dist/cli.js`.

## What changed and why
- New `packages/test-runner/src/flow-chart/` (barrels in every directory, one export per file, tests in `tests/`):
  - `read/`: reads the run's step files. The Flow is the newest decision request's `core.flow_draft` (steps with `inResult`); the input is the first chat step's request; per-node examples come from the tool steps' `call.json`/`result.json` matched by call id (rows read and first row); the output is the newest `answer-turn.json` (what the chat showed). `attempt.json` naming a saved Flow id makes the label "saved Flow", otherwise "draft". Missing files are the only failure treated as absent.
  - `build-flow-chart-svg.ts`: pure Flow -> SVG. START, INPUT panel (instruction and each typed/chosen value), one box per node (step, kind, target in words, typed value, example), result read marked and green, loop brackets on the left, branch arrows on the right, "N other steps tried" note, OUTPUT panel (first 5 rows with columns and total, or "no result"), END. Wraps or ellipsizes long text; tall Flows grow the image.
  - `render-chart-png.ts`: `@resvg/resvg-wasm@2.6.2` (added to `packages/test-runner/package.json` and the lockfile), fonts loaded from the system's Segoe UI, Arial or DejaVu files.
  - `redact-chart-text.ts`: hides bearer tokens, JWTs, key-shaped strings, cookie/authorization/password `key=value`, long hex and mixed-case tokens, and the value typed into a field whose label says password/secret/token/pin/card. Page text and address slugs stay.
  - `write-flow-chart.ts`: writes `flow.svg` and `flow.png`; never throws; failure writes `flow-chart-error.txt`; returns the report line (`Flow chart: flow.png (and flow.svg) shows the draft|saved Flow, N nodes`, or `none written, the attempt never got a draft of a Flow`).
  - `chart-run-directory.ts`: the `flow-chart <run dir> [--out DIR]` command (the run directory is only read).
- Hook: `attempt-lane/live/run-attempt-command.ts`, at the start of the outer `finally`, so it runs on success, failure, refusal, stop and throw. It writes the chart then appends the line to `attempt-report.txt`; any error is swallowed as best-effort.
- Command wiring: `commands.ts` (parse, usage), `cli.ts` (dispatch), `scripts/lab/run-lab.mjs` (added to read-only commands so it does not wait for Core). The brief named only `scripts/lab/**` for dispatch; the parser lives in `commands.ts`/`cli.ts`, so those two got small edits too.
- `docs/architecture/testing-facility.md`: one bullet on the evidence file.

## Not verified
- The hook inside a real `lab attempt` (no live, paid or browser run was allowed). It is covered only by typecheck and by the writer's own tests.
- The OUTPUT panel on a real run: the five bigbox recordings and the scripted run hold no `answer-turn.json`, so they show "no result: no answer was recorded for this run". Rows and total in the panel are proven by tests and the fixture render only.
- Branches: the draft evidence carries no branch or state-route data, so `ChartFlow.branches` is always empty from real runs; the builder draws branches, tests cover it, but nothing feeds it yet. Loops come from the draft's `runs: "repeats through step N"`.
- "Parameters" are the values typed or chosen (named by their control), because the draft does not carry the saved Flow's parameter list.
- Saved vs draft: decided by `attempt.json` naming a saved Flow id. A later attempt that only replays the saved Flow has no decisions, so it charts the newest draft in the step files; the chart is written once per run directory (not per `attempt-N` folder).
- `pnpm lab flow-chart ...` ran for 3 minutes without output in `run-lab.mjs` (I stopped it; likely its pre-command guards or lease, unexamined). The built `node dist/cli.js flow-chart` works.
- No full test suite was run (narrow checks only, per repository rules).

# Round 2

## What changed
1. One chart per attempt: `run-attempt-command.ts` `onEnded` now writes `attempt-N/flow.png` and `flow.svg` right after the answer picture (best-effort, `.catch` annotated), from the shared step files as they stand when that attempt ended. `saved` comes from the attempt's own `outcome.saved.flowId`; the answer comes from that attempt's folder. The chart title reads `Flow chart, attempt N (saved Flow|draft)`. The `finally` chart in the run folder stays, for whatever stands at the very end. `ChartRead` (`runDirectory`, `evidenceDirectory`, `attempt`, `saved`) is the new read request.
2. OUTPUT without a shown answer: `read/offered-completion.ts` takes the newest `answer-*` step whose `result.json` holds `core.completion_check` feedback and shows its `resultHolds` rows (first 5, columns, total), labelled "(offered, not accepted)", with the outcome in plain words from `read/completion-outcome.ts`: accepted, held unconfirmed (plus "could not read: ..."), refused (it said no, plus its first sentence), refused without being checked (same evidence), or refused (code). An `answer-turn.json` the chat showed still wins and is labelled "(shown to the person)". With neither, "no result".
3. Hang cause: `run-lab.mjs` ran the whole build phase (build lock, Core build checks, domain build) before any command except `stop` and `watch`, and `flow-chart` was only exempted from the Core lease. Fix: `flow-chart` now returns early, like `watch`, and imports only `dist/flow-chart/index.js`. It needs the runner built once.
