## First review — historical findings

1. **P1 — malformed live holder data can bypass admission arithmetic.** `C:/Users/osrs_/MeritClaude/tools/heavy-slot/policy.mjs:24` validates the candidate/global telemetry, but lines 28–31 trust each holder's `needBytes`. `tools/heavy-slot/state.mjs:77` reads persisted objects without a shape/version check; `scheduler.mjs:15`/22 preserves a live run even when its need is absent or nonnumeric. A holder with valid id/label/kind/live pid but missing `needBytes` survives pruning. Its pending term is `Math.max(0, undefined - workingBytes)` -> NaN; both headroom comparisons against NaN are false, so admission returns allowed. Corrupt or incompatible ownership state must block with a diagnosis, never become free memory. Validate persisted holder/ticket/history shapes and all reservation terms as finite nonnegative numbers before admission; do not delete an invalid live reservation to recover. Add a scheduler test with an on-disk malformed live holder, not only a direct policy test. **Static finding; not executed.**

2. **P1 — snapshot ordering can under-reserve growth already observed in the process table.** `tools/heavy-slot/memory.mjs:6` samples global physical/commit headroom before enumerating process footprints; Linux does the same at lines 16–25. `policy.mjs:27` assumes those global figures already contain the holder footprints, then reserves only remaining growth. If holder A needs 4 GiB, global headroom is sampled as 6 GiB, and A grows from 1 to 3 GiB before the process probe, the policy sees pending A=1 GiB. Candidate B=3 GiB plus reserve=1 fits the stale 6 GiB figure, although current headroom is 4 GiB and the required remaining reservation is 5 GiB. Both physical and commit accounting can cross this window. Collect process usage first and global headroom last, retaining conservative readings/freshness so later footprint samples are never subtracted from earlier headroom. Add a controlled two-probe growth test; real Windows/Linux timing coverage is also needed. **Static interleaving; no actual pressure or OOM observed.**

3. **P1 — launch/register crash window loses an unrecorded live child.** `tools/heavy-slot/run.mjs:27` starts the child before line 38 durably registers `childPid`. If the gate launcher dies in between, the holder contains only its dead pid. `scheduler.mjs:16`–21 can discover only children connected to previously recorded pids. On Linux, the live child is reparented after its parent dies, so the next sample cannot reconnect it and pruning removes the reservation while work continues. A short-lived unobserved intermediary can similarly disconnect deeper descendants. The test at `tests/heavy-slot.test.mjs:80` covers an already registered child only. Use a supervised launch/registration handshake that establishes durable ownership before heavy work starts, plus appropriate process-tree containment/lifetime tracking; sampling alone cannot prove that unobserved orphan work ended. Add cross-process fault injection immediately after spawn/before registration and after a short-lived intermediary exits. **Crash window established from code; platform behavior needs empirical validation.**

4. **P2 — lease mutation addresses a label, not a lease identity.** `scheduler.mjs:80`–96 looks up renew/release solely by label. Old lease A can expire, new lease B can acquire the same label, then A's delayed cleanup/retry can release or renew B. Unlike `release(holder)` at lines 64–69, no id comparison protects this path. This removes B's future-growth reservation while its work may still be active. Return the lease id from acquire and require that identity for renew/release, rejecting a stale holder; preserve label for display. Add an expired/reacquired same-label stale-release and stale-renew test. **Deterministic API interleaving; not executed.**

Implemented and validated:

- `owned-process.mjs` and `windows-job.cs` provide a Windows supervisor with a sole non-inherited kill-on-close job handle. The root is created suspended with `PROC_THREAD_ATTRIBUTE_JOB_LIST`, membership checked, then resumed; only duplicate standard-stream handles are explicitly inherited. Ordinary detached descendants remain members, and kernel active-member accounting owns completion. Unsupported platforms refuse `run` before reservation; missing Windows capabilities fail before user code resumes. The job carries no memory/workload-time limit. This follows [Microsoft's job lifetime contract](https://learn.microsoft.com/en-US/windows/win32/procthread/job-objects) and [creation attribute API](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute).
- A private authenticated control pipe keeps launch arguments out of logs/state and preserves standard input/output/error. The supervisor receives no workload specification until its PID is durably recorded. The actual root uses standard native argument quoting; npm/npx prefix handling and prior native argv/exit behavior remain in `child-command.mjs`.
- SIGINT/SIGTERM retain their original cancellation intent through the control pipe. Windows explicitly terminates the entire owned job and reports 130/143 respectively; launcher disconnect terminates the job, and supervisor crash triggers kernel kill-on-close. Normal root exit waits for all job members and then returns that root's exit code. PID ancestry is optional memory evidence, never proof a contained tree ended.
- `monitor.mjs` separates optional observation from completion, aborts real external probes at workload end, and never awaits a hung custom sample during release. Missing monitoring keeps the full reservation. No admission estimates, memory reserve or slot thresholds were lowered.
- `sampledAt` is the finite start of the actual OS headroom query inside PowerShell, after process inventory. Node preserves that returned timestamp. The admission decision checks it under the state lock against the unchanged five-second cadence, rejecting stale/invalid/future evidence and resampling rather than relabelling old headroom. Added controlled delayed-probe/lock and invalid/future/immediate evidence cases. This validity rule is not an admitted-job timeout.
- Updated the owned README with Windows-only execution support, kernel lifetime/exit/cancel semantics, legacy ambiguous-record handling, and required lease tokens. No installation or migration occurred.
- Added actual detached parent/grandchild, normal completion with never-settling telemetry, SIGINT/SIGTERM cancellation with hung telemetry, supervisor/launcher crash, and empty/quoted/Unicode argv cases. All termination targets are owned process handles/jobs; no process-name or guessed-descendant kills.
