  `verify` when it declares something lasting (as before), **or** when `step.acts` holds an id in `lastingActs`. The set
  holds only top-level act ids, so a choice like `a1.colour` or `a1.quantity` never matches; the steps after it stand on

    promise, so `crossCheck()` reuses it and makes no second paid call. A failed read is cached too, so it is not retried.
  - An act is lasting when, after lowercasing and collapsing whitespace, one of the read's quotes contains the act's
    quote, or the act's quote contains it.
  - Ids containing `.` are dropped. With no acts, no read is made.
  - Every instructed entry counts. The class enum has no "none"; all five classes are lasting.
- `service/flow-bootstrap-commands/permission-outcome.ts`: comment only. `instructed()` is still read after
  `crossCheck()`, and the code is unchanged. The comment now says that a build with acts reads earlier, and that the
  set read after `crossCheck()` is the same. The ordering guarantee still holds, and a test asserts it.
- `flow-draft/dry-run.ts`: header comment only. A step lasts by declaration or by an instructed act.
- Tests:
  - `flow-draft/tests/verify-only.test.ts`: new describe block, 5 cases.
  - `flow-bootstrap/tests/action-permissions.test.ts`: new describe block, 7 cases. They use the run's exact quotes from

## Open questions or contradictions found

- The brief assumed the replay mode could read the instructed consequences through owned files plus one wiring file.
  In fact four `llm/node-tools`/loop files and `service.ts` must carry the set (see above). Please grant them, or give
  them to a follow-up worker.
- `automationStudioFlowDraftStepWithholdsLater` excuses later steps only for declared destructive classes or a moved
  target. A step verified because of an instructed `move_money`, `delete` or `send_or_publish` act, but declared `[]`,
  will not excuse the receipt steps after it. Whether it should is a separate decision. I left it unchanged.
- Quote overlap is substring-only. If the read paraphrased or trimmed differently (for example, quoting only
  "put three ... in my cart" when the act quote starts at "On Farbazaar"), substring overlap still holds, because the
  act quote contains the read's quote. A read quote that crosses two acts would mark neither.
