## Open questions or contradictions found

- **D5 Join paths is not hidden.**
  - Cause: a run's step row becomes a message in EXT `stream/step/messages.ts`, which I don't own. If the classifier returned null for `join`, the message would remain as a bare spoken line ("Step N: ..."), which is no better.
  - Needed: in `messages.ts`, skip the step when `actionCard(...)?.kind === "join"`. Then flip U-A2 in `panel/chat/tests/live-run-display.test.ts`, which currently asserts a "Join paths" card exists. Core's `runtime/activity/step.ts` could instead not emit merge-node steps at all.
- **D8: why playback dropped the reason (00018).**
  - Core's run-step row (`runtime/activity/step.ts`) carries only `Node: <definition>`. The recovery row (`executor/graph-run.ts:566`, "Recovery started") carries no result code. EXT `messages.ts` marks the started step `failed` when it sees that recovery row and sets no `why`, so no row in the stream ever carries `web.action.rate_limited`.
  - Needed: give the recovery row `text: "Result: <failure code> · Reason: <reason>"`, and have `messages.ts` take `why` from `activityActionOf` on that row. Both files belong to others. `failure-reason.ts` already words the code once it arrives.
- **Left as they are:**
  - The completion check still reads "Test run · Passed" before the steps (00011). A new kind would break the exhaustive `Record<ActivityActionKind, ...>` icon map in the Core panel.
  - Playback "Type · Done" with no target (00019): the step title is "Typing into the page" and carries no field name (`activity/wording/action.ts` and `step.ts`).
  - The "Not confirmed: ..." sentence is the agreement text, and its jargon is D3 (`agreement.ts`).
