### 2. The judges see the page

- **(c) Contract.** `AutomationStudioResultEndView` and `endView?: AutomationStudioResultEndView` were moved onto `AutomationStudioRunResultSummary` in `result-verification/contracts.ts`.
  - `result-verification/result-summary.ts` (type move only) now imports the type from contracts and re-exports it.
  - It keeps `AutomationStudioRunResultSummaryWithEndView` as a `@deprecated` alias of `AutomationStudioRunResultSummary`, because `build-test/summary.ts`, `run-outcome.ts` and w87's tests (none of them mine) still import those names from there.
- **New module `service/end-view/`**, with `index.ts`, `look.ts`, `run-reader.ts` and `tests/look.test.ts`.
  - `automationStudioEndViewLook({tools, viewKeys, timeoutMs?})` sends the domain's own free look: the first tool with `initialObservation`, which for a library domain is `runsNodes.initial` under `core.run_node`.
    - It keeps only the domain's declared top-level view keys.
    - It is bounded by `AbortSignal.timeout` (10 s by default). The call's signal is aborted, and the look rejects with a `TimeoutError`.
    - A look that answers without a view key is "no view" (`undefined`).
  - `automationStudioRunEndViewReader(binding)` is the post-run port. It sends the look through `binding.executeTool` for the run's own project and Flow, under `automationStudioActionPermissionDenied`, with no `startLocation`, and the call id `result-check.end-view.<runId>`.
- **(a) Post-run check.** `service.ts` `resultPorts` sets `readEndView` from `automationStudioRunEndViewReader(this.llmEvidenceRuntime)` when the binding has a free look and view keys.
  - A failure or timeout throws into w87's existing `automationStudioResultEndViewRead`. That reader carries the error's kind and marks the summary `withheld`, and the check is still made, without a view.
  - So the failure is soft for the check. It is said as withheld rather than as silent absence, which is the contract w87 built.
- **(b) Build-test judge**, in two parts:
  - `dry-run-gate.ts` captures the page right after a replay passes, both clean and with a step made optional, and before anything else can move the page.
    - The look goes through a new gate input `endView`, asked for only when the test is `observed`.
    - The result goes on `AutomationStudioFlowDraftTestReport.endView`, typed structurally as `AutomationStudioFlowDraftTestEndView` so `llm/` does not import `result-verification/` (cycle guard). `after` is the replay's last step.
    - A reused clean replay reports the same look and does not look again.
    - A failed look leaves the report without one, and the test still passes.
  - `service/flow-bootstrap-commands/build-judge.ts`
    - Takes `look: { tools, executeTool }` and exposes `testEndView`. `service.ts` hands that to the loop as `testEndView`.
    - Passes `judgedTest.endView` to `automationStudioBuildTestResultSummary` as `endView`.
    - I put the look's construction here, not in `service.ts`, because `service.ts` is baselined at 4419 lines and may not grow. The brief names `build-judge.ts` for (b).
- `service.ts` is exactly 4419 lines.
  - The one new import is offset by moving the standalone comment above the `test:` line, which I was already editing, to a trailing comment on that line.
  - The lasting-acts provider sits on the existing `buildJudge` statement line, which already chains statements.

### Test harness fix (tests of `service.ts`)

`tests/service-bootstrap/tests/judged-build.test.ts` ("lane A's run 40") failed after the wiring. Cause:

- The instruction read (`service/instruction-authority.ts`) is an `evidence_tool_decision` with `metadata.source = "instructionAuthority"`. The test's mock provider answered every non-judge request with the next scripted model decision.
- Before this change the read happened only after the build, once the script was exhausted. The mock threw there, and the cached failure named nothing.
- Now the read happens at the first test, so it consumed scripted decision 8 and shifted the script.

I confirmed the cause before touching the test:

- Removing `lastingActs` from `service.ts` temporarily made the test pass.
- A temporary probe copy showed request 8 was an extra `evidence_tool_decision`.
- Both temporary changes were reverted, and `service.ts` was restored byte-for-byte from a backup.

The fix: the mock answers `instructionAuthority` requests itself (`complete`, `{instructed: []}`) and does not record them as model decisions. No assertion was changed.

- Whether the web domain answers the free look right after a build test. It goes through the same executor as the replay, including person-needed and routing recording, so a look could be recorded as a route observation.
