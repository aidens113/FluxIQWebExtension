## What changed and why

All paths are under `packages/fluxiq/src/programs/automation-studio/runtime/`.

- **D2: the counter advanced on a retry.** Cause: `executor/graph-run.ts` emitted `index: step + 1`. `step` is the run loop's pass counter, so it advances on every pass: a retry (`continue` after a ladder retry), a state route or a skip. `count` was `flow.nodes.length`, which counts Merge nodes.
  - New file `activity/step-numbers.ts` (`automationStudioActivityStepNumbers`), exported from `activity/index.ts`. It gives each step a number from its place in the graph: a depth-first walk from the Flow's start node, in reverse post-order. That puts every step after the steps with an edge into it and both sides of a fork before their Merge, and an edge back to an earlier step changes no number. Nodes the walk does not reach follow in list order. List order is not used for anything else, because nodes come back sorted by id (see `start-node.ts`).
  - **Choice: a Merge ("Join paths") is not counted and not announced.** It has no number, it is left out of "of M", and `graph-run.ts` emits no "Running step" for it. This also removes the "Join paths" step card that came from that emission. The person-facing numbers are then exactly the steps a person sees. Because the number is the step's place in the Flow, a retry, a state route back, or a partial or resumed run (`startNodeId`) all keep the step's number.
  - `graph-run.ts` computes the numbers once per run, from `startChoice ?? chooseAutomationStudioStartNode(flow)`. `activity/step.ts` changed only in its doc comment: `index` is now the place in the Flow.
- **D4: "Test run · Passed" before any test step.** Source: `activity/observer.ts` `checkCompletion`. The completion check reads the plan and runs nothing, and it settles before the dry run starts. It was emitted as `detail.kind: "check"`, and the extension's `action-card.ts` turns any check row into a test card ("Passed"). It is now emitted as `detail.kind: "note"` for started, ok and refused:
  - With no text (started, ok), the panel shows it only on the live line. `panel/chat/stream/step/messages.ts` drops notes that have no words, and `action-card.ts` never makes a card from a note.
  - Refused, it is a plain message carrying the refusal text, with no "Test run · Didn't pass" card.
  - The title stays "Completion check", so the extension's status sentence (`shared/activity/wording.ts:120`, which keys on the title) is unchanged.
- **D5: the bare "Recovery started" line.** In `graph-run.ts`, the `repairing` emission keeps its label "Recovering from a failed step: <label>" for the live line but no longer carries a detail. A detail-less event makes no chat row. The extension's pacer tests already use that detail-less shape. The recovery thought ("Trying the step again — …") is now the only row. One code comment that named "Recovery started" was reworded.
