## What changed and why

### Item 1, Cause 13: fact values were dropped on a pass
- `packages/test-runner/src/flow-lane/creation/oracles.ts`
  - New `JudgedFact` type (`UnheldFact` plus `held`) and `JudgedFinalState` type (`FinalStateVerdict` plus optional `facts`).
  - `CreatedFlowOracles` gains an optional `facts` member.
  - New `judgeEveryFact(facts, probe)`. It wraps the probe so it records the value it read. It then asserts each fact through the same `assertExpectedFacts`. Held facts carry the value that was compared: trimmed text for `text`, the raw value otherwise. Unheld facts carry `details.actual`, as `judgeExpectedFacts` does. A fact the fixture declares wrongly still throws.
  - `judgeCreatedFlowOracles` passes `facts` through on both a pass and a fail.
  - New `withholdObservedFactValues` withholds every observed value, held facts included, when the scenario declares a secret. This is the same rule the unheld facts had before; the inline code in run-scenario was replaced by it.
  - `assertCreatedFlowOracles` strips `facts` from the failure's `details`. Failure records therefore carry only what they carried before (`unheldFacts`), never held facts' page text.
- `packages/test-runner/src/run-scenario.ts`
  - `judgeFinalState`, on a pass, re-reads every fact on the page that held and returns `facts`. The read is not swallowed, because the structure audit's failure-as-empty rule refuses that.
  - `nearestFinalStateMisses` now uses `judgeEveryFact`. It keeps the same nearest-page rule and the same `unheldFacts`, and adds `facts` for that page.
  - The snapshot write uses `withholdObservedFactValues`.
  - The values reach `snapshots/flow-lane.json` `oracles.facts` through `createdFlowLaneSnapshot`, which is unchanged.
- `packages/test-runner/src/flow-lane/creation/index.ts`: one line, `export * from "./oracles.js";`. **This file is outside my owned list.** The structure audit refused run-scenario's deep import into `creation/oracles.js` ("Import from the directory (its index) instead"), so the barrel had to export it. There were no name collisions.

### Item 2, Cause 12: result checks were reported as a repair
- `packages/test-contracts/src/harness-recovery.ts`: `RunHarnessRecovery.resultChecks?: RunHarnessIntervention[]` (documented). It is absent when there are no checks.
- `packages/test-contracts/src/harness-recovery-validation.ts`: `resultChecks` is an allowed key, and each entry is validated with the intervention's shape. It is not counted toward `attempted`.
- `packages/test-runner/src/flow-lane/harness-recovery.ts`: `readHarnessRecovery` reads `metadata.source === "verifyAutomationStudioRunResult"` from the raw run detail, keyed by `interventionId`, because the control client's parser drops the source. Those interventions go to `resultChecks`. `interventions`, `attempted` and the refusal logic now see recovery only. A run like murwd8le now reads `attempted: false, interventions: [], resultChecks: [2 entries]`.
- `packages/test-runner/src/live-llm/live-llm-run.ts`, `settleRepair`:
  - `repair.observed` is now the recovery-only view (new private `withoutResultChecks`). Its calls and cost are the runtime phase exactly as `run-spend.ts` counts it. Its `observedCalls` and `interventions` leave out the checks, matched by request id.
  - New `repair.resultChecks: { calls, totalEstimatedCostUsd, record: "verification" }`, written when there were checks.
  - `this.repairObserved`, which feeds the spend, stays the raw usage. So `runSpend`, `observed.calls/totalEstimatedCostUsd` and `usage.calls` are computed exactly as before. The budget assertion is unchanged too.
  - Publishing: a `{ repair, runTotal }` event goes out only when recovery called or filed something, or when there were no checks (so a run that called nothing settles as before). A separate `{ resultChecks: { calls, totalEstimatedCostUsd, status }, runTotal }` event goes out when there were checks.
- `packages/test-runner/src/run-scenario.ts`: the `settleRun` publish labels a `resultChecks` event "The created Flow's result was checked". The repair event keeps "The created Flow's repair attempt finished".
